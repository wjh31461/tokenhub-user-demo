本文将业务需求、页面结构、交互逻辑、接口、表结构和数据字典合并维护。交给代码生成模型时，同时提供本文和公共设计。本文只描述用户门户操作审计，不修改工作台或其他业务模块的既有实现。

## 第一部分：业务需求与页面交互

## 1. 目标、范围与概念

### 1.1 用户目标

让主账户在有权查看的范围内核对“谁、何时、对什么对象、执行什么操作、结果如何、修改了哪些内容”，支持按条件定位事件和查看详情。

典型问题：某个 Key 是谁暂停的？子账户配额从多少改到多少？创建密钥为什么失败？已删除的密钥是否还能查到操作记录？

### 1.2 本期范围

- 操作审计列表、条件查询、稳定翻页、详情抽屉。
- 用户密钥、子账户与配额、告警已读操作的事件接入契约。
- 成功、失败、拒绝三种已确定结果的审计记录。
- 字段变更前后值、历史名称快照、结果说明。
- 服务端可靠记录、重复投递去重、账户隔离和敏感字段白名单。

本期不做：日志编辑／删除、用户侧日志导出、批量处理、统计图表、全文日志检索、管理员全平台审计、登录安全日志、CRM原始回调日志、模型请求内容审计、请求体／响应体下载。

日志保留和到期清理由后台策略执行，用户门户没有删除按钮。未来若增加导出，必须另行定义导出权限、异步任务和下载有效期，本期不预留可点击的“导出”按钮。

### 1.3 和其他模块的边界

| 类型 | 本模块是否展示 | 归属说明 |
|---|---|---|
| 创建、暂停、恢复、删除用户密钥 | 是 | API密钥模块产出操作事实 |
| 添加子账户、分配／调整配额 | 是 | 子账户模块产出操作事实 |
| 模型调用、Token消耗、调用耗时 | 否 | 用量中心／调用明细 |
| 额度预扣、校正、释放 | 否 | 用量／计费流水 |
| CRM订购、退订、停复机原始通知 | 否 | 服务历史或内部集成日志 |
| AI应用业务密钥自动创建 | 否 | 业务开通内部审计，不混入用户密钥管理 |
| 供应商、渠道、模型路由操作 | 否 | 运营门户审计 |
| 告警标记已读 | 是 | 告警模块产出事实；仅真实状态变更 |
| 单纯打开列表、筛选、查看详情 | 否 | 不产生可见审计事件，避免查询产生查询日志递归 |
| 查看／复制密钥原文 | 暂不承诺覆盖 | 现有流程未定义；浏览器剪贴板动作不能保证服务端获知 |

## 2. 权限与归属

### 2.1 权限矩阵

定义权限码 `portal.audit.read`；本版默认授予可进入门户的主账户身份，子账户不授予。具体是否授予停机账户由公共权限服务决定，不直接由模型调用状态推断。

| 情形 | 页面及接口行为 |
|---|---|
| 主账户有审计权限 | 显示菜单，可查询本账户审计域内事件 |
| 子账户 | 隐藏菜单；直接访问页面显示无权限；列表／详情接口返回403 |
| 登录用户另有其他主账户身份 | 不合并显示，切换身份后单独查询 |
| 操作人或对象已删除 | 保留历史记录，展示事件发生时快照 |
| 无权限访问的日志ID | 当前身份本身有效且有审计权限时返回404，不泄露记录存在性 |
| 登录失效 | 返回401，由公共框架处理 |

**本版设计、待确认：**主账户可查看发生在自己审计域内的子账户管理操作和子账户用户密钥操作。若业务不允许，应调整服务端可见性策略，不只隐藏前端筛选项。

### 2.2 四个标识不可混用

- `ownerAccountId`：事件发生时的主账户审计域，服务端根据被操作资源和已认证上下文确定，作为查询隔离键。
- `actorUserId`：实际登录的操作用户。
- `actorAccountId`／`actorContextId`：执行操作时采用的业务账户及身份。
- `targetId`：被操作的密钥、子账户、配额或告警对象。

子账户后续转移、解除关系、改名或注销，不改变历史事件的 `ownerAccountId`。新主账户不能因获得当前子账户关系而查询原主账户历史；原主账户只能看到当时归属自己的事件。

无权操作别人的对象时，拒绝事件归属请求者已验证的审计域，不把对方对象名称、服务ID、是否存在等信息写入用户可见日志。无法确定可信账户身份的未登录请求记内部安全日志，本模块不接收。

## 3. 页面结构

### 3.1 列表页

```text
操作审计                                            [刷新]
查看当前账户范围内的关键管理操作。时间按北京时间展示。

┌──────────────────────────────────────────────────────────┐
│ 操作时间 [近7天/近30天/自定义]    业务模块 [全部]           │
│ 操作类型 [全部]   操作结果 [全部]   操作人 [全部/选择]      │
│ 关联服务 [全部/选择]                                      │
│ 定位方式 [对象名称/对象ID/操作编号] [输入内容] [查询] [重置]│
└──────────────────────────────────────────────────────────┘
已查询时间范围：……  记录查询截至：……

操作时间 | 操作人 | 业务模块 | 操作类型 | 操作对象 | 结果 | 操作
……                                                        查看详情

每页 [20/50/100] 条                      [上一页] 第N页 [下一页]
```

首版使用游标分页，不提供“跳到第100页”或未经计算的总页数。列表不显示总记录数，显示本页数量和是否可继续翻页。

桌面两到三列筛选控件；窄屏单列。表格在自身容器内横向滚动，操作列固定右侧；不使整页横向滚动。键盘可操作筛选、分页、详情和关闭按钮；状态必须有文字，不能只靠颜色。

### 3.2 列表字段

| 列 | 展示规则 |
|---|---|
| 操作时间 | `YYYY-MM-DD HH:mm:ss`，北京时间；默认按事件发生时间倒序，再按ID倒序 |
| 操作人 | 历史名称快照，下方显示主／子账户身份；不是当前资源拥有者 |
| 业务模块 | API密钥、子账户管理、告警中心 |
| 操作类型 | 根据事件字典展示中文名称 |
| 操作对象 | 对象历史名称；无名称显示类型和ID；长文本省略并提供完整提示 |
| 结果 | 成功（绿）、失败（红）、已拒绝（橙） |
| 操作 | 固定“查看详情”，无编辑、删除、重试业务操作 |

刷新和查询不重放任何原始操作。“重试”只重试读取日志。

### 3.3 详情抽屉

建议宽度720px，窄屏全宽；不新增左侧菜单。列表URL可带 `logId`，例如 `/audit-logs?logId=...`，支持刷新恢复及从其他页面直达。

区域一“基本信息”：操作编号、操作时间、日志接收时间、操作人、操作身份、模块、操作类型、结果。

区域二“操作对象”：对象类型、历史名称、对象ID、关联服务名称。只显示静态信息，首版不依赖被删除对象的详情页；对象ID可复制。

区域三“变更内容”：字段名称、操作前、操作后。按业务白名单显示，例如“状态：正常 → 已暂停”“配额上限：100000 Token → 200000 Token”。

区域四“结果说明”：成功摘要、失败／拒绝的用户可读原因、可复制的操作编号。不得显示堆栈、SQL、内部服务地址、密钥片段以外的凭证或原始请求内容。

关闭抽屉保留列表筛选、当前页和滚动位置；删除URL中的 `logId`。详情直达无列表状态时，关闭后进入默认列表。

## 4. 筛选与交互规则

### 4.1 筛选定义

| 条件 | 默认值 | 规则 |
|---|---|---|
| 操作时间 | 近7个自然日（含今天） | 必填；近30天或自定义起止日期；单次最多90个自然日，本版设计 |
| 业务模块 | 全部 | 单选；改变后清空不属于新模块的操作类型 |
| 操作类型 | 全部 | 单选；选项来源事件字典，不显示未接入模块的事件 |
| 操作结果 | 全部 | SUCCESS／FAILURE／DENIED |
| 操作人 | 全部 | 远程搜索历史操作人名称，选择稳定actorAccountId；同名显示身份及ID尾部 |
| 关联服务 | 全部 | 从授权历史日志提取服务快照选项，支持已删除服务；不依赖当前有效服务列表 |
| 定位方式和输入 | 对象名称／空 | 对象名称：转义后模糊匹配，2～100字符；对象ID或操作编号：精确匹配，最多64字符 |

日志时间范围不允许未来日期。结束日期为今天时查询上界取本次查询时间；其余结束日期转换为下一日00:00:00，采用左闭右开区间。数据库保存UTC，页面展示上海时区，与公共设计一致。

操作编号搜索仍受权限、保留范围和时间条件限制；空结果提示用户检查时间范围，不能为方便搜索跳过授权。

### 4.2 操作流程

1. 进入页面先确定当前身份和权限，再查询能力／筛选元数据和默认列表。
2. 修改表单不会立即查询；点击“查询”或输入框回车后校验参数、回到第一页。
3. 点击“重置”恢复近7天、清空其他筛选并立即查询。
4. 点击“刷新”沿用已提交条件、回第一页、获得新的查询快照；未提交的表单修改保持但不用于此次刷新，界面明确显示“存在未查询的筛选修改”。
5. 修改每页条数回第一页；同一次翻页使用相同快照和筛选。
6. 查看详情独立请求；详情失败不清空列表，详情关闭后晚到响应不得重新打开抽屉。
7. 新查询取消／忽略旧查询；按请求序号和身份校验返回结果。
8. 切换账户立即清空列表、候选项、详情、游标和URL中的旧筛选；新身份恢复默认条件。
9. 筛选状态可保留在当前页面内存；首版只同步 `logId` 到URL，不把历史操作人和对象名称写入长期本地存储。

### 4.3 异常与空态

| 场景 | 行为 |
|---|---|
| 首次加载 | 列表骨架屏，查询按钮加载中 |
| 查询成功无记录 | “当前条件下暂无操作记录”，保留筛选并提供重置 |
| 已知当前尚未接入事件源 | 页面提示“部分操作尚未接入审计”，不暗示覆盖完整 |
| 列表查询失败 | 显示错误及重试；原列表若保留必须标明旧查询，不能标为新结果 |
| 详情不存在／无权／已超留存范围 | 统一“该记录不存在或当前无法查看”，无跨账户信息 |
| 游标过期或条件被修改 | 提示“查询已失效，请重新查询”，回第一页 |
| 日志延迟 | 显示“新操作可能稍后出现”，并展示服务端返回的已接收日志截止时间；不声称是所有操作完整截止点 |
| 元数据失败 | 错误重试，不将未加载权限默认为允许；列表成功部分可展示 |

本期不自动轮询。查询入口成功不代表其他业务写入链路已完整接入，覆盖情况由能力接口显式返回。

## 第二部分：事件、接口与数据设计

## 5. 审计事件字典与内容白名单

### 5.1 事件目录

| eventCode | 模块 | 对象类型 | 中文名称 | 成功事件记录时机 | 允许的变更字段 |
|---|---|---|---|---|---|
| API_KEY_CREATE | API_KEY | API_KEY | 创建密钥 | 用户密钥事务提交 | name、status、serviceId（只存ID和名称快照） |
| API_KEY_PAUSE | API_KEY | API_KEY | 暂停密钥 | 状态发生实际变化并提交 | status |
| API_KEY_RESUME | API_KEY | API_KEY | 恢复密钥 | 状态发生实际变化并提交 | status |
| API_KEY_DELETE | API_KEY | API_KEY | 删除密钥 | 删除／撤销生效并提交 | lifecycle：EXISTING → DELETED |
| SUBACCOUNT_ADD | SUBACCOUNT | SUBACCOUNT | 添加子账户 | 账户或关联关系创建提交 | name、membershipStatus |
| SUBACCOUNT_QUOTA_SET | SUBACCOUNT | QUOTA_ASSIGNMENT | 设置子账户配额 | 初次分配提交 | limit、unit、quotaMode、resetAt |
| SUBACCOUNT_QUOTA_CHANGE | SUBACCOUNT | QUOTA_ASSIGNMENT | 调整子账户配额 | 已有配额变更提交 | limit、unit、quotaMode、resetAt |
| ALERT_MARK_READ | ALERT | ALERT | 标记告警已读 | 未读变为已读并提交 | readStatus |

事件名称不赋予额外业务能力。例如子账户模块未实现周期配额时，不因为本表包含 `quotaMode` 就自动增加业务功能。已有业务的枚举值通过适配层映射，不改变现有表的状态定义。

只展示已接入的事件。原方案没有明确密钥改名、子账户移除、告警阈值设置等操作，后续确认后再扩展字典。未知事件代码应显示“其他操作（代码）”，保留可读摘要，不导致页面崩溃。

### 5.2 操作结果

| 值 | 语义 | 示例 |
|---|---|---|
| SUCCESS | 业务变更已经提交／已确认生效 | 密钥状态已暂停 |
| FAILURE | 有资格执行但执行失败，最终结果明确未成功 | 合法创建请求因业务校验或事务失败未提交 |
| DENIED | 已认证请求被权限规则拒绝，未执行变更 | 当前身份不允许操作目标对象 |

异步请求“已受理”不能写SUCCESS。本期仅接入能够确定最终结果的同步管理操作；异步操作必须在最终处理方产出终态事件。远程响应超时且结果未知时，先由业务链路核对最终状态，不能直接写“失败”。

重复暂停已暂停Key、重复标记已读等无实际变更的幂等返回不新增成功记录；同一逻辑操作重试使用同一 `operationId`。用户主动重新提交新的业务尝试使用新编号。批量操作由业务模块确定事务边界：每个实际变化对象一条记录，共用批次标识，不把部分成功写为整体成功。

### 5.3 前后值规范

变更项格式为 `{fieldKey, fieldLabel, before, after, unit}`。before／after包含 `{state, value}`：

- `VALUE`：有值，value为字符串或布尔值。
- `NULL`：业务值为空，例如无限制上限；value=null，需结合字段规则显示“无限制”等。
- `ABSENT`：对象／字段在该时点不存在；value=null。
- `UNKNOWN`：历史数据未采集；value=null，展示“未记录”，不能冒充空值。

创建时before为ABSENT；删除时只记录lifecycle和历史名称，不存整份对象；失败和拒绝时changes为空，不把用户期望修改值表现为真实变更。

密钥原文、密钥密文、密码、授权头、Cookie、验证码、个人联系电话、模型输入输出均禁止进入事件、Outbox、查询DTO和应用日志。只允许白名单业务字段，不能先记录完整对象再在前端脱敏。

本期不展示来源IP或User-Agent；若内部安全系统采集，独立管理。历史名称等展示内容按纯文本渲染，禁止使用未净化HTML。

## 6. 后端记录机制

### 6.1 写入责任

审计由执行业务变更的后端记录，浏览器不能上报“业务已成功”来创建权威审计。用户端只开放GET查询接口，不开放审计新增、修改、删除接口。

事务内变更（如暂停密钥）推荐采用业务库Outbox：

1. 验证登录身份和业务权限；由可信资源确定审计归属。
2. 生成／取得业务幂等 `operationId`，读取并锁定或乐观校验目标版本。
3. 从实际已读取状态提取白名单before值，执行变更，提取after值。
4. 在同一本地事务中写业务变更和审计Outbox事件。Outbox写入失败则该事务回滚，不允许业务成功而没有可靠事件。
5. 事务提交后异步投递审计事件；审计存储按 `eventId` 幂等插入，成功后确认Outbox。
6. 审计服务暂不可用不回滚已提交业务；Outbox保留待重试事件，展示可能延迟。

若业务库和审计库同库、同事务，可直接插入审计表，省略Outbox。跨库禁止宣称普通本地事务可保证双写原子性；应使用Outbox或已有等效可靠事件机制。

失败／拒绝事件须在业务事务回滚后，用独立短事务持久化；不能与已回滚事务一起丢失。该持久化再失败时，保留原业务失败响应，同时产生内部采集失败监控和可重试线索，不向用户声称日志已记录。未验证身份的攻击流量不进入本模块。

### 6.2 去重、并发与失败恢复

- `eventId` 在生产端生成并在消息重投时保持不变；重复消费不得产生多条记录。
- `operationId` 是一次逻辑业务操作ID，与查询接口 `requestId` 不同。
- 单次业务操作对同一对象和事件类型只生成一个终态；不能先写失败再覆盖为成功。
- 并发修改的before值必须来自事务内实际版本，不可用前端提交的旧对象；只有提交成功的变更写SUCCESS。
- 已记录事件不可修改；发现错误通过内部纠正事件机制处理，首版不提供用户编辑功能。
- Outbox工作线程采用带超时租约的领取机制，崩溃后可重新领取；投递后未确认导致重投由消费者去重。
- 重试使用退避，达到10次（本版默认，可配置）进入待处理状态并告警；不得自动丢弃，人工重放沿用原eventId。
- 监控采集失败次数、最老未投递事件时间、重试积压和入库延迟；这些监控属于内部运维，不展示在用户审计列表。

## 7. 查询接口

### 7.1 公共约定

沿用公共设计的身份、时间、字符串ID、空值规则。本模块JSON采用camelCase、枚举大写；现有 `specs/001-user-portal-workbench` 草稿存在snake_case等约定，本模块不据此修改公共规范，接入现有实现时由DTO适配。

接口前缀 `/api/portal/v1`。身份由会话或经验证的 `X-Account-Context-Id` 提供。业务记录数量用十进制字符串；pageSize等分页控制值用整数。

### 7.2 接口清单

| 方法及路径 | 用途 |
|---|---|
| GET `/audit-logs/capabilities` | 返回可查询时间范围、事件字典、实际接入覆盖范围 |
| GET `/audit-logs/filter-options` | 授权范围内历史操作人／服务候选项 |
| GET `/audit-logs` | 游标分页查询 |
| GET `/audit-logs/{logId}` | 详情查询 |

固定路径应先于ID路由匹配。所有接口均需审计读取权限，包括候选项与能力查询。

### 7.3 列表参数

| 参数 | 类型 | 必填 | 约束 |
|---|---|---|---|
| startDate、endDate | date string | 是 | 上海时区自然日，跨度≤90天，不能超出可查询范围 |
| module | string | 否 | 已知模块代码 |
| eventCode | string | 否 | 与module一致，不一致400 |
| result | string | 否 | SUCCESS／FAILURE／DENIED |
| actorAccountId | string | 否 | 精确匹配，仅在已授权审计域内应用 |
| serviceId | string | 否 | 同上 |
| searchType | string | 否 | TARGET_NAME／TARGET_ID／OPERATION_ID |
| searchValue | string | 否 | 和searchType成对提供；去除首尾空白；名称2～100字符、ID≤64 |
| pageSize | integer | 否 | 20、50、100，默认20 |
| cursor | opaque string | 否 | 首次不传，后续使用服务端返回值 |

过滤条件中 `%`、`_` 作为普通字符转义；SQL采用绑定参数。不得把用户输入直接拼接到ORDER BY或WHERE。客户端不能传任意排序字段。

### 7.4 返回类型

```ts
type AuditResult = 'SUCCESS' | 'FAILURE' | 'DENIED';
interface AuditItem {
  id: string;
  operationId: string;
  occurredAt: string;
  actor: { accountId: string; displayName: string; role: 'MAIN' | 'SUB' };
  module: string;
  eventCode: string;
  eventLabel: string;
  target: { type: string; id: string | null; name: string | null };
  service: { id: string; name: string } | null;
  result: AuditResult;
  summary: string;
}
interface AuditPage {
  requestId: string;
  accountContextId: string;
  queryAsOf: string; // 本次分页快照创建时间，不是事件完整性水位
  latestReceivedAt: string | null; // 已可见事件的最新接收时间
  items: AuditItem[];
  nextCursor: string | null;
  hasNext: boolean;
  limitReached: boolean; // 匹配结果超过本次快照10000条上限
  pageSize: number;
}
interface AuditValue {
  state: 'VALUE' | 'NULL' | 'ABSENT' | 'UNKNOWN';
  value: string | boolean | null;
}
interface AuditDetail extends AuditItem {
  receivedAt: string;
  resultCode: string | null;
  resultMessage: string | null;
  changes: Array<{
    fieldKey: string;
    fieldLabel: string;
    before: AuditValue;
    after: AuditValue;

}

```

列表不返回changes和内部操作者登录信息；详情也不返回actorUserId、ownerAccountId、内部错误堆栈。空结果返回items=[]、hasNext=false、nextCursor=null。

### 7.5 能力及候选项

能力接口返回 `requestId, accountContextId, data`；data包含 `timezone="Asia/Shanghai"`、`maxRangeDays=90`、`earliestQueryableDate`（无历史时null）、`enabledEvents`（code/module/label）、`coverageStatus=COMPLETE|PARTIAL|NOT_CONNECTED`、用户可读 `coverageMessage`。COMPLETE只表示本版已约定事件全部接入，不代表任意系统操作均被记录。

候选接口参数：`type=ACTOR|SERVICE`、startDate、endDate、keyword（最多100字符，可空）、cursor（可空）；每页固定20条，返回 `requestId, accountContextId, items[{id,label,secondaryLabel}], nextCursor, hasNext`。同一ID存在多种历史名称时显示区间内最近快照，搜索可匹配历史别名；不把其他审计域名称暴露为候选项。

### 7.6 分页一致性

首期推荐短期服务端查询快照，避免新增或延迟到达日志导致重复、漏页：首次查询在一致性读中按 `occurred_at DESC, id DESC` 固定前10000条匹配ID，存储为带身份、权限版本及筛选哈希的短期快照。游标仅保存签名令牌及位置，不信任客户端偏移。

快照TTL本版设15分钟；上限10000条、每身份最多3个活跃快照，超限时提示缩小范围或重新查询。返回字段 `limitReached: boolean`；若为true，页面显示“结果较多，请缩小条件，当前最多浏览10000条”。首版不宣称可翻阅全部无限历史。

快照只保存ID和查询元数据，不缓存整份敏感日志。每页仍校验当前权限并在数据库再次加ownerAccountId条件。归档／清理导致ID消失时提示快照失效重查，不以空洞页冒充完整结果。上一页由前端保存已访问页游标实现；刷新、新查询和变更页大小均创建新快照。

无共享缓存条件的部署可使用短期查询会话存储实现等效快照；不得直接改成无水位offset分页。快照存储属于临时查询设施，不是第二份审计事实表。

### 7.7 错误

400 参数／日期范围不合法；401 登录失效；403 当前身份无权限；404 详情不可查看；409 `AUDIT_CURSOR_EXPIRED` 或筛选／权限版本不匹配；429 查询限流；503 审计查询源不可用。错误响应含 `requestId, code, message`，message可直接展示且不含内部异常信息。

## 8. 数据表结构

### 8.1 建模边界

与概览不同，本模块需要持久化审计事实。建议新增 `portal_audit_logs`；仅在没有既有可靠事件设施时新增业务库 `portal_audit_outbox`。复用现有users、accounts、services和api_keys，不为审计复制业务主表。

以下DDL按MySQL兼容语法给出，TeleDB具体版本的JSON、索引和CHECK支持需在迁移验证时确认。枚举采用varchar加应用校验，避免依赖未验证的CHECK行为。所有datetime为UTC；连接和驱动统一UTC。ID大小写敏感，应用生成且不可包含空白。

### 8.2 审计事实表

```sql
CREATE TABLE portal_audit_logs (
  id VARCHAR(64) CHARACTER SET ascii COLLATE ascii_bin NOT NULL,
  operation_id VARCHAR(64) CHARACTER SET ascii COLLATE ascii_bin NOT NULL,
  batch_id VARCHAR(64) CHARACTER SET ascii COLLATE ascii_bin NULL,
  owner_account_id VARCHAR(64) CHARACTER SET ascii COLLATE ascii_bin NOT NULL,
  actor_user_id VARCHAR(64) CHARACTER SET ascii COLLATE ascii_bin NOT NULL,
  actor_account_id VARCHAR(64) CHARACTER SET ascii COLLATE ascii_bin NOT NULL,
  actor_context_id VARCHAR(64) CHARACTER SET ascii COLLATE ascii_bin NOT NULL,
  actor_name_snapshot VARCHAR(128) NOT NULL,
  actor_role VARCHAR(16) NOT NULL,
  module_code VARCHAR(32) NOT NULL,
  event_code VARCHAR(64) NOT NULL,
  target_type VARCHAR(32) NOT NULL,
  target_id VARCHAR(64) CHARACTER SET ascii COLLATE ascii_bin NULL,
  target_name_snapshot VARCHAR(256) NULL,
  service_id VARCHAR(64) CHARACTER SET ascii COLLATE ascii_bin NULL,
  service_name_snapshot VARCHAR(128) NULL,
  result VARCHAR(16) NOT NULL,
  result_code VARCHAR(64) NULL,
  result_message VARCHAR(512) NULL,
  summary VARCHAR(512) NOT NULL,
  changes_json JSON NOT NULL,
  source_code VARCHAR(64) NOT NULL,
  schema_version SMALLINT UNSIGNED NOT NULL DEFAULT 1,
  occurred_at DATETIME(3) NOT NULL,
  received_at DATETIME(3) NOT NULL,
  PRIMARY KEY (id),
  KEY idx_audit_owner_time (owner_account_id, occurred_at, id),
  KEY idx_audit_owner_actor (owner_account_id, actor_account_id, occurred_at, id),
  KEY idx_audit_owner_event (owner_account_id, event_code, occurred_at, id),
  KEY idx_audit_owner_target (owner_account_id, target_id, occurred_at, id),
  KEY idx_audit_owner_operation (owner_account_id, operation_id),
  KEY idx_audit_owner_service (owner_account_id, service_id, occurred_at, id),
  KEY idx_audit_retention (received_at, id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

`id`等于生产端eventId，用主键实现跨重复投递幂等。operationId可关联同一批操作的多对象事件，因此不单独加唯一约束。源业务幂等控制仍由业务模块负责，不能仅凭审计表主键保证业务不重复执行。

不对业务对象设置级联删除外键；对象删除不能删除日志。ID与快照并存，禁止查询时强制INNER JOIN当前对象，导致已删对象日志消失。物理外键策略遵循现有项目，但不得出现级联删除审计。

名称模糊查询只在已限定账户和最多90天范围内执行，首版不提供无时间边界全表扫描。索引须按真实数据量和查询计划验证；不要给所有字段盲目创建组合索引。

### 8.3 Outbox表（必要时）

```sql
CREATE TABLE portal_audit_outbox (
  event_id VARCHAR(64) CHARACTER SET ascii COLLATE ascii_bin NOT NULL,
  payload_json JSON NOT NULL,
  delivery_status VARCHAR(16) NOT NULL DEFAULT 'PENDING',
  attempts INT UNSIGNED NOT NULL DEFAULT 0,
  next_attempt_at DATETIME(3) NOT NULL,
  lease_until DATETIME(3) NULL,
  lease_token VARCHAR(64) CHARACTER SET ascii COLLATE ascii_bin NULL,
  last_error_code VARCHAR(64) NULL,
  created_at DATETIME(3) NOT NULL,
  delivered_at DATETIME(3) NULL,
  PRIMARY KEY (event_id),
  KEY idx_outbox_dispatch (delivery_status, next_attempt_at, event_id),
  KEY idx_outbox_lease (delivery_status, lease_until)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

状态为PENDING／DELIVERING／DELIVERED／DEAD。payload必须在入Outbox之前完成字段白名单校验，包含审计事实字段但不含消费者赋值的receivedAt。lastErrorCode只能存内部错误分类，不能存密钥或完整异常请求。

确认投递的更新必须校验leaseToken，避免旧工作线程覆盖新租约。发送成功但更新DELIVERED失败时允许再次投递；消费者相同eventId和相同内容视为成功，相同eventId但不同内容拒绝并内部告警，不覆盖原记录。

### 8.4 保留策略

原方案未规定保留期。**本版建议在线保留180天，单次查询最多90天，两者不同；正式期限待确认。** 未配置经确认的生产保留策略前，不启用自动删除任务，不把180天作为法定要求。

清理按receivedAt分批执行，避免迟到事件刚入库即被清除；操作时间仍按occurredAt查询，早于可查询窗口的迟到记录可留存但不保证在默认范围出现。能力接口的earliestQueryableDate应基于可查询数据和服务配置计算，不简单将当前时间减180天。

Outbox建议已成功投递保留7天后清理；PENDING、DELIVERING、DEAD不得按普通TTL自动删除。保留策略上线前应另行明确备份和归档需求。

查询账号只具备读取审计表权限；写入服务具备插入权限，常规业务接口不具备更新／删除审计事实权限。归档清理使用独立维护权限。首版不宣称具备密码学防篡改能力。

## 9. 数据字典补充

| 字段／枚举 | 解释及校验 |
|---|---|
| id／eventId | 事件唯一标识，1～64个ASCII字符，重投保持不变 |
| operationId | 业务操作编号，非查询requestId；复制给支持人员排查 |
| batchId | 批量操作关联编号，可空，不作为单条日志唯一键 |
| ownerAccountId | 发生时可信主账户审计域，落库后不因当前关系变化改写 |
| actorNameSnapshot | 当时的显示名称，不存电话／邮箱作为替代名；缺少显示名用“账户+ID尾部” |
| actorRole | MAIN／SUB；本期不接入SYSTEM或运营管理员事件 |
| moduleCode | API_KEY／SUBACCOUNT／ALERT |
| targetType | API_KEY／SUBACCOUNT／QUOTA_ASSIGNMENT／ALERT |
| targetId | 已授权且存在的目标ID；创建失败未分配ID或越权拒绝时可空 |
| serviceId | 有明确授权关联时填写；账户级操作可空 |
| resultCode | 稳定业务错误分类，可空，例如VALIDATION_FAILED、PERMISSION_DENIED；不直接存SQL错误 |
| resultMessage | 可读安全原因；拒绝跨账户对象时采用通用“无权执行该操作” |
| sourceCode | 产出事件的可信服务代码，服务端白名单，不由浏览器传入 |
| schemaVersion | 事件结构版本，初始1；新增字段应兼容旧事件 |
| occurredAt | 权威业务提交／拒绝／失败确认时刻，不使用浏览器时间 |
| receivedAt | 审计服务接收入库时刻，消费端生成 |
| changesJson | 变更项数组；空数组表示无真实变更／没有采集字段，不是失败 |
| queryAsOf | 分页查询快照时间，不代表所有此前事件已到达 |
| latestReceivedAt | 已可见记录接收时间，null表示无已可见记录 |

业务数量在changes中使用精确十进制字符串，配额携带unit，沿用所属模块的token／point等实际单位；不可在审计层自行换算。状态值展示采用事件版本对应字典，不用未来改名后的字典篡改历史语义。

事件载荷建议上限32KiB、变更项最多20项；业务接入前应验证白名单可在限额内表达。超限时拒绝审计写入并按第6章事务策略处理，不静默截断导致关键信息消失。

## 10. 实现约束与代码生成说明

1. 只实现本模块和审计接入基础设施，不根据事件目录补建未经要求的密钥、子账户或告警业务功能。
2. 前端建议拆分AuditFilter、AuditTable、AuditDetailDrawer、AuditChangeTable及统一api服务；筛选表单的草稿状态和已提交状态分离。
3. 后端区分AuditQueryService、AuditEventWriter、AuditEventValidator和可选OutboxDispatcher。所有查询先取得可信审计域再构造SQL，不能先按ID查全量实体再返回前端过滤。
4. 首版可以先Mock页面和事件源，但生产环境不回退到Mock；能力接口准确披露实际接入范围。
5. 不使用通用AOP直接序列化方法全部参数／返回值；可以用拦截器传递身份和operationId，具体before／after必须由业务服务显式构建。
6. 不把HTTP200当作业务成功，不在controller返回后用无持久化保证的异步线程作为唯一留痕方式。
7. 不因日志页面只读而省略写入链路的事务、幂等和权限测试；本模块的价值依赖日志真实、隔离和可追溯。
8. 如仓库已有审计表或可靠事件组件，先评估复用，通过字段适配满足本文，避免部署第二套事实存储。
9. 不修改已有公共设计、工作台规格中的未确认规则；存在冲突在交付说明列出，不由代码生成模型自行决定跨模块业务规则。
10. 交付包含页面与接口、迁移或复用说明、事件接入矩阵、Mock场景及实际验证结果。

## 11. 验收标准

| 编号 | 场景 | 预期 |
