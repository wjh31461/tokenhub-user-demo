## 第一部分：需求分析与页面交互

## 1. 模块定位与范围

### 1.1 模块定位

模型目录是 TokenHub 用户门户中帮助用户完成模型发现、选型和接入准备的只读模块。它回答以下问题：

1. TokenHub 当前对外开放哪些平台模型？
2. 每个模型支持什么输入类型、接口和能力？
3. 模型的公开 `model` 标识是什么，调用时如何填写？
4. 模型按什么用户价格或倍率扣减？
5. 当前业务身份及已订购服务是否可以使用该模型？
6. 用户下一步如何查看接口文档并创建密钥？

模型目录展示的是平台归一化后的“平台模型”，不是底层供应商模型清单。同一个平台模型背后可关联多个供应商及多个端点，TokenHub 根据能力、价格、健康度和路由策略选择实际渠道，但这些内部信息不进入用户门户。

### 1.2 用户价值

- 让用户在创建 API Key 或接入应用前明确可选模型和能力。
- 用统一口径比较模型，不要求用户理解不同供应商的接口差异。
- 明确价格或倍率，减少调用后对额度扣减的疑问。
- 将模型选型、API 文档、密钥和用量记录连接成完整使用路径。
- 在模型上下架、能力或价格变化时，为用户提供可发现的状态和说明。

### 1.3 本期交付范围

- 模型目录列表页：搜索、筛选、排序、模型卡片、分页和状态反馈。
- 模型详情页：基础信息、公开标识、能力、上下文与限制、价格、兼容接口、使用说明和变更提示。
- 基于当前业务身份和订购服务的“可使用/暂不可使用/待确认”提示。
- 跳转接入文档、API 密钥和用量中心的上下文联动。
- 主账户与子账户的数据隔离、接口契约、错误码和埋点要求。
- 模型下架、价格待确认、能力信息不完整等异常状态。

### 1.4 首版不做

- 在线聊天、模型体验或 Playground。
- 创建、编辑、审核、上下架平台模型。
- 模型训练、微调、评测、部署或权重下载。
- 用户侧模型权限申请和审批。
- 用户主动选择供应商、渠道或底层端点。
- 展示供应商名称、供应商模型标识、上游价格、平台成本、毛利、路由权重、熔断和健康数据。
- 展示或管理供应商凭证、业务密钥。
- 模型收藏、用户评分、评论、排行榜和个性化推荐。
- 在目录内模拟费用或根据用户输入预估精确扣减。

未接入的功能不得显示可点击的假按钮；在线体验若后续建设，应作为独立需求评审。

### 1.5 与其他模块的关系

| 模块 | 模型目录使用的数据或入口 | 边界 |
|---|---|---|
| 公共身份框架 | 当前 `accountContextId`、身份类型、权限 | 后端决定数据范围，前端不信任传入账户 ID |
| 我的服务 | 当前有效 Token 服务、服务状态、可用模型范围 | 不查询订单、余额或额度包明细，不在目录办理订购 |
| API 密钥 | “创建/管理 API 密钥”入口 | 目录不展示密钥原文，不创建业务密钥 |
| 用量中心 | 平台模型 ID、历史名称、`model` 标识 | 可按模型跳转筛选用量；历史调用不因模型下架消失 |
| 接入文档 | 模型类型对应的 API 文档和代码示例 | 目录只提供摘要及上下文跳转，不复制完整接口文档 |
| 平台公告 | 模型上线、下架、维护或价格变更公告 | 目录展示摘要，正式通知及历史由公告模块维护 |
| 运营管理门户 | 平台模型配置、提供商模型映射、价格和能力数据 | 用户门户只读，不暴露运营字段 |
| 模型聚合代理 | 运行时选模、渠道选择、路由与容灾 | 目录不参与单次请求路由，不展示实时渠道状态 |

## 2. 核心业务对象和概念

### 2.1 平台模型

平台模型是 TokenHub 对用户开放的逻辑模型。用户调用公开接口时，通过请求体中的 `model` 字段填写平台模型标识。平台模型由运营人员维护，可在后台关联一个或多个提供商模型。

用户门户只识别稳定的 `platformModelId` 和公开 `modelCode`：

- `platformModelId`：平台内部稳定 ID，用于页面路由和接口关联，不建议用户复制使用。
- `modelCode`：面向用户的公开模型标识，用于调用请求的 `model` 字段。
- `displayName`：页面展示名称，可在不修改 ID 的情况下调整。

### 2.2 模型类型与开放接口

平台按能力类型提供统一开放接口，例如文生文、文生图。一个模型只能出现在其实际支持的模型类型中；同类型模型可共享公开接口，通过 `model` 字段区分。

模型详情必须明确：

- 模型类型；
- 支持的公开接口协议；
- 对应接入文档；
- 该接口下公开使用的 `modelCode`。

用户不需要知道平台实际转发到哪个供应商接口端点。

### 2.3 模型能力

能力用于描述模型是否可处理某类请求参数。首版至少支持以下标准能力：

| 能力代码 | 用户文案 | 含义 |
|---|---|---|
| `TOOL_CALLING` | 工具调用 | 支持模型按接口约定返回工具调用信息 |
| `VISION_INPUT` | 视觉输入 | 支持在请求中提交图片等视觉内容 |
| `LONG_CONTEXT` | 长上下文 | 达到平台定义的长上下文阈值；仍需展示具体上限 |
| `THINKING` | 思考模式 | 支持请求启用模型推理/思考相关参数 |
| `STRUCTURED_OUTPUT` | 结构化输出 | 支持按平台接口约定输出结构化内容 |
| `STREAMING` | 流式输出 | 支持流式返回结果 |

能力配置来源为平台模型管理，不由门户根据模型名称猜测。若同一平台模型背后的提供商能力不齐，运营后台应给出“平台对用户承诺的能力交集或可稳定路由能力”；门户只展示平台已确认的公开能力。

### 2.4 用户价与定价倍率

原方案允许展示“用户价或定价倍率”，但两者代表不同计价口径，页面不得混合成一个无单位数字。

本版设计采用可扩展价格结构：

- `UNIT_PRICE`：直接展示输入、缓存命中输入、缓存写入、输出等用户单价及单位。
- `MULTIPLIER`：展示模型相对基础计价单位的扣减倍率。
- `INCLUDED`：已包含在所订购服务权益中，不单独展示单价；仅在计费系统明确返回时使用。
- `CONTACT`：价格未公开或需另行确认。

价格是模型目录中的公开计价说明，不等于用户余额、套餐额度、供应商成本或最终账单。实际扣减以计费/额度服务记录为准。

## 3. 用户、身份和权限

### 3.1 权限码

建议权限码：`portal.models.read`。主账户和子账户均可按业务需要授予。

### 3.2 身份数据范围

| 身份 | 可见范围 | 可用性判断 |
|---|---|---|
| 主账户 | 平台对该主账户业务域开放的模型 | 根据主账户有效 Token 服务及服务模型范围判断 |
| 子账户 | 平台允许子账户查看的模型 | 同时受主账户服务有效性、主账户为子账户开放的模型范围和子账户状态约束 |
| 无模型目录权限 | 不返回模型数据 | 返回 403，由公共框架显示无访问权限 |

本版不展示其他账户、其他子账户或供应商侧信息。身份切换后必须清空旧模型列表、详情和服务可用性结果，并按新 `accountContextId` 重新查询。

### 3.3 “可见”与“可使用”

可见性和可使用性必须区分：

- **可使用 `AVAILABLE`**：当前身份至少有一个有效服务允许调用该模型。
- **暂不可使用 `NOT_ENTITLED`**：模型可在目录中了解，但当前身份没有覆盖该模型的有效服务。
- **服务受限 `SERVICE_RESTRICTED`**：服务存在，但停机、冻结、到期或其他状态阻止调用。
- **信息待确认 `UNKNOWN`**：服务或模型范围数据暂不可用，不能误显示“可使用”。
- **即将下架 `DEPRECATED`**：模型仍可使用，但已发布停止新调用或停止服务计划。

目录中的可使用状态仅用于说明当前业务关系，不替代网关在每次请求时的密钥、服务、流控和额度校验；即使目录显示可使用，请求也可能因密钥无效、余额不足或限流被拒绝。

### 3.4 子账户约束

- 子账户不接收主账户余额、订单、套餐金额或其他子账户信息。
- 子账户可查看自己是否能够使用某模型，但不展示造成限制的主账户敏感细节。
- 子账户是否可进入 API 密钥和接入文档，由后端分别返回 `canManageApiKey`、`canReadDocs`，不能仅凭身份类型硬编码。
- 子账户没有订购入口；若模型不可用，默认提示“当前账户暂不可使用，请联系主账户管理员”。

## 4. 页面信息架构

### 4.1 页面结构

```text
模型目录                                               [接入文档]
查看 TokenHub 当前开放的模型能力、公开标识和用户计价

[搜索模型名称或 model 标识________________] [搜索]
模型类型 [全部 ▾]  能力 [多选 ▾]  可用状态 [全部 ▾]
接口协议 [全部 ▾]  [重置]

共 N 个模型                         排序 [综合排序 ▾]

[模型卡片] [模型卡片] [模型卡片]
[模型卡片] [模型卡片] [模型卡片]

[上一页] 第 N 页 [下一页]
```

点击模型卡片进入详情页：

```text
模型目录 / 模型名称

模型名称                     [当前可使用]  [复制 model 标识]
一句话简介
model: model-code

[能力概览] [计价说明] [接口与限制] [更新说明]

下一步
[查看接入文档] [管理 API 密钥] [查看该模型用量]
```

首版详情可采用单页分区，不强制使用标签页；若内容较长，可用锚点导航，但不得因标签切换丢失当前模型上下文。

### 4.2 URL 状态

列表页已执行的筛选条件同步到 URL，建议参数：

- `keyword`
- `modelType`
- `capability`，多值以重复参数或逗号形式实现，项目内统一
- `availability`
- `protocol`
- `sort`
- `page`
- `pageSize`

详情路由使用稳定 `modelId`，不使用可变展示名称。未知或无权访问的模型统一返回 404，防止通过 ID 探测不可见资源。

## 5. 模型目录列表页

### 5.1 首次进入

- 默认展示当前身份可见的所有已发布模型。
- 默认每页 12 或 20 个模型，由页面布局确定；同一版本固定，不按屏幕宽度改变分页总数。
- 默认排序为运营排序 `RECOMMENDED`，相同排序值时按模型名称和稳定 ID 保序。
- 页面顶部显示目录数据更新时间，不把浏览器当前时间当作数据更新时间。
- 从身份切换进入时，清空上一身份的筛选结果；是否保留纯展示筛选可后续评估，首版统一重置。

### 5.2 搜索

搜索范围：

- 模型展示名称；
- 公开 `modelCode`；
- 模型别名；
- 模型简介中的运营关键词。

搜索规则：

- 去除首尾空格，空字符串按未搜索处理。
- 最长 100 个字符，超长由前后端共同校验。
- 英文大小写不敏感；中文按完整关键词匹配，是否支持分词由搜索服务能力决定。
- 输入后点击“搜索”或按 Enter 执行，防止每次按键触发请求。
- 搜索词和筛选条件共同生效。
- 搜索无结果时保留条件，并提供“清除筛选”操作。

### 5.3 筛选

| 筛选项 | 选项来源 | 规则 |
|---|---|---|
| 模型类型 | 后端返回的当前可见类型 | 单选；例如文生文、文生图 |
| 模型能力 | 标准能力字典 | 多选；多个能力按“同时具备”匹配 |
| 可用状态 | AVAILABLE、NOT_ENTITLED、SERVICE_RESTRICTED、DEPRECATED | 单选；UNKNOWN 可由异常提示呈现 |
| 接口协议 | 当前公开协议字典 | 单选；如 OpenAI 兼容、Anthropic 兼容 |

筛选选项本身也必须经过当前身份可见范围裁剪，不能泄露不可见模型类型或内部协议。

### 5.4 排序

首版支持：

- 综合排序：后台运营排序，其次模型名称。
- 名称升序。
- 最近更新：按公开信息更新时间降序。
- 价格排序是否支持，取决于所有模型是否存在可比较的统一价格口径；在价格单位和结构不统一前不提供。

不得按供应商成本、路由质量或后台健康度排序。

### 5.5 模型卡片

每个模型卡片展示：

- 模型名称；
- 一句话简介，最多两行，完整内容可在详情查看；
- 公开 `modelCode`，支持复制；
- 模型类型；
- 最多四个核心能力标签，剩余显示“+N”；
- 核心规格摘要，例如上下文上限；
- 价格摘要或倍率摘要；
- 当前身份可用状态；
- 即将下架/价格变更等重要提示；
- “查看详情”入口。

卡片不展示：提供商、供应商模型名、端点 URL、渠道数、健康状态、成本价、毛利、路由策略。

### 5.6 价格摘要

价格结构较复杂时，卡片只展示可准确比较的最小摘要：

- 单价型：展示“输入 ¥X / 百万 Token 起”等明确单位，并提示详情含完整输入/输出价格。
- 倍率型：展示“X 倍额度”，并在详情解释基础计价单位。
- 多模态或非 Token 计价：展示主计价项和“查看完整价格”。
- 无法确认：显示“价格待确认”，不得显示 0 或“免费”。

### 5.7 分页与结果数量

- 使用服务端分页，返回当前筛选下的 `total`。
- 支持上一页、下一页和页码；大数据量可仅支持稳定游标，但产品展示应保持一致。
- 删除或下架导致当前页为空时，自动回退到最后一个有效页并重新查询。
- 更改搜索、筛选、排序或每页条数后回到第 1 页。

## 6. 模型详情页

### 6.1 顶部摘要

展示：

- 模型名称、简介、模型类型；
- 公开 `modelCode` 及复制按钮；
- 当前身份可用状态；
- 公开信息更新时间；
- 即将下架、价格变更或能力调整提示。

复制成功只表示文本已写入剪贴板，不表示已创建密钥或已完成接入。

### 6.2 能力概览

展示平台已确认的标准能力、输入/输出模态及简要说明：

- 工具调用；
- 视觉输入；
- 长上下文及具体上下文上限；
- 思考模式；
- 结构化输出；
- 流式输出；
- 其他模型类型扩展能力。

每项能力采用“支持/不支持/未确认”三态，未知不得按不支持处理。若能力依赖接口协议或特定参数，应在能力说明中明确并链接接入文档。

### 6.3 规格与限制

按模型类型展示差异字段，文生文首版建议包括：

- 最大上下文长度；
- 最大输出长度；
- 支持的输入模态；
- 支持的输出模态；
- 支持语言或适用说明；
- 是否支持流式输出；
- 已知限制和不适用场景；
- 请求体或媒体大小限制应引用平台开放接口限制，不把供应商内部限制直接暴露给用户。

未知数值显示“暂无公开信息”，不显示 0。所有 Token 长度字段要明确单位，不能用 `K` 而不提供完整数值或解释。

### 6.4 用户计价

详情页必须同时展示：

- 价格类型及完整价格项；
- 每项名称、数值、币种/额度单位、计量单位；
- 生效时间；
- 计价说明；
- “实际扣减以用量中心和额度账本为准”的说明；
- 未来价格已发布时的生效日期与变更入口。

单价型文生文模型可分别展示：

- 输入 Token；
- 缓存命中输入 Token；
- 缓存写入 Token（若有独立价格）；
- 输出 Token。

没有缓存价格时不补 0。非 Token 模型按其真实计量单位展示，例如张、秒或次；不同单位不强行折算为 Token。

### 6.5 接口与使用说明

展示：

- 公开接口名称；
- 协议兼容类型；
- 请求 `model` 字段示例；
- 接入文档入口；
- API 密钥管理入口；
- 与当前模型有关的最小调用示例可选展示，但完整字段说明由接入文档维护。

示例不得包含真实密钥。基础 URL、认证头和请求参数由文档服务提供或统一配置，不在前端硬编码多份。

### 6.6 当前账户可用性

详情页展示可用性结论及不敏感的原因摘要：

| 状态 | 主账户文案及操作 | 子账户文案及操作 |
|---|---|---|
| AVAILABLE | 当前账户可使用；查看文档、管理密钥 | 当前账户可使用；按权限查看文档或管理密钥 |
| NOT_ENTITLED | 当前账户暂无可用服务；查看我的服务或 CRM 办理说明 | 当前账户暂不可使用；联系主账户管理员 |
| SERVICE_RESTRICTED | 关联服务当前受限；查看我的服务 | 当前账户暂不可使用；联系主账户管理员 |
| UNKNOWN | 暂时无法确认使用状态；支持重试 | 暂时无法确认使用状态；支持重试 |
| DEPRECATED | 显示停止服务时间和迁移建议 | 同左，不展示主账户敏感信息 |

不在此处显示精确余额，也不以余额是否大于零判断“可使用”；余额不足属于调用准入和我的服务/告警范围。

### 6.7 更新与下架说明

- 模型刚上线时可显示上线日期。
- 模型能力、价格或公开标识发生影响接入的变化时，应显示简要变更说明。
- 即将下架模型必须展示公告时间、停止新接入时间（若适用）、停止服务时间和建议替代模型。
- 已完全下架模型默认不出现在目录列表；已有历史调用可从用量中心显示历史名称，跳转详情时进入只读历史说明页或 410 页面，具体策略待确认。
- 下架模型不能因页面隐藏而删除历史计量、审计或公告记录。

## 7. 跨模块跳转

### 7.1 接入文档

跳转建议：`/help/docs?modelId={modelId}&modelType={modelType}`。目标页面校验模型可见性，并按模型类型定位对应接口文档。模型目录不直接传递内部端点 URL。

### 7.2 API 密钥

跳转建议：`/api-keys?from=models&modelId={modelId}`。API 密钥模块可显示来源提示，但创建的用户密钥是否限制具体模型以密钥模块和服务规则为准，目录不得暗示“一模型一密钥”。

### 7.3 用量中心

跳转建议：`/usage?tab=statistics&platformModelId={modelId}`。用量中心按当前身份和历史调用归属校验范围。即使模型已下架，历史调用仍可按历史平台模型 ID 查询。

### 7.4 我的服务

模型暂不可使用时，可跳转 `/services?modelId={modelId}` 帮助主账户了解现有服务。我的服务是否支持按模型反查服务由该模块定义；未支持前只跳转服务列表，不伪造推荐套餐。

## 8. 页面状态与异常处理

### 8.1 加载状态

- 列表首次加载显示卡片骨架，不显示旧身份数据。
- 更改筛选后可保留页面框架，但旧结果应明确处于刷新状态，避免误认为新条件结果。
- 详情的基础信息和当前账户可用性可分区加载；若可用性失败，基础信息仍可展示。

### 8.2 空状态

- 平台暂无可见模型：显示“当前暂无开放模型”，不引导创建密钥。
- 搜索/筛选无结果：显示“当前条件下未找到模型”，提供清空筛选。
- 当前账户无可使用模型但存在可见目录：仍展示模型，统一提示当前账户暂无可用服务。

### 8.3 错误状态

- 列表整体错误：显示通用错误和重试按钮，不把错误当作空列表。
- 可用性分区错误：显示“暂时无法确认”，不降级成可使用。
- 价格分区错误：显示“价格暂不可用”，不缓存或显示未经验证的 0。
- 接口返回未知枚举：按未知状态安全展示并上报前端异常，不按正常状态处理。
- 401、403、404 遵循公共设计；错误信息不得暴露供应商或内部路由细节。

### 8.4 旧数据降级

若平台允许使用缓存旧数据：

- 必须与当前身份、权限版本、筛选条件一致；
- 明确显示原数据截至时间；
- 价格、上下架状态和可用性不应长期使用过期缓存；
- 旧数据不得用于实际调用准入或费用结算。

## 9. 响应式与可访问性

- 桌面端优先，卡片根据内容区宽度显示 2～4 列；卡片阅读顺序与 DOM 顺序一致。
- 窄屏时筛选项可折叠，但已应用条件必须可见且可清除。
- 卡片整体可进入详情时仍要保证复制按钮、标签和链接具备独立可访问名称，避免嵌套交互冲突。
- 状态不能只依赖颜色；使用文字和图标共同表达。
- 所有按钮支持键盘操作和清晰焦点样式。
- 复制结果通过可访问提示反馈。
- 价格表在窄屏可横向滚动，表头与单位保持可见或在每项重复说明。

## 11. 接口设计

接口前缀示例为 `/api/portal/v1`，实际以前后端统一网关前缀为准。当前身份通过已验证会话或 `X-Account-Context-Id` 传递。

### 11.1 查询模型目录

`GET /api/portal/v1/models`

查询参数：

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `keyword` | string | 否 | 名称、公开标识、别名或关键词，最多 100 字符 |
| `modelType` | string | 否 | 模型类型代码 |
| `capabilities` | string[] | 否 | 能力代码，多项按同时具备 |
| `availability` | string | 否 | 当前身份可用状态 |
| `protocol` | string | 否 | 公开兼容协议 |
| `sort` | string | 否 | `RECOMMENDED`、`NAME_ASC`、`UPDATED_DESC` |
| `page` | integer | 否 | 从 1 开始 |
| `pageSize` | integer | 否 | 建议 12、20、40，服务端限制最大值 |

响应示例：

```json
{

  "accountContextId": "acct_ctx_001",

      "contextWindowTokens": "128000",
      "protocols": ["OPENAI_CHAT", "ANTHROPIC_MESSAGES"],
      "pricingSummary": {
        "pricingType": "UNIT_PRICE",
        "displayText": "输入价格见详情",
```

`total` 使用十进制字符串，避免统一契约中的大整数精度问题。价格摘要由后端生成安全文案，但详情仍返回结构化价格项。

### 11.2 查询模型详情

`GET /api/portal/v1/models/{modelId}`

响应核心结构：

```ts
interface ModelDetail {
  modelId: string;
  displayName: string;
  modelCode: string;
  aliases: string[];
  summary: string;
  description: string;
  modelType: { code: string; name: string };
  lifecycle: 'ACTIVE' | 'DEPRECATED';
  capabilities: Array<{
    code: string;
    name: string;
    support: 'SUPPORTED' | 'UNSUPPORTED' | 'UNKNOWN';
    description: string | null;
  }>;
  specifications: Array<{
    code: string;
    name: string;
    value: string | null;
    unit: string | null;
  }>;
  protocols: Array<{
    code: string;
    name: string;
    docsPath: string | null;
  }>;
  pricing: ModelPricing | null;
  availability: ModelAvailability;
  notices: ModelNotice[];
  updatedAt: string;
  dataAsOf: string;
}
```

价格结构：

```ts
interface ModelPricing {
  pricingType: 'UNIT_PRICE' | 'MULTIPLIER' | 'INCLUDED' | 'CONTACT';
  currencyOrUnit: string | null;
  effectiveAt: string | null;
  items: Array<{
    code: string;
    name: string;
    amount: string;
    perQuantity: string;
    measureUnit: string;
  }>;
  description: string | null;
  upcoming: {
    effectiveAt: string;
    items: ModelPricing['items'];
    announcementId: string | null;
  } | null;
}
```

金额、倍率和数量均使用字符串。`pricing=null` 表示该身份无权查看或数据不可用时，必须结合分区状态或错误码区分，不能默认免费。

### 11.3 查询筛选选项

筛选选项可随列表一起返回，也可独立提供：

`GET /api/portal/v1/models/filter-options`

独立接口适用于选项较稳定且需要缓存的场景。缓存键必须包含权限版本和业务域；不得跨身份复用未经裁剪的选项。

### 11.4 查询历史下架模型摘要

若用量中心允许跳转已下架模型，可提供：

`GET /api/portal/v1/models/{modelId}/history-summary`

仅返回历史展示名称、公开标识、下架时间、替代模型和公告链接，不返回当前目录外的敏感配置。是否提供本接口由下架策略评审后决定。

## 12. 后端编排与数据来源

### 12.1 建议数据来源

| 数据 | 权威来源 | 门户处理 |
|---|---|---|
| 平台模型基础信息 | 平台模型管理 | 读取已发布、面向当前业务域可见的数据 |
| 模型能力与规格 | 平台模型管理/能力配置 | 归一化为标准能力代码 |
| 公开协议与文档映射 | 开放接口管理/文档配置 | 只返回用户可见协议和文档路由 |
| 用户价格或倍率 | 平台定价/计费配置 | 返回当前有效及已发布的未来价格 |
| 当前服务及模型范围 | 我的服务/权益服务 | 计算当前身份可用性，不返回订单敏感信息 |
| 生命周期与公告 | 平台模型管理/公告 | 返回当前提示和公告 ID |

### 12.2 聚合原则

- 列表查询优先读取面向门户的模型目录读模型，避免逐模型串行查询权益和价格。
- 可用性应按当前身份批量计算，禁止列表页产生 N+1 下游调用。
- 权限和可见性裁剪先于聚合与缓存。
- 提供商模型与端点数据不得进入门户 DTO，即使前端暂不显示也不能返回。
- 下游部分失败时允许基础目录与可用性/价格分区独立降级，但每个分区必须有明确状态。

### 12.3 一致性要求

- 平台模型上下架、公开标识和价格变更应通过事件或缓存失效机制同步到门户读模型。
- 价格生效以服务端时间和配置生效时间为准，前端不自行切换。
- 目录展示的 `modelCode` 必须与网关实际可接受标识一致；发布流程需进行唯一性和可调用性校验。
- 模型能力必须与路由可稳定提供的能力一致，不能展示只有单个异常渠道偶尔支持的能力。

## 13. 数据模型建议

若平台模型管理已有权威表，用户门户不重复建设主数据表。本节描述门户查询所需的逻辑数据，具体表名服从现有架构。

### 13.1 平台模型逻辑字段

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `model_id` | varchar | 是 | 稳定平台模型 ID |
| `model_code` | varchar | 是 | 用户调用时使用的公开标识，同开放范围内唯一 |
| `display_name` | varchar | 是 | 展示名称 |
| `summary` | varchar | 是 | 卡片简介 |
| `description` | text | 是 | 详情说明 |
| `model_type` | varchar | 是 | 模型类型 |
| `lifecycle_status` | varchar | 是 | 草稿、上架、废弃、下架等；门户只返回允许状态 |
| `sort_order` | integer | 是 | 运营排序 |
| `published_at` | datetime | 否 | 首次上架时间 |
| `updated_at` | datetime | 是 | 公开信息更新时间 |

### 13.2 能力逻辑字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `model_id` | varchar | 平台模型 ID |
| `capability_code` | varchar | 标准能力代码 |
| `support_status` | varchar | SUPPORTED、UNSUPPORTED、UNKNOWN |
| `description` | varchar | 对用户的限制说明 |

`model_id + capability_code` 唯一。不得从提供商能力表直接无规则合并到门户；需由平台模型公开能力配置确定。

### 13.3 价格逻辑字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `pricing_id` | varchar | 价格版本 ID |
| `model_id` | varchar | 平台模型 ID |
| `pricing_type` | varchar | 单价、倍率、包含、联系确认 |
| `currency_or_unit` | varchar | CNY、point 等 |
| `effective_at` | datetime | 生效时间 |
| `expired_at` | datetime | 失效时间，允许为空 |
| `status` | varchar | 待生效、生效、失效 |

同一模型、同一价格适用范围在同一时刻只能有一个有效价格版本。具体价格项可使用子表存储 `item_code`、`amount`、`per_quantity`、`measure_unit`。

### 13.4 可见范围与服务范围

平台模型可见范围、服务包含模型范围和子账户授权范围应由现有权益模型维护。门户查询可建立物化读模型或缓存，但不能以门户本地表成为权威来源。

## 14. 安全、性能和可观测性

### 14.1 安全

- 所有列表和详情接口执行登录认证、模块权限和当前身份校验。
- 对不可见模型返回 404，不区分不存在或无权限。
- 描述和公告内容经过安全富文本白名单处理，防止脚本注入。
- 复制、跳转和埋点不得携带供应商模型、端点、凭证、成本或内部路由信息。
- 后端 DTO 采用白名单映射，不直接序列化运营管理实体。

### 14.2 性能目标

- 列表接口 P95 不超过 1.5 秒，首屏页面 P95 不超过 2 秒，不含用户本地网络异常。
- 详情接口 P95 不超过 1.5 秒；可用性/价格分区允许独立超时降级。
- 模型数量预计较少仍使用服务端分页，禁止一次返回全量详情和完整价格历史。
- 搜索和筛选字段建立适当索引；能力多选应避免在应用层全量过滤。
- 缓存不得跨身份、权限版本和业务域污染。

### 14.3 日志与指标

后端记录：

- `requestId`、当前身份匿名化标识、筛选摘要、响应数量、耗时和结果；
- 下游平台模型、权益和价格服务的耗时与错误类型；
- 不记录密钥原文、请求内容或供应商凭证。

建议监控：

- 目录/详情接口成功率和 P95/P99；
- 价格、可用性分区降级率；
- 404/403 比例；
- 模型发布后门户同步延迟；
- 目录 `modelCode` 与网关配置一致性检查结果。

### 14.4 产品埋点

| 事件 | 关键属性 |
|---|---|
| `model_catalog_view` | 身份类型、默认筛选 |
| `model_search` | 关键词长度、筛选项、结果数量，不采集敏感原文可做哈希或分类 |
| `model_card_open` | modelId、列表位置、可用状态 |
| `model_code_copy` | modelId、入口位置 |
| `model_docs_click` | modelId、协议 |
| `model_api_key_click` | modelId、可用状态 |
| `model_usage_click` | modelId |

埋点不采集供应商、端点、价格成本或账户余额。

## 15. 待确认事项

| 编号 | 事项 | 影响 | 当前处理 |
|---|---|---|---|
| Q01 | 目录展示全部已开放模型，还是仅展示当前服务可使用模型 | 列表范围、空状态、选型体验 | 本版展示可见模型并区分可用状态 |
| Q02 | Token 服务是否限制可使用的模型范围 | 可用性算法、我的服务联动 | 预留权益范围，不假定全部模型通用 |
| Q03 | 用户价使用直接单价、定价倍率还是两者并存 | 卡片和详情价格结构 | 采用可扩展 `pricingType`，禁止混用 |
| Q04 | 额度的实际单位及不同模型倍率扣减规则 | 价格文案、用户理解 | 不在目录自行换算，等待计费定义 |
| Q05 | 输入、缓存命中、缓存写入和输出的用户价格项是否全部存在 | 价格表字段 | 缺失显示未提供，不补零 |
| Q06 | 非 Token 模型采用什么计量单位 | 文生图等价格展示 | 使用结构化真实单位，不折算 Token |
| Q07 | `auto` 是独立平台模型、路由模式还是接口参数 | 列表项、详情、用量归属 | 首版不创建 Auto 卡片，确认后补充 |
| Q08 | 子账户是否可查看全部目录、接入文档及创建密钥 | 权限与入口 | 后端分别返回能力，不由前端硬编码 |
| Q09 | 模型下架后的详情访问和历史跳转策略 | 用量中心联动、SEO/路由 | 预留历史摘要或 410 页面 |
| Q10 | 模型价格、能力和下架变更提前多久公告 | 变更提示、缓存失效 | 由运营规则和公告模块确认 |
| Q11 | 长上下文的标签阈值是多少 | 能力标签一致性 | 由后台配置或产品统一定义，不由前端判断 |
| Q12 | 公开接口当前实际支持哪些协议及协议转换边界 | 协议筛选、文档映射 | 从开放接口管理读取已确认协议 |
| Q13 | 是否存在仅特定行业/组织可见的模型 | 可见范围和缓存键 | 预留业务域/组织范围控制 |
| Q14 | 是否需要展示模型服务可用性或维护状态 | 用户预期、内部信息边界 | 首版仅展示目录生命周期和账户可用性，不展示渠道实时健康 |

## 16. Mock 场景

至少准备以下稳定 Mock 场景，禁止使用每次刷新随机变化的数据：

1. 主账户：多个模型，包含可使用和未覆盖模型。
2. 子账户：可使用模型较少，不返回主账户敏感原因。
3. 能力完整的文生文模型：工具、视觉、长上下文、思考、流式。
4. 单价型价格：输入、缓存命中、缓存写入、输出价格不同。
5. 倍率型价格：显示倍率与单位说明。
6. 非 Token 计价模型：按张或次计价。
7. 即将下架模型：含停止服务时间、公告和替代模型。
8. 价格待确认：价格为未知，不显示免费或 0。
9. 可用性查询失败：基础详情正常，可用性为 UNKNOWN。
10. 搜索无结果和平台无模型两个不同空状态。
11. 列表整体错误、重试后恢复。
12. 身份切换中旧请求迟到，不得覆盖新身份页面。
13. 详情 ID 不存在或不可见，统一 404。
14. 历史下架模型从用量中心跳转的处理场景。

## 17. 验收标准

### 17.1 功能验收

1. 当前身份具备 `portal.models.read` 时可进入目录；无权限返回 403 且不泄露模型数据。
2. 列表只展示当前身份可见的已发布平台模型，不展示提供商模型和渠道。
3. 用户可按名称或公开 `modelCode` 搜索，并按模型类型、能力、可用状态和协议筛选。
4. 多个能力筛选按“同时具备”执行，清空筛选恢复默认列表。
5. 搜索、筛选、排序和分页状态可从 URL 恢复。
6. 模型卡片展示名称、公开标识、能力、规格摘要、价格摘要和当前可用状态。
7. 公开 `modelCode` 可复制，且与网关可接受的模型标识一致。
8. 详情页正确展示能力三态、上下文/限制、完整价格项、公开协议和使用入口。
9. 未知能力、规格和价格不显示为“不支持”、0 或免费。
10. 当前账户可用性由后端权益结果决定，不根据余额或前端规则自行推断。
11. 子账户页面不返回主账户余额、订单、套餐金额或其他子账户信息。
12. 接入文档、API 密钥、用量中心和我的服务跳转携带正确模型上下文，并由目标模块二次鉴权。
13. 即将下架模型展示停止服务时间、公告和迁移信息；完全下架模型不进入正常目录。
14. 身份切换立即清理旧身份数据，迟到响应不能覆盖新身份结果。
15. 列表错误、搜索无结果、平台无模型、价格失败和可用性失败均有不同且准确的状态反馈。

### 17.2 安全验收

1. 列表、详情、筛选选项和历史摘要接口均校验当前登录及业务身份。
2. 不可见模型和不存在模型统一返回 404。
3. 所有门户响应均不包含供应商名称、供应商模型标识、端点 URL、凭证、成本、毛利、路由权重和熔断信息。
4. 富文本内容经过白名单处理，不能执行脚本。
5. 缓存、旧数据和前端状态不能跨业务身份复用。

### 17.3 性能与一致性验收

1. 常规数据量下列表和详情接口达到第 14.2 节性能目标。
2. 列表可用性批量计算，不产生逐模型串行查询。
3. 模型上架、下架、公开标识和价格变更在约定同步时限内反映到门户。
4. 当前生效价格由服务端按生效时间返回，前端不使用本地时钟自行判断版本。
5. 目录 `modelCode`、接入文档示例和网关配置通过自动或发布前校验保持一致。

## 18. 开发前置条件

进入真实联调前至少确认：

- 平台模型管理可提供用户侧稳定 ID、公开 `modelCode`、类型、能力、规格和生命周期。
- 定价/计费侧明确价格类型、价格项、单位、生效时间和展示权限。
- 我的服务或权益服务可批量判断当前身份的模型使用范围。
- 开放接口管理和接入文档建立模型类型/协议映射。
- 公共身份框架提供经过验证的 `accountContextId` 和模块权限。
- 模型上下架与公告之间有明确关联和同步时限。
- 第 15 章中 Q01、Q03、Q04、Q07、Q08、Q09 至少形成业务决定。

在上述能力未完成时，前端使用固定 Mock 和适配层开发；Mock 必须明确标注，不得将演示状态宣称为真实可用性或真实价格。
