## 第一部分：需求分析与页面交互

## 1. 模块定位与目标

### 1.1 模块定位

接入文档是 TokenHub 用户门户面向开发者的只读技术文档中心，帮助用户从“已经获得 Token 服务”走到“成功发起并排查一次模型调用”。它需要回答：

1. 接入前需要具备哪些账户、服务和密钥条件？
2. 平台公开的 Base URL、接口协议和鉴权方式是什么？
3. 如何发起第一个请求并正确处理流式响应？
4. 不同模型能力分别使用什么端点、参数和返回格式？
5. 请求被拒绝、限流或失败时如何根据状态码和请求标识排查？
6. 如何把 TokenHub 配置到 Claude Code 或其他受支持的 Agent／SDK？
7. 文档版本与当前实际网关能力是否一致？

### 1.2 用户价值

- 新用户能够在较短路径内完成首次调用。
- 开发者可以按协议、能力和关键字快速定位参数与示例。
- 用户不需要了解底层供应商、渠道和路由策略。
- 接入错误可以通过统一错误码、`requestId` 和工单入口形成排查闭环。
- 模型目录、API 密钥、用量中心与接入文档使用同一组公开标识和计量术语。

### 1.3 建设原则

1. **真实可执行。** URL、鉴权、模型标识和代码示例必须来自已发布的开放接口配置或经过契约测试。
2. **指南和参考分离。**“如何完成任务”放在指南；字段级定义放在 API 参考，避免同一参数多处维护冲突。
3. **用户视角。**只说明公开协议和平台行为，不暴露供应商端点、凭证、成本、路由、熔断与内部服务拓扑。
4. **版本一致。**用户看到的文档版本必须能映射到实际支持的 API 版本；`latest` 只是已发布版本别名。
5. **安全示例。**示例只使用占位密钥和演示数据，不把当前用户真实密钥写入页面、URL、日志或代码块。
6. **可定位。**文档标题、目录、锚点和版本链接稳定，可从模型目录、错误页和工单精确跳转。

## 2. 范围与边界

### 2.1 首版范围

- 文档首页和“快速开始”。
- 左侧分层目录、面包屑、文章正文和右侧页内目录。
- 文档全文搜索、搜索结果和关键字高亮。
- 文档版本查看与历史版本提示。
- Markdown／受控富文本、表格、提示块、代码块及一键复制。
- cURL、Python、JavaScript 等代码示例的语言切换；实际提供语言以文章内容为准。
- 平台访问方式、鉴权、模型选择、流式响应、计量说明、流控、错误码和排障说明。
- 按已上线能力展示 API 参考，如文生文、文生图；不预设未上线端点。
- Claude Code 和已确认支持的 Agent／SDK 配置指南。
- 从模型目录、API 密钥、用量明细和工单页面携带上下文进入文档。
- 文档发布、版本、搜索索引和关联关系所需的后端数据模型。

### 2.2 首版不做

- 在线 API 调试台、Playground 或在浏览器中直接发起模型调用。
- 在文档页创建、展示、自动填入或验证真实 API Key。
- 用户自定义文档、评论区、公开问答社区。
- 用户侧文档编辑、审核、发布和删除。
- SDK 安装包下载、SDK 自动生成或模型能力在线探测。
- 将 OpenAPI 原始文件不加裁剪地暴露给用户。
- 展示供应商名称、供应商端点、上游凭证、成本、毛利、路由权重或实时渠道状态。
- 对未确认支持的框架、Agent 或协议给出“兼容”承诺。

在线调试台如后续建设，应单独评审密钥处理、请求内容留存、费用提示和防滥用策略，不能仅在文档页加一个“运行”按钮。

### 2.3 与其他模块的关系

| 模块 | 接入文档使用的数据或入口 | 边界 |
|---|---|---|
| 公共身份框架 | 登录状态、`accountContextId`、`portal.docs.read` 权限 | 文档内容通常跨身份相同，操作入口和可见范围仍由后端校验 |
| 模型目录 | `platformModelId`、公开 `modelCode`、模型类型、支持协议 | 文档按公开模型和协议定位，不读取供应商模型 |
| API 密钥 | 创建或管理用户密钥入口 | 文档不读取和展示密钥原文，不管理业务密钥 |
| 我的服务 | 当前身份是否有可用 Token 服务 | 只用于“下一步”提示，不在文档中办理订购或展示订单余额 |
| 用量中心 | 调用明细的模型、协议、状态码和 `requestId` | 可跳转到对应错误码或能力文档，不在文档展示调用内容 |
| 平台公告 | API 变更、废弃、维护通知 | 正式通知和影响范围由公告维护，文档可关联公告 |
| 我的工单 | 用户带文档、错误码、请求标识提交问题 | 文档不自动上传请求正文、响应正文或密钥 |
| 开放接口管理 | 公共 Base URL、端点、协议、参数和生命周期 | 是接口参考的权威来源或校验来源 |
| 网关／聚合代理 | 实际可接受协议、模型标识、错误响应与流控行为 | 文档发布前校验，不读取内部路由和供应商配置 |

## 3. 用户、权限和可见范围

### 3.1 权限

建议用户侧权限码：`portal.docs.read`。主账户和子账户均可授予。无权限时路由返回 403，不返回目录、标题、摘要、正文或搜索结果。

文档内容默认仅对已登录且具有权限的用户开放。是否允许匿名访问属于待确认项；在确认前不建设匿名缓存、公开索引或搜索引擎收录。

### 3.2 文档可见范围

首版支持：

| 范围 | 含义 |
|---|---|
| `ALL_AUTHENTICATED` | 所有有文档权限的有效账户身份 |
| `MAIN_ACCOUNT` | 仅主账户身份 |
| `SUB_ACCOUNT` | 仅子账户身份 |
| `ENTITLEMENT` | 具备指定服务、协议或能力权益的身份 |

默认通用接入文档使用 `ALL_AUTHENTICATED`。只有确有业务隔离要求时才使用其他范围。后端先做可见性裁剪，再构建目录、文章和搜索结果；前端隐藏不是权限控制。

### 3.3 身份切换

- 身份切换时重新校验模块权限和当前文章可见性。
- 当前文章在新身份下仍可见时可以保留文章和锚点；“创建密钥”“查看模型”等个性化入口重新计算。
- 当前文章不可见时清空正文并回到文档首页，显示“当前身份无法查看原文档”。
- 旧身份请求迟到时不得覆盖新身份结果。
- 搜索历史不得包含旧身份无权查看的标题；首版不提供服务端个人搜索历史。

### 4.2 必备内容清单

#### 快速开始

必须包含：前置条件、创建用户密钥入口、Base URL、首个可用端点、请求头、最小请求体、模型公开标识、完整响应示例、常见失败入口和查看用量入口。

首个请求示例不得写死生产尚未确认的域名、端点或模型。发布时由配置变量或经验证的示例值生成。示例密钥统一使用明显占位值，例如 `$TOKENHUB_API_KEY`，不得生成看起来可用的真实密钥。

#### 鉴权说明

按协议分别说明鉴权头。若某协议使用 `Authorization: Bearer`，另一协议使用 `x-api-key`，必须分别描述，不能笼统写“把 Key 放入 Header”。内容至少包括：

- 用户密钥的获取和管理入口；
- 请求头名称及格式；
- 密钥只在创建或查看页处理，文档不会自动读取；
- 不在前端代码、公开仓库、URL 查询参数和日志中保存密钥；
- 密钥被暂停、删除、过期或账户受限时的错误行为；
- AI 应用业务密钥不允许用户在门户手动管理。

#### 流控与限制

说明平台实际对外承诺的限制维度，例如 RPS、并发数、请求体大小和模型特定限制。限流数值必须来自当前身份或当前服务可见的权威配置；若不同账户不同，不在静态正文写统一数值，而通过结构化“当前限制”区域展示，或明确指向服务详情。

必须说明 429 的处理建议、是否返回重试时间、退避方式和不可盲目重试的错误类型。文档建议不替代网关实际限制。

#### 错误码与排障

错误参考至少包含 HTTP 状态、平台错误码、用户可见消息、常见原因、是否建议重试和处理建议。必须覆盖鉴权失败、无权限、未知模型、额度不足、限流、请求体过大、参数错误、内容安全拦截、上游暂时异常和平台内部异常；最终枚举以网关实际错误协议为准。

错误页提示用户记录 `requestId`／`traceId` 并用于工单，但不得要求上传 API Key、完整敏感请求或供应商凭证。

#### API 参考

每个已发布端点至少描述：

| 区域 | 必备内容 |
|---|---|
| 基本信息 | 能力、方法、公开路径、协议版本、稳定性状态 |
| 鉴权 | 鉴权方案引用，不重复维护冲突内容 |
| 请求头 | 名称、类型、必填、示例和说明 |
| 路径／查询参数 | 名称、位置、类型、必填、默认值、限制 |
| 请求体 | 字段层级、类型、必填、枚举、限制和示例 |
| 响应 | 状态码、字段结构、流式与非流式示例 |
| 计量 | `usage` 字段是否对用户返回、各字段含义和额度说明 |
| 错误 | 端点特有错误及通用错误引用 |
| 限制 | 请求体、超时、文件、图片或上下文限制 |
| 示例 | cURL 及已验证 SDK／语言示例 |

若平台可能按用户要求移除响应中的 `usage`，文档必须说明对应参数和行为，不能保证每次响应都携带 `usage`。计量和扣减以平台服务端记录为准。

#### Claude Code 接入

原方案明确要求提供 Claude Code 配置示例。内容至少包括：

- 适用前提和已验证版本范围；
- 如何设置 `ANTHROPIC_BASE_URL` 指向平台公开地址；
- 密钥环境变量名称和鉴权映射；
- 可用模型或模型映射配置；
- 临时环境变量和持久化配置的区别；
- 验证命令及成功表现；
- 401、403、404／未知模型、429 和额度不足的排查；
- 配置文件和终端历史中的密钥安全说明。

实际环境变量名、URL 和模型映射必须通过兼容性验证后发布。文档只显示占位密钥，不从当前账户自动注入。

## 5. 页面与路由设计

### 5.1 路由

| 页面 | 路由 | 说明 |
|---|---|---|
| 文档首页 | `/help/docs` | 默认打开当前版本的快速开始首页 |
| 文档文章 | `/help/docs/:articleSlug` | `articleSlug` 为稳定全局路径标识 |
| 文章锚点 | `/help/docs/:articleSlug#section-anchor` | 定位具体章节 |
| 指定版本 | `/help/docs/:articleSlug?version=v1` | 版本代码示例，实际值由服务端返回 |
| 搜索结果 | `/help/docs/search?q=keyword&version=v1` | 可分享、可刷新恢复 |

`latest` 可作为当前已发布版本别名，但页面加载后应显示解析出的真实版本。文章详情使用稳定 slug，不使用标题或数据库自增 ID。slug 变更需保留重定向记录。

### 5.3 文章详情页

```text
┌──────────────┬────────────────────────────────┬──────────────┐
│ 左侧文档目录 │ 面包屑                         │ 本页目录     │
│ [搜索]       │ 文章标题          版本 / 更新时间│ 章节一       │

│ API参考      │ 正文、表格、提示块、代码示例   │              │
│ Agent接入    │                                │              │
│ 常见问题     │ 上一篇 / 下一篇                │              │
└──────────────┴────────────────────────────────┴──────────────┘
```

- ≥1280px 显示三栏；768～1279px 收起右侧目录；<768px 左侧目录改为抽屉，正文单列。
- 中间正文建议最大宽度 900px；代码块自身横向滚动，不导致整页横向滚动。
- 标题区展示文档版本、最后更新时间、适用协议／能力和废弃提示。
- 左侧高亮当前文章；滚动时右侧目录高亮当前章节。
- 页面底部提供上一篇、下一篇和“仍未解决？提交工单”入口。

### 5.4 URL 上下文

从其他模块进入时允许携带：

| 参数 | 含义 | 使用规则 |
|---|---|---|
| `modelId` | 来源模型 | 后端校验可见性后展示模型上下文，不改变正文权威定义 |
| `protocol` | 协议 | 定位对应协议段或示例标签 |
| `errorCode` | 平台错误码 | 定位错误条目 |
| `from` | 来源模块 | 仅用于返回入口和埋点，必须使用允许值 |

不得在 URL 中传递 API Key、请求正文、用户 Prompt、响应正文或账户余额。无效／无权参数被忽略，不影响通用文章阅读。

## 6. 页面交互逻辑

### 6.1 首次进入

1. 校验登录、当前身份和 `portal.docs.read`。
2. 获取当前发布版本、可见目录和首页配置。
3. 无指定文章时打开快速开始首页；有旧链接重定向时使用 301／应用内 replace 跳转到新 slug，并保留允许的版本和锚点。
4. 文章、目录和搜索索引版本必须一致；不能目录显示新版本、正文返回旧版本。
5. 页面保留上次选择的代码语言属于本地展示偏好，可使用 localStorage；不得存储密钥或账户数据。

### 6.2 目录导航

- 目录节点支持最多 3 层；超过 3 层通过文章页内标题组织。
- 点击分类只展开／收起；若分类自身配置落地文章，则标题和展开按钮采用不同点击区域。
- 切换文章保留当前文档版本，滚动到顶部；浏览器前进／后退恢复文章和锚点。
- 上一篇／下一篇按当前可见目录顺序计算，不跨到无权节点。
- 切换版本时优先打开同一 `articleKey` 对应版本；不存在则进入该版本首页并提示“此文章在所选版本中不存在”。

### 6.3 页内目录和锚点

- 正文 H2、H3 生成页内目录，H1 仅作为文章标题。
- 锚点使用发布时生成并持久化的 `headingAnchor`，不能因标题轻微修改自动变化。
- 点击目录更新 URL hash，不整页刷新。
- 外部深链打开后正确滚动到标题；固定顶部栏不能遮挡标题。
- 锚点失效时仍显示文章顶部，不返回整页 404。

### 6.4 搜索

搜索范围包括标题、摘要、正文纯文本、标题层级、公开 API 路径、参数名、平台错误码、公开模型标识和标签，不索引密钥、内部备注、供应商配置或未发布版本。

交互规则：

1. 搜索框输入 300ms 防抖；按 Enter 进入完整搜索页。
2. 查询去除首尾空格，最长 100 字符；空值不查询。
3. 搜索结果展示标题、所属目录、版本、正文片段和命中章节。
4. 片段为服务端生成的安全纯文本；前端只对命中范围加安全高亮，不渲染返回 HTML。
5. 点击结果进入文章并定位命中锚点，保留当前版本。
6. 中文、英文标识、`snake_case`、`kebab-case`、API 路径和错误码应可检索。
7. 无结果时显示相关入口和工单链接，不把查询失败显示成无结果。
8. 搜索只返回当前身份、当前版本可见内容；结果总数也不得包含不可见文章。

### 6.5 代码示例

- 代码块展示语言名称和“复制”按钮；复制成功提示“已复制”，2 秒后恢复。
- 多语言示例使用标签切换，当前选择在同一浏览器保留。
- 复制内容保持原始换行和缩进，不复制行号、提示符或解释文字。
- shell 示例中的 Key 使用环境变量，如 `$TOKENHUB_API_KEY`，不得在复制时替换为真实值。
- Base URL、公开路径和示例模型可使用受控变量渲染；变量缺失时整块显示“示例配置暂不可用”，不能复制半成品命令。
- 示例中的 JSON 必须可解析；代码示例发布前通过格式校验，关键快速开始示例应执行契约测试。
- 页面不自动执行代码，不读取剪贴板，不向外部域名发送示例内容。

### 6.6 版本切换与废弃提示

- 默认版本为服务端返回的当前稳定发布版本，不按浏览器时间推断。
- 历史版本页面顶部显示“正在查看历史版本”，并提供返回当前版本入口。
- 已废弃但仍可用的文章显示废弃时间、停止支持时间、替代文章和迁移指南。
- 已停止支持版本可保留只读历史文档；是否继续可访问由版本策略决定。
- 文档变更记录只描述文档／API 的公开变化；运营通知仍以公告为准。

### 6.7 个性化行动入口

正文旁或页面底部可展示：

- 创建／管理 API 密钥；
- 查看对应模型；
- 查看用量；
- 提交工单。

入口是否可用由后端权限结构返回，不从身份类型或余额自行推断。文档正文不因用户余额变化生成不同版本；个性化状态与可缓存正文分离查询。

### 6.8 异常和空状态

| 状态 | 页面行为 |
|---|---|
| 目录加载中 | 左侧骨架，正文保持或显示文章骨架 |
| 文章不存在／无权 | 统一 404，不泄露标题及存在性 |
| 文档版本不存在 | 返回可用版本列表并引导当前版本 |
| 文章加载失败 | 显示重试；不误显示“暂无内容” |
| 搜索无结果 | 明确“未找到相关文档”，提供常用入口 |
| 搜索失败 | 显示查询失败和重试，不显示 0 结果 |
| 内容变量缺失 | 受影响示例块禁用复制并提示配置不可用 |
| 历史版本 | 全页固定提示，不把历史配置表现成当前推荐 |
| 文档已废弃 | 展示迁移提示和替代入口 |
| 会话失效 | 清空受保护内容，由公共框架处理重新登录 |

## 7. 内容格式与编写规范

### 7.1 内容格式

正文以 Markdown 为推荐权威格式，发布后由服务端使用固定版本渲染器转换为安全 HTML。允许：标题、段落、有序／无序列表、表格、链接、图片、代码块、引用、提示块和受控标签页。禁止脚本、iframe、表单、内联事件和任意 HTML。

每篇文章必须包含元数据：

```yaml
title: 鉴权方式
summary: 使用用户 API 密钥访问 TokenHub 公开接口
articleKey: authentication
slug: guides/authentication
docVersion: v1
contentType: GUIDE
protocols: [OPENAI_COMPATIBLE, ANTHROPIC_COMPATIBLE]
capabilities: [TEXT_GENERATION]
status: PUBLISHED
```

真实字段通过后台表单或内容仓库元数据管理，示例不代表实际协议已经上线。

### 7.2 术语规范

- “API Key”在用户操作处统一称“API 密钥”，代码和字段中保留标准名称。
- 区分用户密钥和业务密钥；用户文档只指导用户密钥。
- 使用“平台模型标识／`model` 标识”，不写供应商模型标识。
- 区分实际 Token 用量、套餐扣减额度和 CRM 费用。
- “Base URL”“端点”“路径”“模型”不得混用。
- 未知、不支持和暂不可用是不同状态；未知不能写成不支持。

### 7.3 链接规范

- 站内文章通过 `articleKey`／slug 关联，不在正文硬编码环境域名。
- 模型、服务、公告和工单使用结构化关联入口。
- 外部链接只允许 `https`，使用新窗口时增加安全属性，并显示外部链接标识。
- slug 调整需配置重定向，避免模型目录、公告和历史工单中的链接失效。

### 7.4 图片和附件

- 图片必须有替代文本，宽度自适应；不得包含真实密钥、手机号、账户余额或未脱敏请求内容。
- 附件首版仅允许受控白名单类型；可下载 OpenAPI 文件是否开放待确认。
- 静态资源发布时进行病毒扫描、类型校验、大小限制和访问权限校验。

## 8. 文档生命周期与发布流程

### 8.1 状态

| 状态 | 含义 | 用户侧可见 |
|---|---|---|
| `DRAFT` | 编辑中 | 否 |
| `IN_REVIEW` | 技术／产品审核中 | 否 |
| `SCHEDULED` | 已审核，等待发布时间 | 否 |
| `PUBLISHED` | 已发布 | 是，仍需通过范围校验 |
| `ARCHIVED` | 归档，不再作为当前内容 | 仅历史版本策略允许时 |
| `WITHDRAWN` | 因错误紧急撤回 | 否 |

### 8.2 发布流程

```text
编写草稿 → 内容校验 → 技术审核 → 产品/安全审核 → 预览
        → 关联开放接口版本 → 发布 → 建立搜索索引 → 刷新缓存
        → 自动一致性检查 → 监控与必要回滚
```

发布前必须校验：

1. slug、文章键和锚点唯一；站内链接可达。
2. 公开 API 路径、鉴权方案、模型标识和错误码存在于已发布配置。
3. JSON、YAML 和代码块格式合法；快速开始示例通过契约测试。
4. 正文通过安全白名单清洗，无真实密钥和受限字段。
5. API 参考不包含内部端点、供应商凭证或仅运营可见字段。
6. 目录、正文、搜索索引和版本清单指向同一发布快照。

发布以不可变文章版本为单位。修改已发布内容必须生成新修订，不直接覆盖历史正文。回滚通过重新激活上一份已审核内容或发布一个回滚修订完成，并记录操作者和原因。

### 8.3 内容来源

支持两种来源：

| 来源 | 用途 | 权威性 |
|---|---|---|
| `AUTHORED_MARKDOWN` | 快速开始、指南、排障、Agent 接入 | 文档内容系统维护 |
| `API_SPEC_GENERATED` | 字段级 API 参考 | 由经裁剪的公开接口规范生成，并允许受控补充说明 |

若暂时没有可用的公开接口规范，可先人工维护 API 参考，但必须标记来源并纳入发布一致性检查。不得把内部 OpenAPI 直接作为用户规范发布。

## 9. 用户侧接口契约

接口遵循[公共设计第 4～6 章](用户门户公共设计.md)的身份、时间、错误和数据隔离规则。示例前缀 `/api/portal/v1`，以项目实际配置为准。

### 9.1 接口清单

| 方法及路径 | 用途 | 关键参数 |
|---|---|---|
| GET `/docs/bootstrap` | 获取当前版本、首页、目录和权限入口 | `version` 可选 |
| GET `/docs/versions` | 获取可查看版本 | 无 |
| GET `/docs/articles/{articleSlug}` | 获取文章详情 | `version`、`modelId`、`protocol` 可选 |
| GET `/docs/search` | 搜索当前版本文档 | `q`、`version`、`categoryKey`、`page`、`pageSize` |
| GET `/docs/articles/{articleSlug}/navigation` | 获取上一篇／下一篇 | `version` |
| GET `/docs/error-codes/{errorCode}` | 精确定位错误说明 | `version` |
| GET `/docs/runtime-context` | 获取个性化操作入口和当前限制摘要 | `modelId`、`protocol` 可选 |

`bootstrap` 可把版本、首页配置和目录合并返回，减少首屏请求。文章正文与 `runtime-context` 分离，使公共内容缓存不携带账户敏感数据。

### 9.2 Bootstrap 响应

```ts
interface DocsBootstrapResponse {

      capabilityCode: string;

  };
  tree: DocTreeNode[];
  permissions: {
    canReadDocs: boolean;
    canManageUserKey: boolean;
    canViewModels: boolean;
    canViewUsage: boolean;

  };
}

interface DocVersionSummary {
  versionCode: string;
  displayName: string;
  status: 'CURRENT' | 'SUPPORTED' | 'DEPRECATED' | 'UNSUPPORTED';
  publishedAt: string;
  supportEndsAt: string | null;
}

interface DocTreeNode {
  nodeId: string;
  nodeType: 'CATEGORY' | 'ARTICLE';

  articleSlug: string | null;

}
```

### 9.3 文章响应

```ts
interface DocArticleResponse {
  requestId: string;
  accountContextId: string;
  articleKey: string;
  articleSlug: string;
  title: string;
  summary: string;
  contentType: 'QUICKSTART' | 'GUIDE' | 'API_REFERENCE' | 'INTEGRATION' | 'FAQ' | 'CHANGELOG';
  docVersion: string;
  revision: number;
  contentHtml: string; // 服务端按白名单渲染并清洗

    level: 2 | 3;

  retiredAt: string | null;

```

前端只渲染服务端已清洗的 `contentHtml`，仍需设置严格 CSP，不能执行正文脚本。`relatedLinks` 由服务端按当前身份裁剪。

### 9.4 搜索响应

```ts
interface DocSearchResponse {
  requestId: string;
  accountContextId: string;
  version: string;
  query: string;
  total: number;
  page: number;
  pageSize: number;
  items: Array<{
    articleKey: string;
    articleSlug: string;
    title: string;
    breadcrumbTitles: string[];
    headingTitle: string | null;
    headingAnchor: string | null;
    snippetText: string;
    highlightRanges: Array<{ start: number; end: number }>;
    contentType: string;
    updatedAt: string;
  }>;

```

高亮范围使用 Unicode 字符索引的统一约定，前后端联调时必须验证中文和 emoji，不允许服务端返回可执行高亮 HTML。

### 9.5 状态码

| HTTP 状态 | 用户侧含义 |
|---|---|
| 200 | 查询成功 |
| 400 | 参数或版本格式错误 |
| 401 | 登录失效 |
| 403 | 当前身份无文档权限 |
| 404 | 文章／版本不存在或当前身份不可见 |
| 410 | 文章或版本已停止支持且不再提供正文（如采用该策略） |
| 429 | 文档搜索等接口触发平台保护限制 |
| 500／503 | 文档服务或索引暂不可用 |

这里是文档服务自身的 HTTP 行为，不等于模型调用 API 的错误码内容。模型调用错误码由文档正文和结构化错误码数据维护。

## 10. 后端编排与数据来源

| 数据 | 权威来源 | 门户文档服务职责 |
|---|---|---|
| 文档正文、目录和修订 | 文档内容系统／内容仓库 | 版本化、发布、渲染、权限裁剪 |
| Base URL、公开端点和协议 | 开放接口管理 | 读取已发布用户侧配置，填充受控变量 |
| 请求／响应 Schema | 公开 API 规范 | 裁剪内部字段后生成参考文档 |
| 模型公开标识和能力 | 平台模型管理 | 校验示例模型，不读取供应商模型 |
| 鉴权方案 | 网关公开配置 | 生成协议对应鉴权说明 |
| 错误码 | 网关统一错误码目录 | 保持状态、含义和重试建议一致 |
| 流控与限制 | 网关／权益／服务配置 | 返回公开通用值或当前身份限制摘要 |
| 公告 | 平台公告模块 | 关联正式变更和迁移通知 |
| 个性化入口权限 | 账户、服务、密钥模块 | 单独返回，不写入可共享正文缓存 |

一致性要求：

- 公共 Base URL、路径、鉴权头、`modelCode` 和错误码必须与网关实际配置一致。
- 文档发布不能先于对应接口生产可用时间，除非明确标为“即将上线”且用户无法误用。
- 接口下线或参数破坏性变更必须有废弃期、迁移文档和公告；紧急安全撤回除外。
- 模型目录到文档的协议映射由稳定标识关联，不能通过标题模糊匹配。
- 内容变量渲染失败时禁止发布或禁用受影响示例，不能把 `${BASE_URL}` 原样展示给普通用户。

## 11. 表结构设计

若组织已有成熟文档平台，可以用其 API 提供以下逻辑能力，不要求在门户重复建表。若由 TokenHub 自建，建议采用下列表结构。所有业务 ID 使用字符串或分布式 ID；时间建议数据库存 UTC，接口按公共设计输出。

### 11.1 `doc_release` 文档版本

| 字段 | 类型建议 | 必填 | 说明 |
|---|---|---|---|
| `id` | varchar(64) | 是 | 主键 |
| `version_code` | varchar(32) | 是 | 稳定版本代码，如实际确定的 API 文档版本 |
| `display_name` | varchar(64) | 是 | 页面显示名 |
| `release_status` | varchar(24) | 是 | DRAFT、CURRENT、SUPPORTED、DEPRECATED、UNSUPPORTED |
| `published_at` | datetime(3) | 否 | 发布时间 |
| `deprecated_at` | datetime(3) | 否 | 废弃提示开始时间 |
| `support_ends_at` | datetime(3) | 否 | 支持结束时间 |
| `sort_order` | int | 是 | 版本选择器排序 |
| `created_at` / `updated_at` | datetime(3) | 是 | 审计时间 |

约束：`version_code` 唯一；同一时刻只能有一个 `CURRENT`。状态切换需审计，不依赖前端时间自行改变。

### 11.2 `doc_category` 目录分类

| 字段 | 类型建议 | 必填 | 说明 |
|---|---|---|---|
| `id` | varchar(64) | 是 | 主键 |
| `category_key` | varchar(128) | 是 | 稳定业务键 |
| `parent_id` | varchar(64) | 否 | 父分类，最多 3 层 |
| `title` | varchar(128) | 是 | 分类标题 |
| `description` | varchar(512) | 否 | 分类说明 |
| `sort_order` | int | 是 | 同级排序 |
| `visibility_scope` | varchar(32) | 是 | 可见范围 |
| `status` | varchar(16) | 是 | ENABLED、DISABLED |
| `created_at` / `updated_at` | datetime(3) | 是 | 审计时间 |

约束：`category_key` 唯一；禁止循环父子关系；分类删除采用逻辑停用，存在已发布文章时不能直接删除。

### 11.3 `doc_article` 文章稳定主记录

| 字段 | 类型建议 | 必填 | 说明 |
|---|---|---|---|
| `id` | varchar(64) | 是 | 主键 |
| `article_key` | varchar(128) | 是 | 跨版本稳定键 |
| `article_slug` | varchar(256) | 是 | 当前稳定路由 |
| `category_id` | varchar(64) | 是 | 所属分类 |
| `content_type` | varchar(32) | 是 | QUICKSTART、GUIDE、API_REFERENCE、INTEGRATION、FAQ、CHANGELOG |
| `source_type` | varchar(32) | 是 | AUTHORED_MARKDOWN、API_SPEC_GENERATED |
| `visibility_scope` | varchar(32) | 是 | 可见范围 |
| `sort_order` | int | 是 | 分类内排序 |
| `status` | varchar(16) | 是 | ENABLED、DISABLED |
| `created_by` / `updated_by` | varchar(64) | 是 | 操作人 |
| `created_at` / `updated_at` | datetime(3) | 是 | 审计时间 |

约束：`article_key` 唯一；当前 `article_slug` 唯一。旧 slug 写入重定向表，不覆盖历史映射。

### 11.4 `doc_article_revision` 文章修订

| 字段 | 类型建议 | 必填 | 说明 |
|---|---|---|---|
| `id` | varchar(64) | 是 | 主键 |
| `article_id` | varchar(64) | 是 | 文章主记录 |
| `doc_release_id` | varchar(64) | 是 | 所属文档版本 |
| `revision_no` | int | 是 | 文章在该版本内的修订号 |
| `title` | varchar(256) | 是 | 标题 |
| `summary` | varchar(1000) | 是 | 摘要 |
| `markdown_content` | longtext | 否 | 人工编写源内容 |
| `rendered_html` | longtext / object URI | 是 | 发布时安全渲染结果 |
| `toc_json` | json | 是 | 持久化标题及锚点 |
| `metadata_json` | json | 是 | 协议、能力、代码语言等受控元数据 |
| `content_hash` | varchar(64) | 是 | 内容完整性及缓存失效 |
| `workflow_status` | varchar(24) | 是 | DRAFT、IN_REVIEW、SCHEDULED、PUBLISHED、ARCHIVED、WITHDRAWN |
| `published_at` | datetime(3) | 否 | 实际发布时间 |
| `deprecated_at` / `retired_at` | datetime(3) | 否 | 生命周期提示 |
| `replacement_article_id` | varchar(64) | 否 | 替代文章 |
| `created_by` / `reviewed_by` / `published_by` | varchar(64) | 否 | 流程人员 |
| `created_at` / `updated_at` | datetime(3) | 是 | 审计时间 |

唯一约束：`article_id + doc_release_id + revision_no`。同一文章和文档版本只能有一个当前发布修订。已发布正文不可原地修改。

### 11.5 `doc_heading` 稳定锚点

| 字段 | 类型建议 | 说明 |
|---|---|---|
| `id` | varchar(64) | 主键 |
| `revision_id` | varchar(64) | 所属修订 |
| `heading_key` | varchar(128) | 跨修订稳定章节键 |
| `anchor` | varchar(160) | URL hash |
| `title` | varchar(256) | 标题 |
| `level` | tinyint | 2 或 3 |
| `sort_order` | int | 文内顺序 |

同一修订内 `anchor` 唯一。编辑器应尽量沿用已有 `heading_key` 和锚点。

### 11.6 `doc_redirect` 路由重定向

| 字段 | 类型建议 | 说明 |
|---|---|---|
| `id` | varchar(64) | 主键 |
| `source_slug` | varchar(256) | 历史 slug，唯一 |
| `target_article_id` | varchar(64) | 目标文章 |
| `target_anchor` | varchar(160) nullable | 可选目标章节 |
| `status` | varchar(16) | ACTIVE、DISABLED |
| `created_at` | datetime(3) | 创建时间 |

### 11.7 `doc_relation` 结构化关联

| 字段 | 类型建议 | 说明 |
|---|---|---|
| `id` | varchar(64) | 主键 |
| `article_id` | varchar(64) | 文档文章 |
| `relation_type` | varchar(32) | ARTICLE、MODEL、PROTOCOL、CAPABILITY、ERROR_CODE、ANNOUNCEMENT、SERVICE |
| `target_key` | varchar(128) | 目标稳定键 |
| `label` | varchar(128) nullable | 自定义展示名 |
| `sort_order` | int | 排序 |

唯一约束建议：`article_id + relation_type + target_key`。返回用户前再次校验目标可见性。

### 11.8 `public_api_spec` 公开接口规范版本

| 字段 | 类型建议 | 说明 |
|---|---|---|
| `id` | varchar(64) | 主键 |
| `spec_key` | varchar(128) | 规范稳定键 |
| `doc_release_id` | varchar(64) | 文档版本 |
| `protocol_code` | varchar(64) | 公开协议代码 |
| `spec_version` | varchar(64) | 规范版本 |
| `source_uri` | varchar(1024) | 受控存储位置，不直接对用户暴露 |
| `content_hash` | varchar(64) | 完整性校验 |
| `status` | varchar(24) | DRAFT、VALIDATED、PUBLISHED、RETIRED |
| `validated_at` | datetime(3) nullable | 最近校验时间 |

只保存经过用户侧裁剪的规范；内部规范与公开规范隔离存储和发布。

### 11.9 `api_error_definition` 公开错误码

| 字段 | 类型建议 | 说明 |
|---|---|---|
| `id` | varchar(64) | 主键 |
| `error_code` | varchar(64) | 平台公开错误码 |
| `http_status` | int | HTTP 状态 |
| `title` | varchar(128) | 简短名称 |
| `user_message` | varchar(512) | 对用户的解释 |
| `common_causes` | text/json | 常见原因 |
| `resolution` | text/json | 处理建议 |
| `retryable` | boolean | 是否建议重试 |
| `doc_release_id` | varchar(64) | 适用版本 |
| `status` | varchar(16) | DRAFT、PUBLISHED、RETIRED |

唯一约束：`error_code + doc_release_id`。错误码目录应由网关错误协议同步或校验，不能由文档团队独立创造。

### 11.10 搜索索引

搜索索引是派生数据，不作为正文权威来源。索引文档至少包含 `articleId`、`revisionId`、版本、可见范围、标题、摘要、标题层级、正文纯文本、API 路径、参数名、错误码、标签和更新时间。

发布、撤回、范围调整和版本状态变化必须触发索引更新。索引不可用时，文章直达仍可工作；不得自动降级为无权限过滤不完整的全库搜索。

## 13. 安全、性能与可观测性

### 13.1 安全

- 所有文档接口执行登录、身份和权限校验；不可见与不存在文章统一 404。
- 服务端渲染时使用严格白名单清洗；前端配置 CSP，禁止正文脚本和不受控 iframe。
- 示例、截图、附件和日志不得含真实 API Key、用户 Prompt、完整敏感请求、账户余额或供应商凭证。
- 搜索结果、推荐、上一篇／下一篇和总数均执行相同可见性过滤。
- 公开 API 规范采用字段白名单，不能直接序列化内部网关或运营实体。
- 外部资源域名使用允许列表；禁止 `javascript:`、`data:` 等危险协议，必要图片例外由安全评审确定。
- 复制功能只复制静态示例，不读取用户剪贴板或自动拼入账户信息。
- 审计记录文档创建、审核、发布、撤回、版本切换和权限范围变更。

### 13.2 性能目标

- 文档首屏 P95 不超过 2 秒；文章接口 P95 不超过 1 秒；搜索接口 P95 不超过 1.5 秒，均不含用户本地网络异常。
- 发布正文和目录可使用 CDN／缓存，但缓存键必须包含版本和可见范围；个性化入口不得进入公共正文缓存。
- 大文章按合理大小限制；首版不做正文客户端无限分片，单篇 Markdown 建议不超过 1 MB，超出应拆分。
- 搜索采用专用全文索引或数据库能力，禁止每次请求全表扫描 Markdown。
- 目录一次返回当前版本完整可见树，节点数量超过约定阈值时再评估懒加载。

### 13.3 服务端日志与监控

服务端记录：`requestId`、匿名化身份、版本、articleKey／搜索条件摘要、耗时、命中数量和结果状态。搜索原文如可能包含敏感信息，应只记录长度、分类或不可逆摘要。

建议监控：

- 首页、目录、文章和搜索接口成功率及 P95／P99；
- 404、重定向、历史版本访问比例；
- 搜索无结果率和高频无结果主题；
- 发布到缓存／索引生效延迟；
- 断链、变量缺失、示例契约测试失败数；
- 文档 `modelCode`、端点、错误码与网关配置的一致性结果；
- 撤回文档仍被缓存命中的异常。

### 13.4 产品埋点

| 事件 | 关键属性 |
|---|---|
| `docs_home_view` | 文档版本、身份类型 |
| `docs_article_view` | articleKey、版本、来源模块，不采集正文内容 |
| `docs_search` | 查询长度／分类、结果数，不采集可能敏感的原文 |
| `docs_search_result_click` | articleKey、结果位置 |
| `docs_code_copy` | articleKey、代码语言、示例标识，不采集代码内容 |
| `docs_version_switch` | 来源版本、目标版本 |
| `docs_related_action_click` | articleKey、目标模块、关联类型 |
| `docs_ticket_click` | articleKey、errorCode 是否存在，不采集 requestId 原值 |

## 14. Mock 场景

至少提供以下固定 Mock，不得每次刷新随机生成：

1. 当前稳定版本：首页、完整目录和快速开始文章。
2. 历史受支持版本：同一文章内容不同并显示历史提示。
3. 某文章在历史版本不存在，切换后回到版本首页。
4. 主账户和子账户都可阅读，但个性化操作入口权限不同。
5. 权益限定文章对子账户不可见，目录和搜索均不泄露。
6. 带 cURL、Python、JavaScript 标签的代码示例和复制行为。
7. Claude Code 配置指南，变量均为安全占位值。
8. 文生文 API 参考：参数表、流式与非流式响应、通用错误引用。
9. 非 Token 能力文档，不错误套用 Token 字段和计量单位。
10. 废弃文章：替代文章、停止支持时间和迁移指南。
11. 旧 slug 重定向并保留版本、锚点。
12. 搜索中文、API 路径、参数名、错误码和 `modelCode` 均有结果。
13. 搜索无结果与搜索服务失败两个不同状态。
14. 文章正文成功、个性化运行时上下文失败，正文仍可阅读。
15. 内容变量缺失，示例不可复制且不展示半成品。
16. 文章不可见／不存在统一 404。
17. 身份切换时旧搜索或文章响应迟到，不覆盖新身份页面。
18. 恶意 Markdown、脚本链接和 iframe 被清洗。
19. 超长代码块在小屏幕内部滚动，页面无整体横向溢出。
20. 发布后目录更新成功但搜索索引失败，发布流程告警并按原子策略处理。

## 15. 验收标准

### 15.1 功能验收

1. 有 `portal.docs.read` 权限的主、子账户可访问文档；无权限不返回目录和正文。
2. 文档首页展示快速开始、常用入口、已上线能力和最近更新。
3. 左侧目录、面包屑、上一篇／下一篇和右侧页内目录导航一致。
4. 文章刷新、浏览器前进后退和深层锚点可恢复正确位置。
5. 搜索可命中文章标题、正文、API 路径、参数、错误码和公开模型标识。
6. 搜索结果只来自当前可见版本，查询失败不显示为无结果。
7. 代码示例可以按已有语言切换和复制，不含行号或真实密钥。
8. Base URL、端点、鉴权头、公开模型标识和示例与已发布网关配置一致。
9. 快速开始最小示例通过契约测试，JSON／YAML 示例格式合法。
10. Claude Code 文档正确说明 `ANTHROPIC_BASE_URL`、鉴权、模型配置和排障，且不自动读取用户密钥。
11. API 参考包含方法、路径、请求、响应、流式行为、计量、限制和错误说明。
12. 历史、废弃和停止支持版本有明确提示及迁移入口。
13. 模型目录、调用错误和平台公告能够精确跳转到文章或章节。
14. 个性化操作入口由后端权限决定；正文与账户敏感数据分离。
15. 文章加载失败、无权限、无结果、索引失败和变量缺失均有准确状态。

### 15.2 安全验收

1. Markdown 中的脚本、事件属性、iframe、表单和危险协议无法执行。
2. 未发布、已撤回和当前身份不可见文章不会出现在目录、搜索、推荐及导航数量中。
3. 用户侧响应不包含供应商端点、凭证、成本、路由、内部服务名或内部 OpenAPI 字段。
4. 页面、URL、埋点和日志均不记录 API Key、完整敏感请求或用户 Prompt。
5. 旧 slug 和关联目标跳转后仍执行目标资源权限校验。
6. 缓存和搜索索引不能跨版本、可见范围或身份权限泄露内容。
7. 撤回内容在约定时间内从正文缓存、目录和搜索索引同步移除。

### 15.3 发布与一致性验收

1. 已发布修订不可直接覆盖，变更生成新修订并有审核、发布时间和操作者记录。
2. 同一文章／版本最多一个当前发布修订，同一时刻最多一个当前稳定文档版本。
3. 目录、正文、搜索和版本清单在同一发布快照下可见，不出现混合版本。
4. 文章 slug 或章节标题调整后，旧链接通过重定向或稳定锚点继续访问。
5. 文档发布校验能发现断链、重复锚点、无效 JSON、未知模型标识、未知错误码和未发布端点。
6. 接口配置变更触发文档一致性检查；不一致时告警并阻止错误内容成为当前推荐版本。

### 15.4 性能与适配验收

1. 常规数据规模下达到第 13.2 节性能目标。
2. 三栏、两栏和移动单栏布局可用，代码块不会造成整页横向滚动。
3. 中文、英文标识、路径和错误码搜索均正常，命中高亮不破坏 Unicode。
4. 大目录和长文章不导致明显主线程阻塞，滚动目录定位稳定。

## 16. 待确认事项

| 编号 | 事项 | 影响 | 当前处理 |
|---|---|---|---|
| Q01 | 接入文档是否允许未登录公开访问 | 鉴权、缓存、SEO、安全 | 暂按登录且有权限访问 |

| Q10 | 是否对用户提供裁剪后的 OpenAPI 下载 | 附件、SDK 使用和安全 | 首版不提供下载，保留数据模型 |
| Q11 | 文档由运营后台编辑还是 Git 内容仓库维护 | 工作流和管理端实现 | 用户侧契约不变，二选一或混合需架构确认 |
| Q12 | 子账户是否可阅读全部接入文档 | 权限和范围 | 默认有权限时可读，预留范围裁剪 |
| Q13 | 文档历史版本保留多久，停止支持后是否返回 410 | 存储、链接和合规 | 保留状态和 410 能力，策略待定 |
| Q14 | 是否收集“本文是否有帮助”反馈 | 页面和反馈表 | 首版不做，后续单独补充 |
| Q15 | 请求大小、超时、重试和幂等的公开承诺 | 基础指南和错误处理 | 由网关团队给出真实规则 |
| Q16 | 文生图等非 Token 能力的计量和示例 | API 参考、用量说明 | 按实际能力单位展示，不强行换算 Token |

## 17. 开发前置条件

真实联调前至少具备：

- 开放接口管理提供公开 Base URL、协议、方法、路径、参数和生命周期。
- 网关提供真实鉴权方式、错误响应结构、错误码、流控及限制。
- 平台模型管理提供稳定 `platformModelId`、公开 `modelCode` 和协议映射。
- 文档内容来源、审核责任人、发布方式和当前版本策略已经确定。
- Claude Code 至少完成一次端到端兼容性验证并明确支持边界。
- 公共身份框架提供经过验证的 `accountContextId` 和 `portal.docs.read` 权限。
- 第 16 章 Q01～Q09 形成可供生产发布使用的决定。

## 18. 交给代码生成模型的实施说明
