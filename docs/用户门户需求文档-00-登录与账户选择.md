# TokenHub 用户门户需求与技术设计：00 登录与账户选择

版本：V0.1，开发评审稿  
日期：2026-09-29  
适用范围：产品评审、交互设计、用户门户前后端、账户与权限服务、CRM 联调、安全评审和测试验收  
页面路由：`/login`、`/account-selection`  
公共依据：[TokenHub 用户门户公共设计](用户门户公共设计.md)  
原始依据：《TokenHub 平台设计方案》

本文定义用户如何进入 TokenHub 用户门户，以及同一个登录用户如何选择主账户或子账户业务身份。登录只解决“当前访问者是谁、以哪个账户身份使用门户”；Token 服务状态、额度、API Key 和模型调用资格仍由对应业务链路独立校验。

**规则状态：**原方案明确同一用户可能同时具备主账户、子账户或多个子账户身份，并要求登录时选择账户。原方案未明确认证渠道、账号注册、会话时长、冻结与注销后的登录规则。本文将可进入设计开发的建议标记为“本版设计”，把必须由产品、CRM、统一认证或安全团队决定的内容保留为“待确认”。

**当前 Demo 范围：**本期只演示主账户登录、登录态拦截和退出登录，不演示子账户登录及账户身份选择。本文仍保留账户选择的目标需求，供后续迭代使用。

## 第一部分：需求分析与页面交互

## 1. 模块定位与目标

### 1.1 模块定位

登录与账户选择是用户门户的公共入口，负责：

1. 通过统一认证能力确认自然人身份。
2. 查询该自然人可以进入的业务账户。
3. 在存在多个账户身份时让用户明确选择当前身份。
4. 建立服务端可信的账户上下文和权限范围。
5. 在登录、切换身份、退出和异常处理中保持数据隔离并记录审计日志。

### 1.2 核心概念

| 概念 | 定义 | 示例 |
|---|---|---|
| 登录用户 | 完成身份认证的自然人，由稳定的 `userId` 标识 | 张三 |
| 主账户 | Token 服务及账户额度的归属主体 | A 企业 Token 账户 |
| 子账户 | 主账户授权给某个用户使用的业务身份 | 张三在 A 企业下的子账户 |
| 账户上下文 | 用户当前选择的业务身份，由 `accountContextId` 标识 | 以 A 企业子账户身份进入门户 |
| 登录会话 | 用户认证成功后由服务端维护的会话 | 当前设备上的门户会话 |
| API Key | 外部智能体或 AI 应用调用 TokenHub 接口的凭证 | `sk-***`，不用于网页登录 |

同一个自然人只有一个登录身份，但可以关联多个业务账户身份。页面展示、查询权限、API Key 管理和用量范围以当前账户上下文为准。

### 1.3 建设目标

- 用户能够清楚地进入正确的主账户或子账户。
- 用户切换账户后不会看到上一个账户的数据。
- 服务暂停、余额不足或 API Key 停用不会被错误地当成登录失败。
- CRM 已开通但尚未同步完成时，用户得到可理解、可追踪的状态反馈。
- 运营管理门户和用户门户使用彼此隔离的入口与权限边界。

## 2. 用户与认证边界

### 2.1 用户门户用户

用户门户面向：

- 仅拥有主账户身份的用户。
- 仅拥有一个子账户身份的用户。
- 同时拥有主账户和子账户身份的用户。
- 同时属于多个主账户、拥有多个子账户身份的用户。
- 订购 Token 服务或 AI 应用后，需要查询服务、额度、用量或业务状态的用户。

### 2.2 运营管理人员

运营人员通过独立的运营管理门户登录，根据 RBAC 角色访问模型、供应商、用户、成本和监控功能。本文件只定义用户门户登录；运营登录需复用统一认证、安全和审计原则，但另行维护角色与后台权限矩阵。

### 2.3 外部智能体和 AI 应用

外部智能体和 AI 应用不使用网页登录。它们调用 TokenHub 模型接口时携带 API Key，由接入网关校验 Key、服务、账户、额度和流量限制。

不得把 API Key 输入框放在用户登录页，也不得把门户登录令牌用于模型接口调用。

### 2.4 账户来源

平台设计方案规定用户账户开通、停复机等业务由 CRM 发起，TokenHub 接收接口调用并维护本地业务数据。因此，本期按以下边界设计：

- TokenHub 用户门户不提供自助注册正式业务账户。
- 身份认证成功不等于已经开通 TokenHub 业务账户。
- TokenHub 根据统一认证返回的唯一用户标识查询本地账户及关联关系。
- 未查到业务账户时不自动创建可用账户，也不自动发放额度。
- CRM 重复通知必须幂等，不得重复创建账户、服务、额度包或业务 Key。

是否允许未订购用户登录后浏览公开模型目录和接入文档属于待确认项；在确认前，按“无可用账户则不进入业务门户”处理。

## 3. 登录主流程

### 3.1 流程说明

```text
用户访问 TokenHub 用户门户
    ↓
检查当前登录会话
    ├─ 会话有效且账户上下文仍有效 → 进入目标页或概览
    └─ 无有效会话 → 跳转统一身份认证
                           ↓
                    用户完成身份认证
                           ↓
                 TokenHub 获取唯一 userId
                           ↓
               查询可进入的账户身份及权限
                           ↓
        ┌──────────────────┼──────────────────┐
        ↓                  ↓                  ↓
    0 个可用身份       1 个可用身份       多个可用身份
        ↓                  ↓                  ↓
 未开通／同步中提示   自动选中并进入      账户身份选择页
                                              ↓
                                      用户选择账户身份
                                              ↓
                              服务端再次校验关联关系和状态
                                              ↓
                                建立账户上下文和权限快照
                                              ↓
                                      进入门户概览页
```

### 3.2 身份认证

身份认证由统一认证能力完成。具体采用运营商单点登录、手机号短信验证码、账号密码或组合方式，属于待确认项。

认证成功后，认证系统至少需要向 TokenHub 提供：

- 稳定、唯一且不可由用户修改的主体标识。
- 本次认证时间和认证方式。
- 认证结果和必要的安全等级。
- TokenHub 可校验的签名、票据或令牌。

手机号、昵称和展示名称不能单独作为账户关联主键。

### 3.3 查询账户身份

TokenHub 根据 `userId` 查询用户当前可进入的账户身份，返回：

- `accountContextId`：可选择身份的唯一标识。
- `accountId`：业务账户标识。
- `accountType`：`PRIMARY` 或 `SUB_ACCOUNT`。
- `accountName`：当前账户展示名称。
- `ownerAccountId`、`ownerAccountName`：子账户所属主账户。
- `relationshipStatus`：主子账户关联状态。
- `accountStatus`：账户状态。
- `permissions` 或权限版本。
- 最近使用时间，可选。

已解除、已禁用、已失效的子账户关系不能出现在可选列表中。

### 3.4 账户身份选择

当用户只有一个可用身份时，系统直接选中并进入门户；当用户同时具有主账户、子账户或多个子账户身份时，必须进入账户选择页。

账户选择卡片展示：

| 字段 | 展示规则 |
|---|---|
| 账户名称 | 明确本次将进入哪个账户 |
| 账户类型 | 展示“主账户”或“子账户” |
| 所属主账户 | 子账户必须展示；主账户不展示 |
| 账户状态 | 仅展示会影响选择的状态 |
| 最近使用 | 可选，用于帮助识别常用账户 |

选择页不展示 Token 余额、完整手机号、API Key 或不必要的业务敏感信息。

### 3.5 建立账户上下文

用户选定身份后，服务端重新校验用户与目标账户的关系，并建立当前账户上下文，至少包含：

- `sessionId`
- `userId`
- `accountContextId`
- `accountId`
- `ownerAccountId`
- `accountType`
- 角色和权限集合或权限版本
- 登录时间、最近活动时间和会话到期时间

后续请求必须以服务端会话中的上下文为准。前端提交的 `accountId` 只能作为查询条件，不能作为授权依据。

### 3.6 登录成功后的跳转

- 用户直接访问门户首页：进入 `/overview`。
- 用户在登录前访问合法的门户内页面：登录并选定身份后返回原目标页。
- 原目标页在当前身份下无权限：进入 403 页面，并提供返回概览入口。
- 原目标地址属于其他账户的数据详情：不得自动加载；回到模块列表或概览。

## 4. 账户切换流程

具有多个有效身份的用户登录后，可以通过顶部账户选择器切换账户。

切换流程：

1. 用户打开账户选择器。
2. 前端重新获取可用账户身份，不只依赖登录时缓存。
3. 用户选择目标身份。
4. 服务端校验用户与目标账户的当前关联关系。
5. 服务端更新或重新签发账户上下文及权限快照。
6. 前端清除上一身份的页面状态、查询缓存和敏感数据。
7. 各模块按新身份重新加载。
8. 默认进入概览；只有经模块确认安全的列表页可以保留当前路由。

切换失败时保留原账户上下文，不得出现“页面显示新账户、服务端仍使用旧账户”的中间状态。

主账户和子账户数据范围遵循[用户门户公共设计](用户门户公共设计.md)的身份与权限规则。

## 5. 页面需求

### 5.1 登录页或统一认证跳转页

如果采用外部统一认证，TokenHub 页面只展示品牌、登录说明、跳转按钮、隐私与服务协议入口及认证失败提示；账号、密码、验证码等字段由认证系统负责。

如果采用 TokenHub 自有登录页，字段和验证方式必须在认证方案确认后补充，不在本文件中编造。

### 5.2 账户身份选择页

页面包括：

- 标题“选择要进入的账户”。
- 当前登录用户的脱敏识别信息。
- 可用账户卡片或列表。
- 主账户、子账户及所属关系标识。
- 退出登录入口。
- 加载失败后的重试入口。

账户较多时支持按账户名称搜索，但搜索只在后端已授权结果中进行。

### 5.3 无可用账户页

身份认证成功但没有可用账户时，区分展示：

- 尚未开通 TokenHub 服务。
- 服务正在开通或等待同步。
- 原有关联关系已失效。
- 账户因安全原因不可用。
- 账户服务查询失败。

页面提供重试、退出登录和联系客服入口。错误信息不得暴露其他账户是否存在。

### 5.4 会话过期提示

会话过期后停止业务请求并跳转认证。重新登录后必须重新查询账户关系，不得直接恢复已失效的旧账户权限。

### 5.5 无权限页

服务端返回 403 时展示无权限页面，提供返回概览或切换账户入口。不得用空白页、无限加载或 404 掩盖明确的权限问题。

## 6. 权限与数据范围

### 6.1 主账户身份

主账户登录后原则上可访问：

- 主账户基本信息和服务。
- 主账户可见的额度及用量。
- 主账户自行创建的用户 API Key。
- 子账户管理和配额分配。
- 主账户权限范围内的汇总统计、订单、告警和审计。

具体权限以各模块需求和后端权限码为准。

### 6.2 子账户身份

原方案已明确子账户可以：

- 查看自己的可用额度。
- 查看自己名下密钥的 Token 使用情况。
- 创建和管理自己的用户 API Key。

子账户不能访问：

- 主账户全部余额和完整消费明细。
- 其他子账户的数据。
- 主账户或其他子账户创建的 API Key。
- 未授权的订单、服务管理和子账户管理功能。

模型目录和接入文档建议对正常登录的主账户与子账户开放；告警、工单等额外权限仍需各模块确认。

### 6.3 权限实施要求

- 页面菜单根据权限展示，但服务端仍必须逐接口鉴权。
- 列表、汇总、导出、详情和关联下拉选项使用同一权限范围。
- 缓存键必须包含 `accountContextId` 和权限版本。
- 账户切换、关系解除、账户冻结或权限变更后，相关缓存和会话及时失效。
- 用户修改 URL、请求体或查询参数中的账户标识，不能越权访问其他账户。

## 7. 状态与登录规则

身份、账户、服务和 API Key 状态必须分开管理。

| 状态 | 是否允许登录 | 登录后的处理 | 规则状态 |
|---|---:|---|---|
| 身份正常、账户正常 | 是 | 正常进入门户 | 本版设计 |
| Token 服务停机或暂停 | 建议允许 | 可查看状态和历史；模型调用受限 | 待业务确认 |
| Token 余额不足 | 是 | 展示余额不足；模型调用被拒绝 | 本版设计 |
| API Key 暂停 | 是 | 可查看和管理；对应 Key 不能调用 | 本版设计 |
| 子账户配额用尽 | 是 | 可查看数据；模型调用受限 | 本版设计 |
| 子账户关系解除 | 否，不能选择该身份 | 其他有效身份不受影响 | 本版设计 |
| 账户因安全原因冻结 | 建议禁止或限制 | 展示原因和申诉／联系入口 | 待业务确认 |
| 账户注销 | 待确认 | 按历史数据保留政策处理 | 待业务确认 |
| CRM 开通数据同步中 | 暂不能进入业务账户 | 展示“服务开通中”并允许重试 | 本版设计 |

服务停机与账户冻结含义不同：服务停机通常限制业务使用，账户冻结用于安全或合规处置。两者不得共用一个前端提示或状态码。

## 8. 异常流程

| 场景 | 用户提示 | 系统处理 |
|---|---|---|
| 身份认证失败 | 身份验证失败，请重试 | 不透露账户是否存在；记录失败审计 |
| 没有业务账户 | 当前身份尚未开通 TokenHub 服务 | 不自动创建正式业务账户 |
| CRM 同步中 | 服务正在开通，请稍后重试 | 查询开通状态或提供人工支持入口 |
| 没有有效身份 | 当前没有可访问的账户 | 允许退出或联系客服 |
| 账户关系在选择时失效 | 该账户已不可用，请重新选择 | 刷新身份列表，保留其他有效身份 |
| 会话过期 | 登录状态已过期，请重新登录 | 终止业务请求，重新认证 |
| 权限不足 | 当前账户无权访问该功能 | 返回 403，不返回受限数据 |
| 账户服务不可用 | 系统暂时不可用，请稍后重试 | 不绕过认证或使用过期权限降级 |

## 第二部分：技术设计与接口契约

## 9. 建议权限码

| 权限码 | 用途 |
|---|---|
| `portal.login` | 进入用户门户 |
| `portal.context.switch` | 切换已有账户身份 |
| `portal.profile.read` | 查看当前登录用户基础资料 |
| `portal.services.read` | 查看当前账户服务 |
| `portal.apikey.read` | 查看当前身份的用户密钥列表 |
| `portal.apikey.manage` | 创建、暂停、恢复和删除当前身份的用户密钥 |
| `portal.usage.read` | 查看当前身份用量 |
| `portal.subaccount.manage` | 管理子账户，主账户专用 |

登录接口不得直接把“主账户”“子账户”等前端标签当成完整授权；最终权限由后端返回并校验。

## 10. 接口清单

接口路径为建议契约，可按项目网关规范调整。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/auth/login-options` | 获取认证方式和登录入口配置 |
| POST | `/api/v1/auth/exchange` | 用统一认证票据换取 TokenHub 会话 |
| GET | `/api/v1/session` | 查询当前登录用户、会话和当前账户上下文 |
| GET | `/api/v1/account-contexts` | 查询当前用户可进入的账户身份 |
| POST | `/api/v1/session/account-context` | 选择或切换当前账户身份 |
| POST | `/api/v1/session/logout` | 退出当前会话 |
| POST | `/api/v1/session/logout-all` | 退出全部设备，可选 |

### 10.2 选择账户身份请求

```json
{
  "accountContextId": "ctx_002"
}
```

服务端处理顺序：

1. 从当前会话取得 `userId`。
2. 查询 `userId` 与 `accountContextId` 的有效关联关系。
3. 校验账户和关系状态。
4. 加载角色、权限和权限版本。
5. 原子更新会话中的账户上下文。
6. 返回当前上下文的脱敏信息和权限集合。
7. 写入账户切换审计日志。

## 11. 会话设计

### 11.1 会话原则

- 优先使用安全、不可由前端脚本读取的会话 Cookie 或经安全评审的令牌方案。
- 令牌和 Cookie 使用 HTTPS 传输，并设置适当的 `HttpOnly`、`Secure`、`SameSite` 属性。
- 会话具有绝对有效期和空闲超时时间，具体数值待安全团队确认。
- 退出登录后，服务端立即使当前会话失效。
- 用户冻结、主子账户关系解除、权限撤销或高风险事件发生后，可以强制相关会话失效。
- 修改权限后不得继续使用旧权限缓存直到自然过期。

### 11.2 前端状态

前端只保存展示所需的脱敏用户信息、当前账户摘要和权限结果。不得在本地持久化：

- 认证密码或验证码。
- 统一认证原始票据。
- 完整 API Key。
- 供应商凭证。
- 可用于绕过服务端校验的账户权限数据。

## 12. 数据模型建议

以下为逻辑模型，不代表必须由 TokenHub 新建同名表；若统一身份或账户中心已有权威数据，应通过适配层引用。

### 12.1 用户账户关联

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | bigint / string | 关联记录标识 |
| `user_id` | string | 登录用户唯一标识 |
| `account_context_id` | string | 可选择的业务身份标识 |
| `account_id` | string | 当前账户或子账户标识 |
| `owner_account_id` | string nullable | 子账户所属主账户 |
| `account_type` | enum | `PRIMARY`、`SUB_ACCOUNT` |
| `relationship_status` | enum | `ACTIVE`、`DISABLED`、`REMOVED`、`EXPIRED` |
| `role_code` | string | 角色标识 |
| `permission_version` | string | 权限版本，用于缓存失效 |
| `effective_at` | datetime | 生效时间 |
| `expired_at` | datetime nullable | 失效时间 |
| `updated_at` | datetime | 更新时间 |

建议唯一约束覆盖 `user_id + account_context_id`。关联关系变化需要发布权限失效事件。

### 12.2 登录会话

| 字段 | 类型 | 说明 |
|---|---|---|
| `session_id` | string | 会话标识 |
| `user_id` | string | 登录用户 |
| `account_context_id` | string nullable | 当前业务身份；选择前为空 |
| `permission_version` | string nullable | 当前权限版本 |
| `authenticated_at` | datetime | 认证时间 |
| `last_active_at` | datetime | 最近活动时间 |
| `expires_at` | datetime | 绝对过期时间 |
| `status` | enum | `ACTIVE`、`LOGGED_OUT`、`EXPIRED`、`REVOKED` |
| `client_ip` | string | 客户端地址，按安全规范处理 |
| `device_summary` | string nullable | 脱敏设备摘要 |

会话存储和留存周期由安全架构确定，不建议把可用会话令牌明文写入业务数据库或日志。

## 13. 审计要求

下列事件需要记录审计日志：

- 登录成功和失败。
- 查询到无业务账户或同步中状态。
- 账户身份选择和切换。
- 退出登录和强制会话失效。
- 因冻结、关系失效或权限不足而被拒绝。
- 运营人员对用户状态、账户关系和会话采取的管理操作。

日志至少包含事件类型、时间、结果、`userId`、`accountContextId`、会话标识、客户端地址、必要的设备摘要和失败原因码。日志不得记录密码、短信验证码、认证票据、完整 API Key 或完整供应商凭证。

## 14. 安全和非功能要求

- 所有认证和会话接口只允许 HTTPS。
- 防止会话固定、重放、CSRF、开放重定向和账户枚举。
- 连续认证失败达到阈值后启用验证码、短期限制或统一认证侧的安全策略。
- 登录和账户切换接口需要限流。
- 可用账户查询必须在服务端完成用户归属过滤。
- 多实例部署下会话撤销和权限变更应及时同步。
- 认证服务不可用时不得绕过认证；已有会话是否短时继续使用由安全团队确认。
- 页面和接口错误信息使用统一错误码，便于客服和审计定位。
- 登录链路需要监控成功率、失败原因、响应时间、无账户比例和 CRM 同步异常量。

## 15. 验收标准

### 15.1 正常场景

1. 只有一个正常主账户的用户认证成功后直接进入概览。
2. 同时具有主账户和子账户的用户进入账户选择页，并能分别进入两个身份。
3. 属于多个主账户的子账户用户能够识别所属关系并选择正确身份。
4. 用户切换身份后，页面数据、菜单、权限和查询缓存全部按新身份重载。
5. 用户退出后，原会话不能继续调用受保护接口。

### 15.2 状态场景

1. 余额不足的用户仍能登录和查看数据，但模型调用被额度校验拒绝。
2. API Key 暂停不影响门户登录，对应 Key 无法调用模型。
3. 子账户关系解除后不再出现在身份列表中，已有相关会话及时失效。
4. CRM 开通同步中时展示明确状态，不提示错误账户，也不重复创建账户。
5. 服务停机、账户冻结和账户注销按照确认后的独立规则处理。

### 15.3 安全场景

1. 子账户修改 URL、请求体或查询参数中的账户 ID，服务端拒绝越权访问。
2. 切换账户失败时仍保持原账户上下文，不发生前后端身份不一致。
3. 缓存数据不跨账户上下文复用。
4. 会话过期、退出或被撤销后，受保护接口返回统一未认证响应。
5. 日志、错误页和浏览器存储中不存在密码、验证码、完整密钥或认证票据。

## 16. 待确认事项

| 编号 | 待确认问题 | 责任方 | 未确认前处理 |
|---|---|---|---|
| C01 | 用户门户采用哪种统一认证方式 | 统一认证／产品 | 保留认证适配层，不实现自有账号密码 |
| C02 | 身份系统返回的唯一用户标识是什么 | 统一认证／账户 | 不使用手机号作为唯一主键 |
| C03 | 是否完全禁止用户自主注册 | 产品／CRM | 不建设自助注册和自动开户 |
| C04 | 未订购用户能否登录浏览模型目录和文档 | 产品 | 无业务账户时进入提示页 |
| C05 | Token 服务停机后允许查看和操作哪些页面 | 产品／账户 | 登录与调用资格分离，具体按钮按后端权限 |
| C06 | 账户冻结和注销后的登录及历史查询策略 | 产品／安全／合规 | 不自行推断，使用独立状态 |
| C07 | 会话有效期、空闲超时和并发设备数量 | 安全 | 配置化，开发环境不代表生产规则 |

| C09 | 是否记住上次使用的账户身份 | 产品／安全 | 只可作为候选，进入前仍校验关系 |
| C10 | AI 应用订购用户在 TokenHub 门户可查看哪些内容 | 产品／AI 应用 | 不开放业务 Key 管理，不暗示额度跨业务共享 |
| C11 | CRM 是否提供可查询的“开通中”状态 | CRM／账户 | 无能力时使用通用同步提示和人工支持入口 |
| C12 | 子账户除密钥、额度和用量外还有哪些权限 | 产品 | 仅开放原方案已明确或模块已确认的权限 |

## 17. 评审结论要求

开发前至少冻结 C01、C02、C05、C06、C07 和 C11。其余待确认项可以通过配置、权限适配层和受控入口隔离，但不得由前端或代码生成模型自行补充生产业务规则。
