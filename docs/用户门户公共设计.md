## 1. 文档范围与规则状态

本文统一跨模块复用的规则。各模块在同一文档内分段描述页面需求、交互逻辑、技术设计、接口及实现约束。提取为公共设计不代表待确认规则已获业务确认。

规则标记：

- **方案已有**：原平台设计方案明确描述。
- **本版设计**：本需求文档提出的实现约定，可用于原型、Mock 和开发。
- **待业务确认**：原方案尚未明确；联调前须确认，禁止开发模型自行补充业务规则。

状态：本版设计可以作为编码输入，但涉及计量单位、账户数据范围和下游接口的待确认项仍是生产联调前置条件。下游能力未具备时使用适配层和 Mock，不得用随机数据冒充真实业务数据。

相关文档：[概览需求与技术设计](用户门户需求文档-01-概览.md)。公共规则由本文维护；模块文档引用，不另行定义冲突版本。

## 4. 身份与权限

### 4.1 身份模型

区分登录用户 `userId` 与当前业务身份 `accountContextId`。同一个登录用户可以具有一个主账户身份及多个子账户身份。

后端根据登录会话及当前业务身份确定权限，不能直接信任前端传入的用户 ID、主账户 ID 或子账户 ID。跨身份读取一律返回 403。

### 4.2 身份切换与会话失效

1. 顶部选择器负责发起身份切换，公共框架完成身份验证。
2. 切换开始即清空旧身份业务数据，并取消或丢弃旧请求。
3. 验证成功后，各模块按新身份重新加载数据、重算入口与权限；筛选条件如何重置由模块需求定义。
4. 响应必须携带 `accountContextId`；与当前身份不一致的响应不得渲染。
5. 登录失效 401 时清空业务数据，由公共框架处理重新登录。
6. 身份无权限 403 时清空业务数据，显示无访问权限，不自动切换到其他身份。
7. 权限校验及字段裁剪由后端完成，不能仅依赖前端隐藏。

### 4.3 数据范围与权限边界

子账户仅查看自身配额和用量，不接收主账户精确余额、订单或其他子账户信息。调用同时受主账户服务状态、可用余额和自身配额限制。

主账户用量暂按本账户及其子账户归属本账户服务的调用汇总，按调用记录去重；须与用量中心统一，并在生产联调前确认。不得将主账户账本扣减和子账户配额扣减当作两笔调用。

状态和操作权限分别由后端返回，不凭余额或状态自行推断创建密钥、管理或调用权限。子账户告警、工单等额外权限仍待确认。

## 5. 统一计量与时间口径

- 调用次数为权限范围内唯一调用数，包含成功和失败，内部重试不重复计数。
- Token 指标仅汇总已获取完整 Token 计量的调用；总量为输入与输出之和。输入含缓存命中部分，输出不额外叠加其中已包含的推理 Token。
- 非 Token 计量调用计入调用次数，不强行换算为 Token。未完成计量不视为零；未完成数量无法提供时返回未知。
- 不同模型的计量字段由后端适配层统一，前端不猜测。未完成计量和非 Token 计量分类须互斥定义后再作数量校验，不能直接假定计数之和等于调用次数。
- 实际计量 Token 与套餐扣减额度使用独立字段，不混用。配额已用量来自权威配额账本，不从近期用量推算。
- 不同服务或单位的额度不自行合并、换算；多额度包的可用额度由权威服务提供。
- 统计时区为 `Asia/Shanghai`，自然日区间按起始日零时至结束日次日零时的左闭右开边界查询，不包含未来时间。
- 数据源截至时间与接口生成时间区分；不能以请求完成时间或服务器当前时间冒充业务数据更新时间。
- 同一统计的每日与区间汇总来自同一快照或明确的同一截止点。

## 6. 公共展示与接口约定

### 6.1 展示与异常

未知状态不按正常处理，未知数量不显示为零；空数组仅表示成功查询后无数据。错误提示不泄露内部堆栈。数量可按万／亿缩写，悬浮提供精确原值。

目标模块尚未接入时，路由占位页明确显示“该模块尚未接入”；不能点击无反应或伪报操作成功。生产发布前必须接通所发布功能的目标页。

### 6.2 接口基础规范

- URL 前缀示例为 `/api/portal/v1`，以项目实际网关前缀为准。
- 使用现有登录机制；当前身份通过现有会话或 `X-Account-Context-Id` 传递。若采用请求头，服务端必须验证该身份属于当前登录用户。
- 所有 ID 为字符串；所有数量为非负十进制字符串，避免 JavaScript 大整数精度损失；额度是否允许小数由 `unit` 决定。
- 日期格式 `YYYY-MM-DD`，时间使用带偏移的 ISO 8601，例如 `2026-09-28T15:00:00+08:00`。
- `null` 表示未知／不可用，不等于零；空数组表示已查询成功但无数据。
- 不返回密钥原文、供应商成本或无权查看的账户字段。
- 返回 `requestId` 用于排查，业务错误提示不暴露下游堆栈。

计算和格式化使用十进制／大整数工具；图表近似值仅用于绘图，精确提示使用原始字符串。负余额是否存在仍待确认；本版契约不接收负数，若真实账本允许透支，应修订契约，适配层不得静默截断为零。

### 6.3 分区查询状态契约

以下结构适用于采用分区聚合查询的模块，不要求所有接口都使用该结构。

```ts
type DecimalString = string;
type SectionStatus = 'READY' | 'EMPTY' | 'STALE' | 'ERROR' | 'HIDDEN';

interface Section<T> {
  status: SectionStatus;
  dataAsOf: string | null;
  data: T | null;
  error: { code: string; message: string; retryable: boolean } | null;
}
```

`HIDDEN` 的 `data` 必须为 `null`，不能只在前端隐藏。`READY`／`EMPTY` 必须有结构化 `data`；`ERROR` 的 `data=null`；`STALE` 必须有同身份旧数据和原截至时间。权限裁剪在聚合前完成。计量完整程度 `PARTIAL` 不等同于接口失败。

### 6.4 数据隔离与存储约定

数据库时间建议统一存 UTC，接口输出带偏移时间，统计按上海时区划分自然日。业务实体、完整 DDL、状态流转、外键和历史留存由所属模块技术设计维护，不据查询契约生成跨系统硬外键。

缓存及旧数据降级不得跨身份、权限范围或筛选条件复用。缓存不能替代权限校验，也不能据缓存余额决定实际调用准入。缓存键须覆盖身份、权限版本及相关筛选条件，权限变化立即失效。

## 7. 跨模块待确认项

| 事项 | 需确认方 | 当前处理 |
|---|---|---|
| 套餐额度实际单位、不同模型折算规则、是否可透支 | 产品／计费 | 保留独立单位；不展示合并余额或百分比；负值规则需修订后接入 |
| Token服务与AI应用是否存在跨业务抵扣 | 产品／CRM | 不暗示共享；按服务展示 |
| 主账户用量是否默认含子账户、服务归属如何标识 | 产品／大网关 | 暂按包含且调用去重设计，生产联调前确认 |
| 网关是否具备完整输入输出、缓存、唯一请求ID、计量完成状态 | 大网关 | 用适配接口隔离，缺失返回未知／部分完整 |
| 子账户配额有效期和周期刷新方式 | 产品／额度模块 | 只展示后端给出的周期，不自行推算 |
| 子账户告警／工单等额外权限 | 产品 | 概览隐藏子账户告警，其他模块后续明确 |
| 账户状态、停机后的管理权限 | 账户模块／产品 | 能否操作通过后端权限字段确定 |
| 告警已读是按用户还是按业务身份 | 产品／告警模块 | 暂按业务身份设计，待统一 |
| 下游查询接口、数据延迟、可查询历史范围 | 各后端负责人 | Mock先行，页面显示真实数据截至时间 |
