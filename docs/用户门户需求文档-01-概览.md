## 第一部分：业务需求与页面交互

## 1. 目标与范围

本文集中描述概览模块的业务需求、页面交互、技术实现、接口、数据字典及验收标准。门户结构、身份权限及统一计量规则引用[用户门户公共设计](用户门户公共设计.md)。公共文档中的待确认规则仍须在生产联调前确认。

用户登录后，在一个页面内回答：

1. 当前使用哪个账户身份？
2. 我的服务／分配配额还剩多少，是否存在使用限制？
3. 最近用了多少 Token？
4. 是否有需要查看的额度或调用告警？
5. 下一步如何创建密钥、查看用量、阅读接入文档？

概览不执行订购、充值、扣费、分配额度或密钥管理，只提供汇总查询和进入对应模块的入口。

概览为默认登录落地页，使用门户公共布局和顶部身份选择器。首版不提供在线支付、应用市场、模型聊天体验、供应商或路由管理、自定义仪表盘。

## 2. 角色展示与身份切换

### 2.1 展示矩阵

| 页面区域 | 主账户身份 | 子账户身份 |
|---|---|---|
| 身份与状态栏 | 当前主账户名称及状态 | 当前子账户名称及状态 |
| 额度区域 | 当前主账户订购服务，按服务展示 | 当前子账户各项分配配额，不返回主账户精确余额 |
| 用量指标及趋势 | 本账户及其子账户归属本账户服务的调用，按调用记录去重 | 仅当前子账户调用 |
| 快捷入口 | 创建密钥、查看用量、接入文档、子账户管理 | 创建密钥、查看用量、接入文档 |
| 告警摘要 | 当前账户有权查看的告警 | 本版隐藏，待子账户告警权限明确 |
| 公告摘要 | 已发布且对当前身份可见的公告 | 同左，本版建议开放 |

主账户汇总范围是本版设计，须与用量中心统一。不得将主账户账本扣减和子账户配额扣减当成两笔调用累加。

### 2.2 切换后的页面行为

身份切换遵循公共设计：立即清除旧身份数据，验证成功后展示新身份数据，旧请求结果不得重新出现。概览时间筛选恢复默认近 7 天，告警区域、快捷入口和额度区域随身份权限同步更新。

## 3. 页面结构

### 3.1 桌面布局

```text

├────────┬─────────────────────────────────────────────────┤
│ 左菜单 │ 概览                           [刷新]             │
│        │ 账户名称 · 身份 · 账户状态                        │

│        ├─────────────────────────────────────────────────┤
```

使用普通管理门户视觉风格：白色内容卡片、轻量边框、状态标签，避免大屏风格。首版不提供卡片拖拽、自定义布局或可配置首页。

宽度 ≥1200px 时服务卡片每行 3 张；768～1199px 每行 2 张；小于 768px 每行 1 张，双列区改为单列。侧栏折叠由公共框架负责。图表与表格不导致整页横向滚动。

### 3.2 页面标题区

- 标题固定为“概览”。
- 显示当前账户名称、身份标签和业务状态。
- 显示刷新按钮，刷新中禁用重复点击。
- 每个区域独立显示数据截至时间，不能用请求完成时间冒充业务数据更新时间。
- 未知状态显示“状态暂不可用”，不自动按正常处理。

## 4. 分区功能与交互

### 4.1 账户限制提示条

仅后端返回明确限制时显示，例如：“当前账户已停机，模型调用受限。请通过原业务办理渠道处理。”

子账户可能显示：“主账户当前服务受限，您的配额可能暂时无法使用。”不泄露主账户余额、订单或其他子账户信息。

状态与操作权限分别由后端返回。前端不得仅凭“余额大于零”推断允许创建密钥或允许调用。

### 4.2 我的服务与余量（主账户）

默认最多 3 张卡片；后端按有效服务优先、即将到期优先、服务 ID 稳定排序。不在前端仅对返回的 3 张再次推断全量排序。

每张卡片包含：

| 内容 | 展示规则 |
|---|---|
| 服务名称 | 单行省略，悬浮展示全称 |
| 服务类型 | Token 服务 / AI 应用 |
| 服务状态 | 正常、待生效、已停机、已到期、已退订、未知 |
| 剩余额度 | 数值和计量单位同时展示；不可用显示 `—` |
| 有效期信息 | 有效期截至时间；连续包可显示下次刷新时间；缺失则不猜测 |
| 额度状态 | 充足、较低、已耗尽、待确认，按后端结果展示 |
| 服务详情 | 跳转 `/services/:serviceId` |
| 查看用量 | 跳转 `/usage?tab=statistics&serviceId=...` |

特殊规则：

- 一个服务存在多个有效额度包时，本模块仅展示后端提供的服务可用额度，不自行累加包额度。
- 额度单位不同或后端无法合并时，卡片显示“多种额度”，按钮文案为“查看额度详情”。
- 首版不显示余量百分比，避免连续包和不同有效期急救包混用导致分母不成立。
- 不显示 AI 应用业务密钥，不提供其复制、暂停等按钮。
- “查看全部”跳转 `/services`，不携带跨账户标识。
- 无服务时显示：“暂无已开通服务，完成业务订购后可在此查看。”仅提供接入文档入口，不伪造 CRM 购买链接。

### 4.3 我的可用配额（子账户）

每项显示：关联服务名称、分配配额、本周期已使用配额、剩余配额、有效期（如有）、可用状态。

- 最多显示 3 项，更多内容通过“查看我的用量”进入 `/usage`。完整配额展示由子账户用量中心承担。
- 固定说明：“实际调用同时受主账户服务状态和可用余额限制。”
- 主账户受限时显示受限原因摘要，不展示其精确余额。
- 无配额时显示：“暂未分配可用配额，请联系主账户管理员。”
- 不显示服务订单入口、加订入口或主账户服务详情入口。

### 4.4 用量概况

默认近 7 天，可切换近 30 天；首版不做自定义日期。统计时区固定为 `Asia/Shanghai`，日期区间从起始日 00:00:00 起，到结束日次日 00:00:00 前，不包含未来时间。

近 7 天包含今天及之前 6 个自然日。今天尚未结束，必须标注“今日数据截至 HH:mm”。

展示调用次数、总 Token、输入 Token、输出 Token 四项指标，按[公共设计第 5 章](用户门户公共设计.md#5-统一计量与时间口径)统计。

存在计量未完成记录时，显示“部分调用用量仍在更新”，不将未知用量当作零。

趋势图采用每日输入／输出 Token 堆叠柱状图，悬浮提示展示日期、输入、输出、合计。完整数据中无调用的日期补零；未完整同步的日期应带标识，不能当成已确认无调用。

交互：

1. 切换时间范围，只刷新用量区域，其余区域保持。
2. 刷新期间用量区显示加载遮罩，避免将旧范围数值标为新范围。
3. 快速切换时只有最后一次请求结果生效。
4. 点击“查看详细用量”，将起止日期带到 `/usage?tab=statistics&startDate=YYYY-MM-DD&endDate=YYYY-MM-DD`。
5. 图表首版无点击钻取，避免隐含交互。

首版概览不放消费金额卡片：方案尚未统一额度、价格倍率和 CRM 实际收费关系。金额统计由后续用量中心需求明确后再扩展，不用上游成本替代用户消费。

### 4.5 快捷操作

| 操作 | 行为 | 可用条件 |
|---|---|---|
| 创建 API 密钥 | `/api-keys?action=create`，目标页打开创建弹窗 | 当前身份具有创建用户密钥权限 |
| 查看用量 | `/usage?tab=statistics` | 有查看本人／当前身份用量权限 |
| 接入文档 | `/help/docs` | 有文档访问权限 |
| 子账户管理 | `/subaccounts` | 主账户且有管理权限 |

后端返回不可创建原因时，创建入口禁用并显示原因，例如“当前身份未关联可创建密钥的 Token 服务”。不要根据额度已耗尽直接禁止创建，除非业务规则明确如此。

目标页未实现时，由路由占位页明确显示“该模块尚未接入”；不能点击无反应或伪报创建成功。生产发布前必须接通所发布功能的目标页。

### 4.6 告警摘要（主账户）

- 显示未读总数和最新 5 条有权查看的告警。
- 列表字段：告警级别、标题、关联服务、发生时间、已读状态。
- 点击进入 `/alerts/:alertId`；是否标记已读由告警详情模块执行，概览不自动改变已读状态。
- “查看全部”进入 `/alerts`。
- 无告警显示“暂无告警”。
- 额度阈值由告警模块／后台规则确定，概览不写死“10元”“0.5元”或百分比阈值。

### 4.7 平台公告

- 展示最新 3 条当前身份可见、已发布且未撤回的公告。
- 按置顶优先、发布时间倒序排列；展示标题、分类、发布时间。
- 点击进入 `/help/announcements/:announcementId`。
- 未授权或不存在的详情由目标页返回无权限／不存在状态，概览不缓存正文绕过权限。
- 无公告显示“暂无公告”。

## 5. 状态、错误与刷新

| 状态 | 页面行为 |
|---|---|
| 初次加载 | 身份验证后，各区域显示骨架屏 |
| 正常无数据 | 使用本区专用空态文案，数值零仅用于已确认的零 |
| 单区失败 | 仅该区显示“暂时无法获取数据”和重试，其余区域继续展示 |
| 下游暂不可用但有同身份旧数据 | 显示旧数据、明确标注“数据暂未更新”及原截至时间 |
| 无旧数据且下游失败 | 显示错误态，不显示 0 或空列表伪装成功 |
| 登录失效 401 | 公共框架处理重新登录，清空业务数据 |
| 身份无权限 403 | 清空页面，显示无访问权限，不自动切换到另一个身份 |
| 刷新成功 | 更新区域数据和截至时间；不强制弹成功提示 |
| 连续点击刷新 | 当前刷新完成前禁用按钮 |

本版只在进入页面、切换身份、修改时间范围、手动刷新时查询，不做后台轮询。保留页面期间数据可能变旧，页面始终展示数据截至时间。

身份认证失败不能按区域部分成功继续展示。

## 第二部分：技术设计与数据定义

## 6. 后端职责与接口契约

### 6.1 职责

门户后端负责身份校验、数据范围控制、聚合查询、字段标准化和部分失败隔离。它不承担网关的 Token 采集、扣减、重试计数或余额账本维护。

建议划分 `AccountContextProvider`、`ServiceSummaryProvider`、`UsageSummaryProvider`、`AlertSummaryProvider`、`AnnouncementProvider` 适配接口，隔离真实下游接口和 Mock。

账户／服务／配额数据来自相应业务模块或 CRM 同步结果；用量来自大网关或用量查询服务；告警和公告来自各自模块。不能假设所有信息都由大网关提供。

### 6.2 公共约定

使用[公共设计第 4～6 章](用户门户公共设计.md)中的身份隔离、计量口径、接口基础规范及 `DecimalString`、`SectionStatus`、`Section<T>` 契约。下文类型引用这些公共定义。

### 6.3 接口清单

| 方法及路径 | 用途 | 参数 |
|---|---|---|
| GET `/overview` | 初次加载和全页刷新 | `range=LAST_7_DAYS\|LAST_30_DAYS`，默认前者 |
| GET `/overview/usage` | 时间范围切换、用量区重试 | 同上 |
| GET `/overview/services` | 服务／配额区重试 | 无 |
| GET `/overview/alerts` | 告警区重试 | 无，仅有权限身份 |
| GET `/overview/announcements` | 公告区重试 | 无 |

各分区接口返回与聚合接口相同的 `Section<T>` 结构。聚合接口响应状态 200 可以包含部分失败区；会话／身份非法返回 401／403，参数错误返回 400，聚合服务自身异常返回 500。

### 6.4 聚合响应结构（TypeScript 契约表示）

```ts

}

  mode: 'OWNED_SERVICES' | 'ASSIGNED_QUOTAS';

  items: ServiceCard[]; // 最多3条；子账户字段裁剪见数据字典
}

  serviceName: string;
  serviceType: 'TOKEN_SERVICE' | 'AI_APPLICATION';

  remainingQuota: DecimalString | null;
  quotaUnit: 'TOKEN' | 'CREDIT' | 'CNY' | 'OTHER' | null;
  quotaUnitLabel: string | null;
  quotaHealth: 'NORMAL' | 'LOW' | 'EXHAUSTED' | 'UNKNOWN';
  expiresAt: string | null;
  nextRefreshAt: string | null;
  assignedQuota: DecimalString | null; // 仅子账户有值
  usedQuota: DecimalString | null; // 仅子账户有值
  availability: 'AVAILABLE' | 'RESTRICTED' | 'UNKNOWN';
  restrictionMessage: string | null;
}

interface UsageSummary {
  startDate: string;
  endDate: string; // 页面日期含首含尾，查询用次日零时作排他边界
  timezone: 'Asia/Shanghai';
  scope: 'MAIN_WITH_SUBACCOUNTS' | 'CURRENT_SUBACCOUNT';
  requestCount: DecimalString | null;
  tokenMeasuredRequestCount: DecimalString | null;
  pendingMeteringRequestCount: DecimalString | null;
  nonTokenRequestCount: DecimalString | null;
  inputTokens: DecimalString | null;
  outputTokens: DecimalString | null;
  totalTokens: DecimalString | null;
  completeness: 'COMPLETE' | 'PARTIAL' | 'UNKNOWN';
  daily: Array<{
    date: string;
    inputTokens: DecimalString | null;
    outputTokens: DecimalString | null;
    totalTokens: DecimalString | null;
    completeness: 'COMPLETE' | 'PARTIAL' | 'UNKNOWN';
  }>;
}

interface AlertSummary {
  unreadCount: number;
  items: Array<{
    alertId: string;
    title: string;
    severity: 'INFO' | 'WARNING' | 'CRITICAL';
    serviceId: string | null;
    serviceName: string | null;
    occurredAt: string;
    isRead: boolean;
  }>;
}

interface AnnouncementSummary {
  items: Array<{
    announcementId: string;
    title: string;
    category: 'MAINTENANCE' | 'MODEL_CHANGE' | 'GENERAL';
    publishedAt: string;
    isPinned: boolean;

```

## 7. 数据字典

### 7.1 关键业务字段

| 字段 | 含义 | 来源／规则 |
|---|---|---|
| accountContextId | 当前业务身份标识 | 身份服务，不是登录用户 ID |
| serviceId | 服务实例标识 | 订购同步／服务模块；不是产品目录 ID |
| remainingQuota | 当前身份在该服务下剩余可用额度 | 主账户为服务额度，子账户为自身配额；不混用 |
| assignedQuota | 当前周期分配配额 | 仅子账户，未知时 null |
| usedQuota | 当前周期已用配额 | 配额账本权威值，不能从近期7天用量推算 |
| quotaUnit | 额度单位代码 | Token、平台额度、人民币或其他；实际产品支持范围待确认 |
| quotaUnitLabel | 单位展示名称 | OTHER 必填；CREDIT 应提供正式业务名称 |
| expiresAt | 当前展示权益到期时间 | 多包无法单一表达则 null，详情页展示 |
| nextRefreshAt | 连续包下一次刷新时间 | 非连续包或未知为 null |
| quotaHealth | 权威额度告警状态 | 由额度／告警模块给出，前端不计算阈值 |
| availability | 当前身份调用该服务的可用性摘要 | 综合业务规则结果，不等同于余额状态 |
| requestCount | 可见唯一调用次数 | 网关／用量服务；内部重试不重复计数 |
| inputTokens | 实际计量输入 Token | 包含缓存命中输入，不是套餐扣减量 |
| outputTokens | 实际计量输出 Token | 不单独叠加已含在输出中的推理 Token |
| totalTokens | 输入与输出之和 | 同一完整计量数据集汇总 |
| completeness | 统计计量完整程度 | PARTIAL 不等同于接口失败 |
| dataAsOf | 数据源截至时间 | 不允许用服务器当前时间伪造 |

### 7.2 空值和一致性校验

- `SINGLE_UNIT`：可用时 `remainingQuota` 和 `quotaUnit` 必填。
- `MULTIPLE_UNITS`：`remainingQuota=null`，概览不进行换算。
- 主账户 `assignedQuota`、`usedQuota` 为 null；子账户不得通过其他字段收到主账户精确余额。
- 已知完整计量数据满足 `totalTokens = inputTokens + outputTokens`，每日汇总与区间汇总来自同一快照或明确的同一数据截止点。
- 未完成计量、非 Token 计量的分类需互斥定义后再用于数量校验；不可直接假定若干计数总和等于调用次数。
- 负余额是否存在为待确认规则；本版契约不接收负数。若真实账本允许透支，须先修订字典和展示规则，适配层不得静默截断为零。

## 8. 表结构与数据存储设计

### 8.1 本模块是否需要新表

**首版概览不新增独立业务表，也不新增余额、订单或用量账本。** 页面是现有业务数据的查询视图。创建 `overview_balance` 等副本会产生余额不一致的问题。

以下保留原稿中的依赖模块最小逻辑模型建议，供后续模块设计时核对，不是公共权威表结构，也不是要求概览开发人员现在建表。完整设计须迁入所属模块合并文档的技术设计部分维护，概览最终仅消费其数据契约。若大网关或现有业务服务已提供对应能力，优先消费接口，不重复建库。

### 8.2 依赖逻辑模型

| 逻辑表／实体 | 最小字段及建议类型 | 键及关系 | 归属 |
|---|---|---|---|
| account_context | id varchar(64), user_id varchar(64), account_id varchar(64), role varchar(16), status varchar(16) | PK id；user_id 索引；身份与账户关系由账户模块约束 | 账户模块 |
| service_subscription | id varchar(64), owner_account_id varchar(64), product_id varchar(64), service_type varchar(32), name varchar(128), status varchar(32), effective_at datetime(3), expires_at datetime(3) | PK id；索引 owner_account_id,status；每条代表服务实例 | 服务／CRM同步模块 |

数据库时间建议统一存 UTC，接口按约定输出带偏移时间，统计按上海时区划分自然日。上述字段是逻辑契约，完整 DDL、状态流转、外键策略及历史留存应由所属模块文档确定，不能据此生成跨系统硬外键。

### 8.3 缓存

首版不要求缓存。若下游性能需要缓存，缓存键至少包括当前身份、权限版本、区间和时区；建议有效期不超过 30 秒，权限变化立即失效。禁止不同身份复用同一个响应缓存。

旧数据降级只限同一身份、同一权限范围、同一筛选条件。缓存不能替代权限校验，不能据缓存余额做实际调用准入。

## 10. 查询超时与验证

每个下游查询设置可配置超时，本版建议 3 秒；失败返回区域错误。身份认证失败不能降级为部分成功。

按本文第 11 章验收场景准备 Mock 与验证，覆盖身份隔离、晚到请求、计量去重、自然日边界、大整数和区域失败。公共安全规则同时适用于聚合接口与各分区接口。

## 第三部分：验收与待确认事项

## 11. 验收标准

| 编号 | 场景 | 预期结果 |
|---|---|---|
| AC01 | 主账户同时有 Token 服务和 AI 应用 | 分服务展示余量，无总余额，AI 应用无密钥操作 |
| AC02 | 子账户访问概览 | 只展示自身配额和用量，无服务订单、子账户管理和主账户余额 |
| AC03 | 用户切换身份，旧请求稍后返回 | 旧数据不出现，菜单和区域权限同步更新 |
| AC04 | 近7天切换近30天并快速切回 | 仅最后选择的数据生效，日期与指标一致 |
| AC05 | 输入100，输出20，其中缓存命中60 | 总Token为120，不能变成180 |
| AC06 | 一次用户请求发生内部重试 | 调用次数按一次计算 |
| AC07 | 主账户和子账户发生关联配额扣减 | 主账户汇总不重复计算同一次调用 |
| AC08 | 子账户配额有余但主账户服务受限 | 显示调用受限摘要，不把自身配额表现为保证可调用 |
| AC09 | 服务查询失败、用量查询成功 | 服务区可重试，用量区正常显示；服务区不显示“暂无服务” |
| AC10 | 完整统计结果为0 | 显示0及空趋势说明，区别于接口失败 |
| AC11 | 存在未完成计量调用 | 显示数据更新提示，不将未完成用量当成已确认零值 |
| AC12 | 多计量单位服务 | 显示“多种额度”，不累加换算 |
| AC13 | 点击服务用量、详细用量 | 目标页保留服务或日期筛选，后端再次验证归属 |
| AC14 | 无可创建Key的服务 | 创建入口禁用并说明原因，无弹窗假成功 |
| AC15 | 告警摘要被读取 | 不自动标记已读 |
| AC16 | 数值超过JS安全整数 | 精确文本不丢位，图表提示使用原始精确值 |
| AC17 | 前端篡改账户身份请求头 | 返回403，不返回该账户任何区域数据 |
| AC18 | 401或403发生 | 清除当前业务数据，由公共框架处理 |
| AC19 | 上海时区跨日查询 | 区间边界准确，近7天含今天，不跨时区错日 |
| AC20 | 小屏幕访问 | 卡片单列，无整页横向滚动，按钮可操作 |

开发至少准备：正常主账户、正常子账户、无服务、无配额、多单位额度、账户受限、单区失败、部分计量、超大整数、快速切身份等 Mock 场景。

## 12. 待确认项与当前页面处理

跨模块问题的确认责任及规则状态统一见[公共设计第 7 章](用户门户公共设计.md#7-跨模块待确认项)。确认前，概览采用以下处理：

- 额度单位、跨业务抵扣及透支规则未明确：按服务及独立单位展示，不显示总余额或余量百分比；负值数据须先修订契约再接入。
- 主账户用量范围未最终确认：暂按包含子账户且调用去重展示。
- 子账户告警权限未明确：隐藏告警摘要。
- 配额周期和有效期不明确：只展示后端提供的信息，不自行推算。
- 账户受限后的管理权限未明确：操作入口按后端权限及原因展示。
- 计量或下游数据缺失：显示未知、部分完整或区域错误，不以零或随机数据替代。
- 告警已读归属未明确：概览不改变已读状态，由告警模块统一处理。
