## 第一部分：需求分析与页面交互

## 1. 模块定位与范围

### 1.1 用户目标

回答五类问题：

1. 指定时间内用了多少 Token，产生多少已确认消费？
2. 哪个服务、模型、密钥、子账户消耗最多？
3. 缓存命中和未命中分别使用多少输入 Token？
4. 某次调用结果如何，计量是否完成，扣减了多少额度？
5. 统计与逐笔记录能否在相同条件下核对？

### 1.2 交付范围

- 一个菜单、两个标签页：“用量统计”“调用明细”。
- 统计页：统一筛选、指标卡、每日趋势、按维度汇总列表、缓存用量说明。
- 明细页：统一筛选、附加筛选、稳定翻页、调用详情抽屉。
- 主／子账户隔离、历史对象保留、数据延迟和部分计量提示。
- 后端查询编排、网关适配接口、必要时可选的本地查询读模型。
- 数据字典、错误码、Mock 场景及验收要求。

首版不做：收费计算、修改或重放调用、余额调整、CRM订单／发票、调用请求或响应原文、供应商成本、渠道故障内部详情、用户侧导出、定时报表、同比环比、模型聊天体验、按小时图表。没有接入的功能不得显示可点击假按钮。

### 1.3 与其他模块的关系

| 模块 | 用量中心使用的数据 | 边界 |
|---|---|---|
| 账户与身份 | 当前身份、权限、历史调用归属 | 后端认证决定查询范围 |
| 我的服务 | 服务标识、名称、服务类型 | 展示调用所属服务，不查询订单或重新计算余额 |
| API密钥 | 用户密钥ID及历史名称 | 不返回密钥原文；业务密钥完全不暴露 |
| 子账户 | 实际调用账户ID、历史名称 | 仅主账户具备跨子账户筛选能力 |
| 模型目录 | 平台模型ID、调用时名称、请求的model标识 | 不展示提供商模型、端点 |
| 大网关／计量服务 | 唯一调用、状态、Token、缓存、时间 | 不重复实现采集；先确认其查询与聚合能力 |
| 计费／额度服务 | 最终用户消费、最终额度扣减 | 不把预扣、上游成本或CRM购买金额当成消费 |
| 操作审计 | 无直接统计依赖 | 管理操作在操作审计，模型调用在本模块 |

## 2. 统一统计口径

### 2.1 一次调用与多条流水

`callId` 是平台受理并能归属到合法账户的一次客户端调用的稳定唯一标识，与门户查询请求的 `requestId` 区分。

- 同一次调用内部重试多家提供商，调用次数仍为1。
- 客户端重新发起的新请求若平台未承诺幂等去重，按新的调用计算，不能凭相同内容去重。
- 预扣、校正、释放是同一次调用的额度处理阶段，不是三次调用。
- 无法归属账户的认证失败请求不进入用户用量；是否接入可归属的准入拒绝记录由网关能力确认，不声称覆盖全部网关请求。
- 时间筛选统一按平台接收调用时间 `startedAt`；迟到计量、最终收费回补到原调用日期。不是按扣款时间查询资金流水。

### 2.2 三类数值不得混用

| 类型 | 字段示例 | 说明 |
|---|---|---|
| 实际模型Token | inputTokens、outputTokens | 物理计量，用于本模块Token统计 |
| 套餐扣减额度 | quotaDeductions[].amount + unit | 权威最终扣减，可能是token或point，不从实际Token乘倍率猜测 |
| 用户消费金额 | charge.amount + currency | 权威服务提供的当前最终净计费结果，不是CRM订单金额或上游成本 |

金额为“调用消费参考／核对”，不宣称是可开票账单。用户实付含套餐优惠如何分摊，必须由产品／计费定义。

### 2.3 Token与缓存

本版采用以下标准化模型：

- `totalTokens = inputTokens + outputTokens`。
- `inputTokens` 包含缓存命中输入和未命中输入；不能再把缓存命中量加到总量。
- 有完整二分拆分时：`inputTokens = cacheReadInputTokens + cacheMissInputTokens`。
- 缓存写入量 `cacheWriteInputTokens` 是未命中输入中的可选子集，仅在上游语义可准确映射时提供，不能额外加到输入或总量。
- 推理 Token 若已含在输出中，不再次相加。
- 标准化输入可能需要适配上游字段；上游某字段已含缓存时不得重复计入。映射策略必须可验证。
- 缓存分类无法准确映射时，输入总量可以完整，缓存拆分单独为“不完整／不支持”。不可用“输入减已知缓存”假定缺失部分全部未命中。
- 缓存命中占比 = 完整缓存拆分记录的命中输入 / 同一记录集合的输入总量。分母0显示 `—`；标注“仅统计支持缓存拆分的已计量调用”，同时展示覆盖调用数。

### 2.4 三种独立状态

| 维度 | 状态 | 含义 |
|---|---|---|
| 调用结果 | PROCESSING / SUCCESS / FAILED / CANCELLED | 处理中、成功、失败、客户端取消 |
| Token计量 | PENDING / COMPLETE / UNAVAILABLE / NOT_APPLICABLE | 等待计量、完整、无法获取、非Token计量 |
| 用户计费 | PENDING / SETTLED / NOT_CHARGED / UNAVAILABLE | 待确认、已确认、明确不收费、暂无法提供 |

调用失败不意味着零消耗或免费；客户端断开后可能仍有已计量和已计费记录。状态由权威系统提供，前端不根据HTTP码推导费用。

记录中 `COMPLETE` 才要求Token非空并纳入统计；`NOT_APPLICABLE` 不计入Token，但计入调用次数。`UNAVAILABLE` 与 `PENDING` 都不作零值。

区间汇总返回已知Token总和及完整／待计量／不可用／非Token调用数。四种计量状态互斥，计数之和等于调用次数。零条完整计量记录且存在待计量或不可用记录时Token卡显示 `—`；零调用或全部非Token记录时可显示0，并说明统计范围。

费用仅汇总 `SETTLED` 的权威净金额；`NOT_CHARGED` 是已知0。其余不按0计算。存在未确认项时显示“已确认消费”，并显示未确认调用数；无任何已确认项时显示 `—`。多币种分别列示，不换算或相加。首版不做退款流水查询；调整后的净值回补原调用，其历史变更由计费系统维护。

## 3. 权限及历史归属

权限码：`portal.usage.read`，本版主／子账户均可按其数据范围授予，查询历史的权限不从“能否发起模型调用”推断。

| 身份 | 范围 | 页面差异 |
|---|---|---|
| 主账户 | 当前主账户服务下，调用发生时归属该主账户的本人及子账户调用 | 可筛选调用账户，可查看AI应用服务消费 |
| 子账户 | 当前子账户在当前主账户业务域内自己的模型服务调用 | 不展示调用账户筛选，不返回其他账户、AI应用服务或订单 |
| 有多种身份的用户 | 一次只查询一个经过验证的身份 | 不用userId合并全部账户数据 |

主账户默认包含子账户为公共设计中的待确认规则，生产接入前需确认。子账户转移或脱离后，历史 `ownerAccountId` 不变；当前主账户不能查询其旧主账户域下的数据。原主账户可按既定历史权限看当时自己的调用，不扩展到转移后的记录。

费用权限独立于用量权限。`canReadCharge=false` 时统计金额区返回HIDDEN且data=null，列表／详情的charge返回null，金额排序和币种选项均不可用；后端不得将金额放入响应后只在前端隐藏。下文非空charge结构只适用于有费用权限的身份。额度扣减仍按自身调用可见性返回，不等于获取主账户余额。

业务密钥不只是“不能管理”，其内部ID、名称、掩码也不返回门户。AI应用调用的密钥栏固定显示“系统业务调用”，无法按业务Key筛选；可按服务查看。

身份非法／无模块权限返回403。已获模块权限但访问不可见callId返回404，与不存在一致。选项查询必须同样鉴权，禁止泄露其他账户名称。

## 4. 页面布局

### 4.1 通用布局与筛选

```text
用量中心                                            [刷新]
当前账户 · 查询范围说明 · 时间按北京时间统计
[用量统计] [调用明细]

时间范围 [近7天 ▾] [开始日期] [结束日期]
服务 [全部 ▾] 模型 [全部 ▾] 用户密钥 [全部 ▾]
调用账户 [全部/主账户本人/选择子账户]（仅主账户）
                                       [查询] [重置]
已应用条件：……   数据截至：……   [部分数据仍在更新提示]
```

日期必填；默认近7个自然日含今天。支持今天、昨天、近7天、近30天、自定义。单次最多90个自然日是本版限制，后端可通过能力接口收紧；不代表历史仅保留90天。不能选未来日期或超出后端可查询最早日期。

筛选采用“编辑草稿→查询后生效”，避免每选一个条件就刷新。日期快捷项也需要点查询。重置恢复近7天及全部维度，并立即查询。每个下拉首版单选，远程搜索，每批20条。

### 4.2 用量统计页

```text
[调用次数] [总Token] [输入Token] [输出Token] [已确认消费]

每日趋势                              [Token用量/调用次数/消费]
输入+输出堆叠柱 / 调用次数折线 / 单币种金额折线

缓存输入分析：命中量 / 未命中量 / 命中占比 / 拆分覆盖调用数

维度汇总           [模型/用户密钥/调用账户/服务] [排序指标 ▾]
对象 | 调用次数 | 输入Token | 输出Token | 总Token | 已确认消费 | 操作
……                                                                  查看调用
[上一页] 第N页 [下一页]                        每页 [20/50/100]
```

- 默认趋势为Token、默认汇总维度为模型、默认按总Token倒序；相同数值按维度ID稳定排序，未知数值置后。
- 趋势和卡片依据全量匹配记录，不依据当前20行计算。
- 首版按日粒度，显示所选区间所有日期。完整同步且无记录的日期补0；无法确认的日期是缺口或明确的部分值，不补成已知0。
- 缓存覆盖不足时提示原因。无缓存拆分能力时显示“当前数据源暂未提供缓存拆分”，不画全为0的图。
- 金额功能未接入时金额卡保留“暂未提供计费数据”，金额趋势与排序禁用并说明原因，不用Token代替金额。
- 多币种时卡片分币种显示，金额趋势及排序必须选择一种币种，禁止跨币种金额排名。
- 子账户没有“调用账户”汇总维度。
- 用户密钥维度中业务调用合并为“系统业务调用”特殊桶，不暴露内部业务密钥；未知用户密钥另设“未识别密钥”桶。
- 未解析模型用“未识别模型”，auto请求展示对外可知的最终平台模型；无法提供则保留auto并说明，不能推断提供商模型。

### 4.3 调用明细页

在公共筛选下仅增加“调用状态”，可选“成功”或“失败”，筛选需点击查询。首版不提供“已取消”“处理中”筛选选项，也不提供计量状态、计费状态和调用编号筛选。

未选择调用状态时仍查询全部可见记录。底层记录若存在处理中或已取消状态，应按真实状态展示，但用户不能单独筛选这两类记录；计量状态和计费状态继续用于决定Token与费用的展示方式，不作为页面筛选条件。

| 默认列 | 展示与交互 |
|---|---|
| 调用时间 | 北京时间，精确到秒，悬浮可看毫秒 |
| 平台模型 | 历史名称；未知显示请求的模型标识或“未识别模型” |
| 所属服务 | 历史名称 |
| 用户密钥 | 用户密钥历史名称及脱敏ID尾部；业务调用仅固定文案 |
| 调用账户 | 主账户显示实际调用账户历史名称；子账户省略 |
| 输入／输出／总Token | 完整计量时显示精确数量，否则按计量状态展示 |
| 缓存命中／未命中输入 | 未提供显示 `—`，不得把0与未知混淆 |
| 已确认消费 | 含币种；待计费、不计费、不可用分别显示 |
| 调用状态 | 文字与颜色共同表示 |
| 操作 | 查看详情 |

表格自身可横向滚动，操作列固定；整页不溢出。首版不显示总页数和随机跳页。默认按 `startedAt DESC, callId DESC` 排序，不开放其他明细排序，支持20／50／100条及前后游标翻页。

调用次数卡在统计页，明细页不额外显示一个易与筛选不一致的“总调用次数”。明细页以实际查询条件和当前页数量说明范围。

### 4.4 调用详情抽屉

建议宽度800px，窄屏全宽，路由使用 `/usage?tab=details&callId=...`。

1. **基本信息**：调用编号（可复制）、调用时间、完成时间、调用状态、所属服务、实际调用账户（按权限）、用户密钥信息（按类型裁剪）。
2. **模型与计量**：请求model、最终平台模型、输入／输出／总Token、缓存命中／未命中／写入、计量状态、计量更新时间。
3. **消费与额度**：计费状态、已确认用户金额及币种、最终额度扣减量及单位、计费更新时间。分别显示，不表示金额必然等于额度换算。
4. **调用结果**：用户可读结果摘要、公开错误码、总耗时、首Token耗时（有数据才展示）。不显示内部堆栈、渠道信息、提示词、输出文本。

预扣、释放流水不作为多笔消费列在抽屉中。本期不展示包级扣减拆分，避免对子账户泄露主账户额度包信息。

关闭抽屉保留筛选、游标页和滚动位置。直达详情先按callId鉴权查询，不能被默认近7天条件挡住更早的合法调用；列表仍按默认日期展示，详情显示自己的实际时间并提示可能不在当前列表范围。

## 5. 交互规则

### 5.1 筛选联动

- 改服务后清空原用户密钥选择。模型和调用账户保留，但选项由当前授权和历史数据决定。
- 改调用账户后清空用户密钥；用户密钥选项仅返回该调用账户的用户密钥。
- 改日期不静默删除历史对象ID；后端可返回“已删除／已停用”的历史名称选项。
- 选择互相不匹配但均有权查看的组合可正常返回空，不改成全部。
- 未知／无权限选项不能退化为“全部”扩大查询，应提示条件无效，待用户修正。
- 所有选项包含稳定ID和快照名称，不靠名称关联。重名显示ID尾部。

### 5.2 标签切换与钻取

- 两标签共享已应用的时间、服务、模型、用户密钥和调用账户条件。
- 明细页的调用状态条件只作用明细，切回统计时不带入；明确提示“统计按公共筛选条件展示”。
- 编辑未提交筛选时切标签，丢弃草稿并恢复已应用条件，防止输入框与数据不一致。
- 维度汇总“查看调用”设置相应筛选，进入明细并清空调用状态条件。已有相同维度条件被替换，其余公共条件保留。
- 特殊桶钻取分别用 `keyCategory=BUSINESS`、`keyCategory=UNKNOWN` 或 `modelCategory=UNKNOWN`，不把固定文案当成ID。
- 特殊桶参数和普通ID互斥；界面显示可删除的筛选标签。
- 从概览／服务／密钥页进入时接收 `startDate,endDate,serviceId,userKeyId,platformModelId,actorAccountId`，没有传入的条件用默认值。服务归属由后端再次验证。

### 5.3 查询状态与URL

URL保存标签、已应用筛选、统计维度和详情callId；不存用户秘密、业务密钥或原始请求。游标／快照令牌不写URL，放页面内存。

点击查询、重置、刷新、改变页大小或统计排序，重置该结果集游标。刷新重新取得快照，关闭已失效详情状态；若抽屉开启则重新读取同callId，明确显示最新结果。

快速重复查询／切换身份时取消旧请求，并使用身份与查询序号双重检查丢弃晚到响应。切换身份清空全部筛选、详情、历史游标、快照和旧结果，默认回统计页近7天。

### 5.4 空态与异常

| 情况 | 行为 |
|---|---|
| 首次加载 | 筛选可见，内容骨架屏 |
| 查询成功无记录 | “所选条件下暂无调用记录”，已知指标0 |
| 计量部分完成 | 展示已计量值及覆盖计数，标记“仍在更新” |
| 缺失计费能力 | Token正常展示，费用不可用，不全页报错 |
| 一个统计区域失败 | 本区重试，其他区保留，不能用0冒充成功 |
| 切条件请求失败 | 不把旧条件数据标为新条件；显示新查询失败，旧数据如保留必须标明其旧条件 |
| 列表失败 | 错误态及重试，不显示“暂无记录” |
| 翻页快照失效 | “数据查询已过期，请刷新后继续”，回首屏重新查询，不拼接两快照 |
| 无权限／登录过期 | 按公共设计清除业务数据并处理 |
| 下游数据延迟 | 显示数据截至时间；接收时间不能冒充源数据更新时间 |

不自动后台轮询。统计限制参数和超时均可配置；建议普通查询服务端超时5秒，客户端10秒。性能目标待按实际数据规模压测确定，不把建议当成网关SLA。

## 第二部分：接口、数据字典与存储

## 6. 后端职责与数据接入策略

### 6.1 默认方案：查询适配

优先复用大网关／用量服务的查询接口。门户负责鉴权、历史归属、标准化、字段裁剪、聚合编排和结果格式；不在每次请求时拉取海量原始日志临时全量统计。

网关若已提供稳定调用明细、维度统计、缓存分类和最终计费数据，本模块不新增用量业务表。网关若仅提供事件日志，需明确由用量服务或门户的数据接入任务建设读模型，不能由前端统计替代。

建议适配接口：`UsageQueryProvider`、`UsageDimensionProvider`、`UsageChargeProvider`、`UsageSnapshotProvider`。费用可选，但原方案要求的Token与缓存能力缺失时必须标为未完成接入，不能以降级页面宣称需求全量验收。

### 6.2 查询快照与回补

仅按 `startedAt <= queryTime` 不能防止迟到日志和计量校正造成翻页／汇总漂移。

本版要求查询会话返回 `snapshotToken`，绑定当前身份、权限版本、查询条件和数据版本，建议有效期10分钟。Token应为不可猜测的不透明值；每次使用仍重新鉴权。

- 同次统计的卡片、趋势、汇总使用同一快照。钻取会改变筛选，须用原快照派生一个新查询会话，继承同一数据版本水位并重新鉴权；不能把绑定原筛选的token直接配上新筛选。
- 新调用和回补数据在刷新取得新快照后出现；旧快照期间结果不漂移。
- 若数据源不能提供真实版本快照，可由后端物化小型统计结果和可分页记录版本，或采用第10章的版本化读模型。
- 禁止把普通查询时间命名为snapshot后声称结果冻结。
- 无法提供快照的实现需先明确降级为“实时结果可能变化”的另一个契约，不能未经说明通过本版稳定分页和核对验收。

统计时间和快照时间不同：`dataAsOf` 是源数据完整处理水位，`snapshotCreatedAt` 是查询会话创建时间。

## 7. API设计

### 7.1 基础约定

前缀 `/api/portal/v1`，遵循公共身份认证；JSON camelCase 为门户DTO，现有 snake_case 模型通过适配层转换。ID与数量均为字符串，计数非负整数字符串，金额／额度为十进制字符串。耗时为带 `Ms` 后缀的安全非负整数或null。

金额精度建议内部保留8位，展示最多8位有效小数并保留精确提示，不逐行四舍五入后累加。数据库建议类型为 `DECIMAL(38,8)`；超过精度应拒绝并告警，不静默截断。输出时金额包含币种、额度包含单位。

本模块固定北京时间，与公共设计一致。日期查询边界为左闭右开；未来数据不计入。首版不更改既有工作台时区逻辑，两套草案需在正式实现时统一。

### 7.2 接口清单

| 方法与路径 | 用途 | 关键参数 |
|---|---|---|
| GET `/usage/capabilities` | 权限与数据能力 | 无 |
| GET `/usage/options` | 历史维度选项 | dimension、keyword、cursor、serviceId、actorAccountId、startDate、endDate |
| POST `/usage/query-sessions` | 创建或派生只读查询快照 | filter公共条件、可选baseSnapshotToken |
| GET `/usage/statistics` | 指标、趋势、缓存摘要 | snapshotToken |
| GET `/usage/breakdowns` | 维度汇总 | snapshotToken、groupBy、sortBy、currency、cursor、pageSize |
| GET `/usage/calls` | 调用列表 | snapshotToken、附加筛选、cursor、pageSize |
| GET `/usage/calls/:callId` | 调用详情 | snapshotToken可选；有则查该快照版本，否则查最新 |

创建查询会话是技术资源写入，不修改业务账本，不在用户操作审计产生“调用消费”事件。接口级访问日志按平台规范处理。

### 7.3 请求与分页

创建查询会话请求为 `{ filter: UsageFilter, baseSnapshotToken?: string }`。普通查询／刷新省略baseSnapshotToken取得新水位；维度钻取传原token，以相同水位建立新筛选会话。派生会话不得延长原快照寿命，且只能在当前权限范围内查询。原token过期则返回410，由用户刷新，不静默切为新水位。

```ts
interface UsageFilter {
  startDate: string; // YYYY-MM-DD
  endDate: string;
  serviceId?: string;
  platformModelId?: string;
  modelCategory?: 'UNKNOWN'; // 与platformModelId互斥
  userKeyId?: string;
  keyCategory?: 'BUSINESS' | 'UNKNOWN'; // 与userKeyId互斥
  actorAccountId?: string; // 主账户可用，范围服务端校验
}
interface CallExtraFilter {
  callStatus?: 'SUCCESS' | 'FAILED';
}
interface CursorPage<T> {
  items: T[];
  nextCursor: string | null;
  hasMore: boolean;
  pageSize: 20 | 50 | 100;
}
interface Envelope<T> {
  requestId: string; // 门户接口请求编号
  accountContextId: string;
  dataAsOf: string | null;
  data: T;
}
```

上一页由前端维护已访问游标栈。游标绑定快照、排序、附加筛选和页大小；变更任何一项后不能复用，错误返回400。可用分页事实键为调用时间和调用ID；汇总分页为指标值与分组ID。不能仅用时间作游标，避免同毫秒记录丢失。

选项接口 `dimension=SERVICE|MODEL|USER_KEY|ACTOR`，每批20条，返回ID、label、historical、已脱敏辅助标签及nextCursor。业务密钥不属于USER_KEY选项。未知桶由固定选项表示。子账户请求ACTOR或BUSINESS返回403。

### 7.4 能力响应

```ts
interface UsageCapabilities {
  canRead: boolean;
  canFilterActors: boolean;
  canReadCharge: boolean;
  cacheBreakdownSupported: boolean;
  quotaDeductionSupported: boolean;
  snapshotSupported: boolean;
  earliestQueryableDate: string | null;
  maxRangeDays: number; // 本版上限90，可由真实下游收紧
  timezone: 'Asia/Shanghai';
  supportedCurrencies: string[];
  unavailableReasons: Record<string, string>;
}
```

费用权限允许但数据源暂未接入时，canReadCharge仍代表授权，金额能力缺口通过unavailableReasons说明；权限不足用HIDDEN，源能力缺失用不可用状态，两者不能混为一谈。

`earliestQueryableDate=null` 表示未知，不能暗示无限留存；后端仍校验下游实际范围。capability只控制展示，不能替代各接口实时鉴权。

## 8. 数据字典与校验

| 字段 | 类型／空值 | 业务含义与规则 |
|---|---|---|
| ownerAccountId | string，内部必填 | 调用时服务所属主账户，作为历史权限隔离键，不接受前端赋值 |
| actorAccountId | string，内部必填 | 实际调用账户，不是登录用户ID |
| userKeyId | string/null | 仅用户密钥，业务密钥不能写入门户公开投影 |
| serviceId | string，必填 | 服务实例，不是产品目录ID |
| platformModelId | string/null | 平台模型，未知／未完成解析时为空 |
| callId | string，必填 | 全局唯一调用键；若来源ID仅源内唯一，接入层生成规范全局ID |
| recordVersion | string，必填 | 单调用公开读模型版本，不是重试次数 |
| startedAt | ISO时间，必填 | 统计归属时间 |
| inputTokens/outputTokens/totalTokens | 整数字符串/null | 仅COMPLETE完整入统计，字段应满足加法关系 |
| cacheReadInputTokens | 整数字符串/null | 缓存命中的输入部分 |
| cacheMissInputTokens | 整数字符串/null | 未命中部分，COMPLETE拆分时与命中合为输入 |
| cacheWriteInputTokens | 整数字符串/null | 可准确映射时为未命中子集；否则null |
| amount/currency | 十进制字符串/币种 | SETTLED必须同时提供；NOT_CHARGED为0，币种可不适用；未确认不得伪填0 |
| quotaDeductions | 数组/null | FINAL返回最终扣减，UNAVAILABLE返回null；空数组只表示明确无扣减／不适用 |
| durationMs/ttftMs | 非负整数/null | 首Token未产生或不适用时null，不能用0冒充 |
| name快照 | string | 调用发生时或首次归集时的可用历史名称，缺失显示ID；不因改名删记录 |

整数量级超过JavaScript安全整数时仍精确显示。计算和金额求和用十进制／大整数工具；图表可以用近似坐标，tooltip必须保留原始值。

异常数据校验：Token负数、总量不等于输入输出和、缓存拆分超过输入、已确认消费缺币种、结束时间早于开始时间等，均隔离该异常字段／事件并告警，不自动改为0掩盖问题。其他可用记录仍可查询并显示部分数据提示。

## 9. 表结构设计与实施选择

### 9.1 先确定是否建表

| 方案 | 使用条件 | 门户需要新增什么 |
|---|---|---|
| A 查询适配（默认） | 下游已支持本需求查询、聚合、快照、权限归属字段 | 不新增用量业务表；查询会话可放短期缓存 |
| B 本地版本化读模型（备选） | 下游提供可靠事件／增量快照，但不能直接查询 | 下述公开调用版本表、单位扣减表、接入水位；不新建扣费账本 |

必须选定一种权威查询路径，不能部分指标读门户副本、部分读网关实时值却声称同一快照。费用来自独立系统时，先形成同版本投影或注明无法做到同快照并调整验收。

既有 `call_logs` 和 `usage_ledger` 可作为源。`usage_ledger` 中 pre_deduction、correction、release 的数值语义未明确前，不写“SUM所有流水=用量”的SQL。源模型需要补充历史owner、唯一事件、版本和最终结果标识；不能仅用 `request_id` 作为多条流水的唯一主键。

### 9.2 可选DDL：公开调用版本表

以下MySQL兼容DDL为方案B设计，不要求方案A建表。数值以DECIMAL保存，通过驱动映射为字符串。数据库时间为UTC，UTC_TIMESTAMP(3)由接入任务写入。

不建跨系统外键；版本表与扣减子表在同一投影事务中维护。`source_versions_json` 仅存各权威数据源的版本号／事件定位，不存密钥、原始响应或请求内容，不返回门户。`result_message` 必须经过白名单脱敏。

逻辑约束由接入服务校验，数据库能力允许时补CHECK：各数量非负；COMPLETE Token三项非空且满足加法；BUSINESS时user_key字段必须null；有效版本区间不重叠；同一callId最多一个valid_to_seq为null的版本。

按模型查询是否增加 `(owner_account_id,platform_model_id,started_at,call_id)` 索引由查询计划确认，不默认给每个字段加索引。大规模统计应由分析引擎／独立读模型支持，不能承诺此MySQL表覆盖任意海量报表。

### 9.3 版本、水位与幂等

- 使用可信数据源单调用单调版本，重复版本忽略，旧版本不得覆盖新版本。若源只给增量事件，需先按唯一eventId幂等归并成最终状态，不能直接使用此快照覆盖流程。
- 计量与计费来自多个源时，分别维护版本，再合成一条完整公开投影；计费更新不能擦除已有Token。
- 有序提交器为可见投影事务分配严格提交序号：同一事务关闭旧版本有效区间、插入新版本、写扣减项和接入水位。
- 快照只捕获已完整提交的连续水位；禁止用普通自增号最大值代替已提交水位，因为并发事务可能有空洞和晚提交。
- 查询版本条件：`valid_from_seq <= W AND (valid_to_seq IS NULL OR valid_to_seq > W)`，同callId只得到一个版本。
- 新快照可看到回补，旧快照仍看到原版本。聚合不能把同callId所有revision求和。
- 接入时缺少可信历史owner，不用当前父子关系回填猜测；进入待补充队列，并报告数据覆盖缺口。

查询会话存储：opaqueToken、已验证身份、权限版本、标准化filter、snapshotW、dataAsOf、创建和失效时间；10分钟TTL。权限变化立即废弃。无需持久化用户首页偏好表。

### 9.4 留存和清理

保留天数由产品与平台容量共同确定，不在本稿写成既定业务期限。查询范围90天与数据留存期不同。旧版本至少覆盖仍有效的查询快照；清理任务不能删除有效快照需要的版本。达到正式留存边界时可查范围由capabilities反映，过期详情返回404，不能继续暴露缓存副本。

## 10. 查询与一致性实现要点

1. 先验证身份、模块权限和所有筛选对象，再建立查询快照。
2. 主账户用历史owner过滤；子账户额外加当前actor及可见服务类型约束。不能只按当前服务表JOIN授权历史。
3. 选取快照内每callId唯一版本后，再计算调用次数、Token、费用和维度分组。
4. Token汇总仅计量COMPLETE；缓存汇总仅缓存拆分COMPLETE；两个覆盖集合不同，不混用分母。
5. 所有趋势按startedAt转换北京时间日期归组，费用校正回原调用日期。
6. 用户密钥汇总把BUSINESS合并成固定桶，明细同样裁剪，不能从groupId恢复内部业务Key。
7. 同一调用的最终额度可能来自多个包，投影按单位归并一次，不能把主账本与子配额扣减重复累计。
8. 分页和详情每次重新鉴权；snapshot、cursor和callId均不能作为授权凭证。
9. 若模型名称、服务名称改动，历史快照保持；历史已删除对象仍可筛选。
10. 原始usage适配错误可观察、可重放修正，但用户接口仅显示安全摘要。

## 11. 与现有文档的差异处理

| 现有内容 | 本模块处理 | 原因／状态 |
|---|---|---|
| 公共设计按上海时区；工作台草案按用户时区 | 本模块沿用公共设计上海时区 | 避免跨页面日期不一致；正式统一待评审，不修改现有实现 |

## 13. 开发拆分与代码生成要求

前端建议组件：`UsagePage`、`UsageFilterBar`、`UsageMetricCards`、`UsageTrendChart`、`CacheUsageSummary`、`UsageBreakdownTable`、`UsageCallTable`、`UsageCallDetailDrawer`。复用现有UI库、请求封装、路由和权限，不另建一套门户框架。

后端建议职责：身份范围解析、查询会话、能力／维度选项、统计查询、明细查询、计费适配；方案B另有独立异步投影任务，不塞进页面请求线程。

交给代码生成模型的要求：

1. 只实现本模块，遵循本文和公共设计，待确认业务规则不得变成隐藏硬编码。
2. 先定义DTO与Provider，再实现页面和服务；优先方案A，无真实网关契约时开发Mock明确标注来源。
3. 方案B仅在确定由门户承担投影时建表，不直接修改既有财务／网关账本。
4. Token、额度和金额分别建模，三种状态独立，不返回业务Key数据。
5. 实现真正可验证的快照；若下游不支持，标为未完成能力，不能用queryTime冒充。
6. 所有查询、筛选、分页、权限和状态依照验收矩阵实现，至少覆盖U04～U15、U19～U25的契约和一致性验证。
7. Mock配置仅开发环境启用，生产数据失败不得自动回退到Mock。金额、缓存和快照未接入须在交付说明列出。
8. 首版无导出、支付、修改调用、重放请求、查看提示词等入口。
9. 交付包含接口清单、依赖数据源清单、Mock/真实接入状态、必要测试结果和未决项，不仅是静态截图。
