# TokenHub 用户门户需求与技术设计：11 我的工单

版本：V0.1，开发评审稿  
适用范围：产品评审、用户门户前后端、工单服务、运营受理端、接口联调与验收  
依据：《TokenHub平台设计方案.docx》及《用户门户公共设计》  
页面路由：`/help/tickets`、`/help/tickets/new`、`/help/tickets/:ticketId`  
相关模块：告警中心、用量中心、接入文档、我的服务、API 密钥、模型目录

## 第一部分：业务需求与页面交互

## 1. 文档范围

平台设计方案明确要求用户门户支持问题反馈工单的提交与跟踪。本模块负责用户侧的工单列表、工单提交、处理进度查看、公开沟通、补充材料、解决确认和未读回复提示。

运营人员的工单池、分派、内部协作、内部备注、SLA 管理、统计报表和知识库沉淀不属于用户门户页面范围。本文仍定义双方共用的状态、消息和数据模型，保证用户侧能够与后续运营受理端形成闭环。

本文引用[《用户门户公共设计》](用户门户公共设计.md)中的登录身份、接口格式、身份切换、错误处理、时间格式和数据隔离规则，不重复定义冲突版本。

规则标记：

- **方案已有**：原平台设计方案明确描述。
- **本版设计**：为形成完整页面和开发契约补充的规则。
- **待业务确认**：原方案未明确；允许按本文暂定规则进行原型和 Mock 开发，生产发布前确认。

## 2. 建设目标与边界

### 2.1 建设目标

用户应能完成以下任务：

1. 提交调用、密钥、额度、服务、模型或账户相关问题。
2. 从告警、调用明细、接入文档等页面带入必要的排查标识。
3. 查看工单当前状态、处理进展及平台公开回复。
4. 在平台要求补充材料时继续回复并上传附件。
5. 对已解决工单确认关闭，或在关闭前说明问题仍未解决。
6. 在不提交 API Key、敏感 Prompt 和内部渠道信息的前提下提供足够排障信息。

### 2.2 首版范围

- 我的工单列表、筛选、搜索、分页和未读标识。
- 新建工单和来源上下文预填。
- 工单详情、公开消息时间线和状态轨迹。
- 用户补充回复与附件上传。
- 用户确认解决，以及已解决状态下申请继续处理。
- 工单消息已读记录。
- 服务、模型、用户密钥、调用、告警、文档等结构化关联。
- 数据表、用户侧接口及运营受理端需要遵循的最小状态契约。

### 2.3 首版不做

- 在线客服、即时聊天、音视频或屏幕共享。
- 用户编辑或删除已经提交的正文、回复和附件。
- 用户自行指定处理人员、内部优先级或承诺处理时限。
- 在用户门户展示受理人员真实联系方式、内部备注、内部标签或内部流转记录。
- 邮件、短信、电话通知；首版只定义站内未读状态，外部通知另行评审。
- 工单评价、满意度问卷、知识库自动推荐和 AI 自动答复。
- 从工单页面读取或展示 API Key 原文、完整 Prompt、完整响应正文、供应商凭证或路由信息。
- CRM 订单变更、退款、充值、停复机等实际办理操作。

### 2.4 与其他模块的边界

| 模块 | 工单可接收的关联信息 | 边界 |
|---|---|---|
| 告警中心 | `alertId`、告警编号、告警类型和发生时间 | 工单服务按权限重新读取告警，不信任 URL 中的标题和描述 |
| 用量中心 | `requestId`、调用时间、公开模型、接口路径、平台错误码 | 不复制 Prompt、响应正文、API Key 或供应商数据 |
| 接入文档 | `articleKey`、文档版本、章节锚点、错误码 | 工单保留稳定文章标识，不复制整篇正文 |
| 我的服务 | `serviceId`、服务名称和服务类型 | 只关联当前身份可见服务，不办理订购或退订 |
| API 密钥 | `apiKeyId`、用户自定义名称、脱敏尾号 | 只允许关联用户密钥；不保存或传输密钥原文 |
| 模型目录 | `platformModelId`、公开模型名称和 `modelCode` | 不关联供应商模型或渠道端点 |
| 操作审计 | 工单提交、回复、确认解决等关键操作 | 审计内容不保存工单敏感正文 |
| 运营受理端 | 状态、分派、公开回复和解决说明 | 内部备注与内部附件永不返回用户侧 |

## 3. 用户、权限与数据范围

### 3.1 权限码

建议权限码：

| 权限码 | 含义 |
|---|---|
| `portal.ticket.read` | 查看当前身份下的工单列表和详情 |
| `portal.ticket.create` | 当前身份提交新工单 |
| `portal.ticket.reply` | 对当前身份下允许回复的工单补充消息 |
| `portal.ticket.resolve` | 确认已解决或申请继续处理 |
| `portal.ticket.attachment` | 上传和下载当前身份有权访问的工单附件 |

前端按权限控制入口，后端对每次请求重新鉴权。隐藏按钮不能替代后端权限校验。

### 3.2 主账户与子账户

本版暂定主账户和子账户都可以使用工单，数据按 `accountContextId` 隔离：

- 当前身份只能查看和操作在该身份下创建的工单。
- 主账户默认看不到子账户身份提交的工单；子账户也看不到主账户及其他子账户工单。
- 同一登录用户切换身份后，列表、详情、未读数、来源上下文和上传中的附件全部按新身份重新处理。
- 工单保存创建时的 `creatorUserId` 用于审计，但用户侧可见范围以 `accountContextId` 为准。
- 是否允许主账户管理员查看全部子账户工单属于待确认项；未确认前不得扩大数据范围。

### 3.3 字段裁剪

用户侧接口不得返回：

- 受理人账号、手机号、邮箱等个人信息。
- 内部分派组、内部优先级、内部标签和内部备注。
- 内部消息、内部附件、风控研判和供应商沟通记录。
- 供应商名称、端点、成本、路由结果或内部完整链路标识。
- 其他账户身份的信息。

用户侧可将处理方统一显示为“平台支持”。如需展示处理团队，应返回用户可见名称，例如“技术支持组”，不得直接暴露内部组织标识。

### 3.4 身份切换

1. 切换开始后立即清空列表、详情、表单上下文和临时附件视图。
2. 尚未提交的表单默认不跨身份保留，也不自动保存到浏览器本地存储。
3. 如果表单已有输入，切换前由公共框架触发离开确认；用户确认后放弃当前输入。
4. 新身份验证成功后进入 `/help/tickets` 并重新查询第一页。
5. 旧身份迟到响应不得渲染；附件上传完成回调也必须校验上传会话所属身份。

## 5. 工单列表页

### 5.1 页面布局

```text
┌────────────────────────────────────────────────────────────┐
│ 我的工单                                      [提交工单]    │
│ 提交问题并跟踪平台处理进度                                  │
├────────────────────────────────────────────────────────────┤
│ [全部状态▼] [全部类型▼] [提交时间▼]                        │
│ [工单编号或标题____________________] [查询] [重置]          │
├────────────────────────────────────────────────────────────┤
│ 工单编号       标题/类型       状态       更新时间      操作 │
│ TH202609...    模型调用失败     待补充     09-29       查看 │
│                [2条未读回复]                                │
│ TH202609...    额度显示问题     处理中     09-28       查看 │
├────────────────────────────────────────────────────────────┤
│                                               分页器         │
└────────────────────────────────────────────────────────────┘
```

宽度不足 768px 时使用卡片列表，每张卡片展示编号、标题、类型、状态、最近更新时间和未读数。桌面端使用表格。页面不得产生整页横向滚动。

### 5.2 筛选条件

| 条件 | 控件 | 默认值 | 规则 |
|---|---|---|---|
| 工单状态 | 单选下拉 | 全部进行中 | 全部进行中、待受理、处理中、待我补充、已解决、已关闭 |
| 问题类型 | 单选下拉 | 全部 | 使用服务端返回的可用分类 |
| 提交时间 | 日期范围 | 空 | 最长 180 天，按上海时区自然日查询 |
| 关键字 | 输入框 | 空 | 精确匹配工单编号或模糊匹配标题，最长 100 字符 |

“全部进行中”包含 `PENDING`、`IN_PROGRESS`、`WAITING_USER`；不包含 `RESOLVED` 和 `CLOSED`。查询参数写入 URL，例如：

```text
/help/tickets?status=OPEN&type=CALL_FAILURE&keyword=TH202609&page=1&pageSize=20
```

查询后刷新页面或从详情返回时恢复筛选与页码。身份切换后恢复默认条件并回到第一页。

### 5.3 列表字段

| 字段 | 展示规则 |
|---|---|
| 工单编号 | 展示可复制的公开编号 `ticketNo`，不展示数据库 ID |
| 标题／类型 | 标题最多两行；展示问题类型标签 |
| 关联对象 | 有关联服务或模型时展示公开名称，最多一项摘要 |
| 状态 | 使用第 8 章状态文案和颜色 |
| 未读回复 | `unreadMessageCount > 0` 时显示，不用红点代替具体可访问文本 |
| 提交时间 | 上海时区，精确到分钟 |
| 最近更新时间 | 公开消息或公开状态变化的最近时间；内部操作不改变用户侧更新时间 |
| 操作 | “查看”；需要用户补充时可显示“去回复” |

服务端排序：`userVisibleUpdatedAt DESC, id DESC`，保证分页稳定。运营内部备注、内部分派不应让工单无故跳到用户列表顶部。

### 5.4 列表交互与状态

1. 点击行、标题或“查看”进入详情。
2. 点击“去回复”进入详情并定位回复区，不直接打开无上下文弹窗。
3. 点击“提交工单”进入新建页；无创建权限时按钮不展示。
4. 修改筛选条件后点击查询，页码回到 1；点击重置立即恢复默认查询。
5. 页大小支持 10、20、50，默认 20。
6. 请求期间保留筛选区，列表显示加载状态；只有最后一次查询结果生效。
7. 查询成功无数据时显示“暂无符合条件的工单”；首次没有任何工单时同时提供“提交工单”和“查看接入文档”入口。
8. 查询失败显示错误状态和重新加载，不得显示为空列表。

## 6. 新建工单

### 6.1 页面布局

```text
┌────────────────────────────────────────────────────────────┐
│ ← 返回我的工单                                             │
│ 提交工单                                                    │
├────────────────────────────────────────────────────────────┤
│ 问题类型*        [请选择___________________________▼]       │
│ 标题*            [________________________________]         │
│ 问题描述*        [多行文本，描述现象、时间和复现方式]       │
│ 发生时间         [日期时间]                                 │
│ 影响范围*        [仅本人 / 当前应用 / 多个使用方]           │
│ 关联服务         [可选____________________________▼]       │
│ 关联模型         [可选____________________________▼]       │
│ 关联用户密钥     [可选，仅名称和尾号______________▼]       │
│ 请求标识         [requestId，可选__________________]        │
│ 平台错误码       [可选____________________________]        │
│ 附件             [上传附件]                                │
│ 安全提示：请勿提交 API Key、敏感 Prompt 或个人敏感信息      │
│                                      [取消] [提交工单]       │
└────────────────────────────────────────────────────────────┘
```

### 6.2 表单字段

| 字段 | 必填 | 长度／格式 | 规则 |
|---|---:|---|---|
| 问题类型 `categoryCode` | 是 | 枚举 | 由服务端元数据返回，不能在前端写死全部业务分类 |
| 标题 `title` | 是 | 5～100 字符 | 去除首尾空格；不允许仅标点或空白 |
| 问题描述 `description` | 是 | 20～5000 字符 | 纯文本或受控换行；首版不接受 HTML／Markdown |
| 发生时间 `occurredAt` | 否 | ISO 8601 | 不能晚于当前时间 5 分钟以上；未选择不猜测 |
| 影响范围 `impactScope` | 是 | 枚举 | `SELF`、`APPLICATION`、`MULTIPLE_USERS`、`UNKNOWN` |
| 关联服务 `serviceId` | 否 | 字符串 ID | 只能选择当前身份可见服务 |
| 关联模型 `platformModelId` | 否 | 字符串 ID | 只能选择当前身份可见平台模型 |
| 关联用户密钥 `apiKeyId` | 否 | 字符串 ID | 只显示用户密钥名称和脱敏尾号，不提供业务密钥和原文 |
| 请求标识 `requestId` | 否 | 1～128 字符 | 平台公开排查标识；后端验证格式和可见性 |
| 平台错误码 `errorCode` | 否 | 1～64 字符 | 使用网关公开错误码，不能提交内部堆栈 |
| 附件 `attachmentIds` | 否 | 最多 5 个 | 仅引用当前上传会话中已可用的临时附件 |
| 来源引用 | 否 | 结构化对象 | 来自告警、用量、文档等；用户不可直接修改内部引用 ID |

“联系方式”不作为首版表单字段。平台通过站内回复沟通；用户基本资料中的手机号或邮箱不得未经明确用途和授权自动附加到工单。

### 6.3 问题类型

首版建议分类：

| 分类代码 | 用户文案 | 常见内容 |
|---|---|---|
| `CALL_FAILURE` | 调用失败或响应异常 | 401、403、429、5xx、超时、流式中断 |
| `API_KEY` | API 密钥问题 | 创建、暂停、恢复、鉴权失败，不提交密钥原文 |
| `USAGE_QUOTA` | 用量或额度问题 | 用量明细、额度余量、扣减疑问 |
| `SERVICE_ORDER` | 服务或订购问题 | 服务状态、套餐、急救包；实际办理仍由 CRM 负责 |
| `MODEL_CAPABILITY` | 模型与能力问题 | 模型不可见、能力说明、协议兼容 |
| `ACCOUNT_SUBACCOUNT` | 账户或子账户问题 | 身份、权限、配额分配 |
| `DOCUMENTATION` | 文档问题 | 文档错误、示例不可用、缺少说明 |
| `OTHER` | 其他问题 | 无法归入以上类型 |

分类是可配置字典，需支持启停和排序。历史工单保留提交时的分类代码和名称快照；分类停用后不可新选，但历史详情仍可展示。

### 6.4 来源上下文预填

允许以下入口：

```text
/help/tickets/new?sourceType=ALERT&sourceId={alertId}
/help/tickets/new?sourceType=CALL&sourceId={requestId}
/help/tickets/new?sourceType=DOC&sourceId={articleKey}&anchor={sectionAnchor}
/help/tickets/new?sourceType=SERVICE&sourceId={serviceId}
```

处理规则：

1. 新建页将 `sourceType`、`sourceId` 交给后端预填接口。
2. 后端校验当前身份是否有权访问来源对象，并返回允许展示的最小信息。
3. 前端不得直接把 URL 参数当成可信工单字段。
4. 来源无效、已删除或无权访问时忽略预填并显示“未能读取关联信息，您仍可手动提交工单”，不得泄露对象是否属于其他账户。
5. 用户可以移除来源关联，但不能修改后端解析出的来源 ID。
6. 预填标题和描述只是建议，用户可编辑；结构化引用单独保存，不从文本反向解析。

调用来源可预填请求标识、发生时间、公开模型、接口路径和平台错误码；不得预填请求头、API Key、Prompt、完整请求／响应体或供应商信息。

### 6.5 表单交互

1. 进入页面先加载分类、可关联对象和来源预填信息；各下拉支持远程搜索。
2. 选择服务后，模型和用户密钥选项可以按服务过滤；清除服务时不自动删除仍合法的关联项。
3. 填写 `requestId` 后可点击“校验关联”，后端只返回最小公开摘要；查不到时仍允许提交，但标记 `referenceValidation=UNVERIFIED`。
4. 页面离开且存在修改时提示“当前内容尚未提交，离开后将丢失”。首版不在 localStorage 保存草稿。
5. 提交期间禁用表单和重复点击，使用 `Idempotency-Key` 防止重复工单。
6. 提交成功后使用 replace 跳转详情页，并显示工单编号。
7. 业务校验失败保留表单内容并定位首个错误；附件失效时只提示重新上传，不清空其他字段。
8. 用户点击取消返回列表；有改动时二次确认。

### 6.6 提交前安全检查

页面固定提示：

> 请勿提交完整 API Key、访问令牌、密码、供应商凭证、敏感 Prompt、完整业务数据或无关个人信息。排查调用问题通常只需要发生时间、公开 requestId、接口路径和平台错误码。

前后端都进行基础敏感信息检测。发现疑似完整平台 API Key、Bearer Token、私钥块或常见云凭证时：

- 默认阻止提交，并指出需要删除的字段或附件。
- 不在错误提示中回显完整敏感值。
- 检测规则误判时的人工例外流程属于待确认项；首版不提供“一键忽略继续提交”。
- 服务端日志不得记录被拦截的原文。

敏感检测是降低误提交风险的补充措施，不能替代存储加密、访问控制和审计。

## 7. 工单详情

### 7.1 页面布局

```text
┌────────────────────────────────────────────────────────────┐
│ ← 返回我的工单                                             │
│ TH202609290001  模型调用持续返回限流              [待我补充] │
│ 类型 · 提交时间 · 最近更新                                  │
├────────────────────────────────────────────────────────────┤
│ 状态进度：已提交 ─ 已受理 ─ 待我补充 ─ 已解决               │
├───────────────────────────────┬────────────────────────────┤
│ 公开沟通记录                  │ 工单信息                    │
│ 用户：问题描述                │ 发生时间 / 影响范围         │
│ 平台支持：请补充 requestId     │ 关联服务 / 模型 / 密钥尾号  │
│ 用户：补充信息与附件           │ 错误码 / requestId          │
│                               │ 来源页面                    │
├───────────────────────────────┴────────────────────────────┤
│ [回复输入框] [上传附件]                         [发送回复] │
│ 已解决时：[问题仍未解决] [确认解决并关闭]                    │
└────────────────────────────────────────────────────────────┘
```

小屏幕下工单信息区移动到沟通记录上方，页面单列展示。

### 7.2 工单摘要

展示工单编号、标题、问题类型、当前状态、提交时间、用户侧最近更新时间、发生时间、影响范围、关联服务、平台模型、用户密钥脱敏信息、请求标识、平台错误码和来源入口。

关联对象已经删除或当前不可用时显示提交时快照，并标注“关联对象当前不可用”；不能因为关联对象删除而无法查看历史工单。

`requestId` 可以复制。API 密钥只展示用户自定义名称和尾号，例如“生产环境 Key（****7K2P）”，不得提供查看原文入口。

### 7.3 沟通时间线

时间线只展示：

- 用户最初提交的问题描述。
- 用户后续补充消息。
- 平台支持发送给用户的公开回复。
- 用户可见的状态事件，例如“平台开始处理”“等待您补充信息”“已给出解决方案”“工单已关闭”。

消息按 `createdAt ASC, id ASC` 排序。平台内部备注、自动分派、内部转组和内部附件不返回用户端，也不以空白事件占位。

每条公开消息显示发送方角色、用户可见名称、发送时间、正文和公开附件。用户消息统一显示“我”或当前身份名称；平台消息显示“平台支持”。

用户不能编辑、撤回或删除已发送消息。若确需删除违法或误传敏感内容，由具备权限的运营流程处理并保留合规审计，用户侧显示“该内容已被平台移除”，不得物理抹除审计记录。

### 7.4 回复与补充材料

允许回复的状态：`PENDING`、`IN_PROGRESS`、`WAITING_USER`、`RESOLVED`。其中：

- `WAITING_USER` 下用户回复成功后，状态自动变为 `IN_PROGRESS`。
- `RESOLVED` 下不能使用普通回复框；用户需点击“问题仍未解决”，填写原因后恢复为 `IN_PROGRESS`。
- `CLOSED` 不允许继续回复，只能创建新工单并关联原工单。

回复正文 1～3000 字符，最多 5 个附件。空正文且无附件不能发送；仅附件回复允许发送，但需二次提示用户补充说明。回复同样使用幂等键和敏感信息检测。

用户在 `PENDING` 或 `IN_PROGRESS` 状态主动补充消息不会改变状态。为防止刷屏，服务端应支持可配置频控；暂定同一工单每分钟最多 5 条用户消息，超过后返回 429 和可重试时间。

### 7.5 已读规则

1. 打开详情并成功获得当前可见消息后，客户端上报最后可见公开消息 ID。
2. 服务端只允许推进 `lastReadMessageId`，不能回退。
3. 用户自己发送的消息不计入用户未读数。
4. 新的公开平台回复或公开状态说明增加未读数；内部消息不增加。
5. 已读失败不影响查看详情，但列表仍可显示未读，客户端可静默重试一次。
6. 切换身份后按新 `accountContextId` 重新计算，不共享已读进度。

### 7.6 确认解决和继续处理

当状态为 `RESOLVED` 时展示平台解决说明及两个操作：

**确认解决并关闭**

- 二次确认后状态变为 `CLOSED`。
- 关闭后不可回复，不可再次打开。
- 操作记录进入状态历史和操作审计。

**问题仍未解决**

- 用户必须填写 5～1000 字符的原因，可上传附件。
- 提交后状态变为 `IN_PROGRESS`，生成一条用户公开消息和状态历史。
- 运营端重新进入待处理队列，具体分派规则由运营端定义。

首版不自动关闭 `RESOLVED` 工单。若后续启用自动关闭，必须由服务端返回明确的 `autoCloseAt`，提前通知用户，并单独确认关闭期限和通知渠道。

## 8. 状态模型

### 8.1 状态定义

| 状态代码 | 用户文案 | 含义 | 用户可执行操作 |
|---|---|---|---|
| `PENDING` | 待受理 | 已提交，尚未开始处理 | 查看、补充回复 |
| `IN_PROGRESS` | 处理中 | 平台正在排查或处理 | 查看、补充回复 |
| `WAITING_USER` | 待我补充 | 平台需要用户补充信息 | 查看、回复 |
| `RESOLVED` | 已解决 | 平台已给出解决方案，等待用户确认 | 确认关闭、继续处理 |
| `CLOSED` | 已关闭 | 处理结束，不再接受消息 | 查看、创建关联新工单 |

首版不提供用户撤回或删除状态。误提交工单可由平台受理后关闭并说明原因。

### 8.2 状态流转

```text
提交
  ↓
PENDING ──平台受理──→ IN_PROGRESS
  │                       │
  │                       ├──平台要求补充──→ WAITING_USER
  │                       │                      │
  │                       │←────用户回复─────────┘
  │                       │
  │                       └──平台给出方案──→ RESOLVED
  │                                               │
  │                          用户仍有问题─────────┤→ IN_PROGRESS
  │                                               │
  └────────平台结束处理（需公开原因）──────────────┴→ CLOSED
                                                  ↑
                                       用户确认解决┘
```

流转规则由后端状态机执行，不能由前端提交任意目标状态。每次状态改变需写入状态历史，使用乐观锁防止运营回复和用户操作并发覆盖。

运营端可以从 `PENDING` 直接关闭重复、无效或不受理工单，但必须填写用户可见原因。用户侧不展示“驳回”等内部措辞，统一显示“已关闭”和公开说明。

## 9. 附件设计

### 9.1 文件限制

| 项目 | 首版规则 |
|---|---|
| 单次附件数 | 最多 5 个 |
| 单文件大小 | 最大 20 MB |
| 单次总大小 | 最大 50 MB |
| 允许扩展名 | `.png`、`.jpg`、`.jpeg`、`.webp`、`.pdf`、`.txt`、`.log`、`.json` |
| 禁止类型 | 可执行文件、脚本、Office 宏文件、压缩包、HTML、SVG 及与声明类型不一致的文件 |
| 文件名 | 最长 200 字符；展示名净化，不能用于对象存储路径 |

扩展名、MIME 和文件特征需综合校验，不能只判断扩展名。附件存储在私有对象存储，不提供永久公开 URL。

### 9.2 上传流程

1. 前端申请临时上传会话，提交文件名、大小、声明 MIME 和 SHA-256。
2. 后端校验身份、权限、数量和大小，返回一次性上传信息。
3. 前端上传至私有对象存储或受控上传接口。
4. 前端调用完成接口，服务端校验实际对象大小、哈希、类型并进入安全扫描。
5. 扫描通过后状态为 `AVAILABLE`，可以随工单或消息提交。
6. `SCANNING` 状态不能提交；`REJECTED` 显示通用原因并要求移除。
7. 未绑定工单／消息的临时附件 24 小时后清理。

附件下载必须再次校验当前身份对工单的访问权限，使用短时签名地址或服务端流式下载。对象存储键、存储桶名称和扫描内部结果不返回前端。

### 9.3 附件安全

- 首版附件默认下载，不在页面内执行或渲染主动内容；安全图片预览可以后续开启。
- 下载响应使用安全的 `Content-Disposition` 和 `X-Content-Type-Options: nosniff`。
- 平台支持的内部附件只有显式标记为 `PUBLIC` 才能被用户下载。
- 被隔离或删除附件保留元数据与审计，用户侧显示“附件已不可用”。
- 上传、下载、扫描结果和运营可见范围均需审计。

## 10. 页面状态与异常处理

| 场景 | 页面行为 |
|---|---|
| 初次加载 | 使用表格／详情骨架屏，不先显示空态 |
| 成功无数据 | 显示对应空态和可用入口 |
| 查询失败 | 显示错误状态与重试，不伪装为无工单 |
| 工单不存在或无权访问 | 统一返回 404 用户文案，避免确认其他身份工单存在性 |
| 工单状态已改变 | 返回 409 和最新状态；刷新详情并提示用户重新操作 |
| 重复提交 | 同一幂等键返回原创建结果，不创建第二张工单 |
| 回复重复 | 同一幂等键返回原消息，不重复展示 |
| 附件扫描失败 | 保留其他表单内容，仅要求移除或替换附件 |
| 来源上下文读取失败 | 允许手动提交，不泄露来源对象信息 |
| 账号被停机 | 是否仍允许查看和提交由后端权限返回；前端不依据账号状态自行推断 |
| 登录失效 | 清空页面和未提交数据，由公共框架处理重新登录 |
| 身份切换 | 清空旧身份数据、临时附件视图和表单，旧响应不得回填 |
| 网络中断发送结果未知 | 使用原幂等键查询／重试，不能换新键盲目重复发送 |

## 第二部分：接口、数据与技术设计

## 11. 后端职责

门户后端／工单服务负责：

- 身份与权限校验、数据范围过滤和字段裁剪。
- 工单编号生成、状态机、并发控制与幂等处理。
- 工单、消息、关联对象、附件、状态历史和已读状态持久化。
- 来源对象校验和最小公开信息快照。
- 敏感信息检测、附件安全扫描接入和下载鉴权。
- 用户侧更新时间与未读数计算。
- 向运营受理端提供同一状态模型，同时隔离内部消息与用户可见消息。
- 写入操作审计并产生站内消息事件。

工单服务不负责调用计量、额度扣减、服务订购、网关路由或 API Key 原文查询。排查所需数据通过受控的服务端接口按 `requestId` 读取，不复制到用户可见字段。

## 12. 用户侧接口契约

### 12.1 公共约定

- 接口前缀示例：`/api/portal/v1`。
- 当前身份按公共设计传递和验证，响应携带 `accountContextId`。
- 新建工单、发送回复、确认解决和继续处理必须携带 `Idempotency-Key`。
- 列表和详情不得返回内部消息、内部分派和内部附件。
- 写请求使用 `version` 或 `If-Match` 进行乐观并发控制。
- 业务校验错误返回稳定错误码和字段错误，不返回内部异常堆栈。

- 不编码账户 ID、用户 ID、手机号或分类。

- 用户搜索可精确匹配且不区分字母大小写。

## 15. 安全、审计与数据保留

### 15.1 安全要求

- 工单正文、公开回复和附件可能包含业务信息，应按敏感数据等级加密存储和传输。
- 所有详情、消息、附件下载都先校验工单所属 `accountContextId`。
- 富文本首版不开放；纯文本展示必须转义，防止 XSS。
- 文件名、错误消息和来源摘要必须转义，不信任用户输入或下游文本。
- 敏感信息检测不得把被检测原文写入应用日志、埋点或错误监控。
- 全文搜索若后续建设，索引必须遵循相同权限和删除／归档策略；首版仅搜索编号和标题。
- 运营端导出、批量下载和跨账户查询不在用户门户权限内，应单独审计。

### 15.2 审计事件

至少记录：

| 事件代码 | 内容边界 |
|---|---|
| `TICKET_CREATED` | 工单 ID、编号、身份、分类，不记录正文 |
| `TICKET_USER_REPLIED` | 工单 ID、消息 ID、附件数量，不记录正文 |
| `TICKET_RESOLUTION_CONFIRMED` | 工单 ID、前后状态 |
| `TICKET_CONTINUE_REQUESTED` | 工单 ID、消息 ID、前后状态，不记录原因全文 |
| `TICKET_ATTACHMENT_UPLOADED` | 附件 ID、类型、大小、扫描结果 |
| `TICKET_ATTACHMENT_DOWNLOADED` | 工单 ID、附件 ID、下载身份 |
| `TICKET_SENSITIVE_CONTENT_BLOCKED` | 规则代码和字段位置，不记录命中内容 |

### 15.3 数据保留

工单、消息、附件和审计的具体保留期限待合规与运营确认。确认前：

- 不提供用户物理删除。
- 不自动永久保留上传失败和未绑定附件；临时附件 24 小时清理。
- 归档后仍要保证工单编号可追踪，并按权限读取。
- 保留期限到期后的正文、附件、关联快照和备份处置必须形成统一策略，不能只删除主表。

## 16. 性能、并发与可用性

- 列表接口默认 20 条，必须分页，不一次返回全部工单或消息正文。
- 详情公开消息首版可在 100 条以内一次返回；超过后按游标分页，最新消息和状态摘要优先加载。
- 新建、回复、状态操作均使用幂等键；同一键不同请求体返回冲突。
- 状态变更使用事务和乐观锁，主表、状态历史、公开消息及附件绑定保持一致。
- 站内未读事件通过事务消息／Outbox 等可靠机制发送，通知失败不回滚已成功工单操作，但需补偿。
- 附件扫描和对象清理异步执行；扫描未完成前不能绑定提交。
- 用户侧列表目标响应时间建议 P95 不超过 2 秒，详情不含附件下载 P95 不超过 2 秒；具体容量目标待部署规模确认。
- 不缓存跨身份详情。列表缓存如存在，键必须包含 `accountContextId`、权限版本和全部筛选参数，写操作后失效。

## 第三部分：验收与实施说明

## 17. 验收标准

| 编号 | 场景 | 预期结果 |
|---|---|---|
| AC01 | 主账户提交工单 | 创建 `PENDING` 工单，生成唯一编号并进入详情 |
| AC02 | 子账户提交工单 | 绑定子账户 `accountContextId`，不泄露主账户余额或其他工单 |
| AC03 | 主账户查看子账户工单 URL | 返回统一 404，不返回标题和状态 |
| AC04 | 切换身份时表单有输入 | 提示放弃；确认后清空输入、来源上下文和临时附件视图 |
| AC05 | 从告警提交工单 | 后端重新校验告警权限，预填最小公开信息并保存结构化引用 |
| AC06 | 篡改 `sourceId` 指向他人告警 | 不预填且不泄露对象存在性，仍可手动提交 |
| AC07 | 从调用明细提交 | 可带 requestId、时间、公开模型和错误码，不带 Prompt、Key 和响应正文 |
| AC08 | 关联用户密钥 | 仅展示名称及尾号，数据库和接口无密钥原文 |
| AC09 | 双击提交或网络重试 | 同一幂等键只创建一张工单并返回同一结果 |
| AC10 | 同一幂等键请求体不同 | 返回冲突，不复用旧结果创建新资源 |
| AC11 | 平台公开回复 | 用户列表未读数增加，内部备注不增加未读数 |
| AC12 | 打开详情并上报已读 | 已读位置只前进，自己的消息不计未读 |
| AC13 | 状态为待我补充时用户回复 | 生成公开消息，状态变为处理中并记录历史 |
| AC14 | 状态为处理中时用户补充 | 状态保持处理中，用户侧更新时间更新 |
| AC15 | 平台标记已解决 | 展示解决说明和“确认解决／仍未解决”操作 |
| AC16 | 用户确认解决 | 状态变为已关闭，不能继续回复 |
| AC17 | 用户选择仍未解决 | 必填原因，状态恢复处理中，产生消息和历史 |
| AC18 | 两端并发改变状态 | 旧版本操作返回 409，刷新后显示最新状态 |
| AC19 | 已关闭工单继续回复 | 后端拒绝；页面只提供创建关联新工单入口 |
| AC20 | 列表内部操作发生但无公开变化 | `userVisibleUpdatedAt` 不变化，列表不无故置顶 |
| AC21 | 上传超过 20 MB 文件 | 上传前后均校验并拒绝，其他表单内容保留 |
| AC22 | 上传脚本、压缩包或伪造 MIME | 拒绝或隔离，不生成可下载公开附件 |
| AC23 | 附件扫描中提交 | 返回附件未就绪，等待或移除后才能提交 |
| AC24 | 下载他人工单附件 | 返回统一 404／无权结果，不生成签名 URL |
| AC25 | 临时附件 24 小时未绑定 | 被清理且无法再次提交引用 |
| AC26 | 正文含疑似完整 API Key | 阻止提交，不在提示、日志和埋点中回显凭证 |
| AC27 | 查询成功无工单 | 显示空态和提交入口，不显示错误 |
| AC28 | 查询失败 | 显示失败与重试，不显示“暂无工单” |
| AC29 | 无创建权限 | 列表仍按读权限展示，提交按钮和创建接口不可用 |
| AC30 | 直接传任意目标状态 | 后端状态机拒绝，不允许越过合法流转 |
| AC31 | 分类被停用 | 历史工单仍展示名称，新建页不再允许选择 |
| AC32 | 关联服务已删除 | 工单显示脱敏快照和“当前不可用”，详情仍可访问 |
| AC33 | 用户输入 HTML／脚本 | 按纯文本转义展示，不执行脚本 |
| AC34 | 小屏幕访问 | 列表改为卡片、详情单列，核心操作可完成且无整页横向滚动 |

开发至少准备：主账户、子账户、空列表、各状态、未读回复、来源无权、敏感内容、附件扫描失败、超大文件、版本冲突、幂等重试和关联对象失效等 Mock 场景。

## 18. 待确认项及暂定处理

| 事项 | 需确认方 | 本版暂定处理 |

| 外部通知渠道 | 产品／消息平台 | 首版只有站内未读，不发送短信／邮件 |

## 19. 交给代码生成模型的实施说明

请同时提供本文和[《用户门户公共设计》](用户门户公共设计.md)，并要求代码生成模型遵守以下边界：

1. 实现 `/help/tickets`、`/help/tickets/new`、`/help/tickets/:ticketId` 三类用户页面及本文用户侧接口，不扩展实现完整运营受理后台。
2. 优先遵循现有仓库技术栈和目录规范；前端将列表筛选、新建表单、来源摘要、附件上传、详情摘要、公开时间线、回复区和状态操作拆分为可维护组件。
3. 所有查询和写操作经统一服务层访问，携带当前业务身份；身份切换时取消或丢弃旧请求并清空表单及临时附件视图。
4. 操作入口使用服务端 `availableActions`，不要只根据状态在前端推断权限。
5. 工单状态由后端状态机控制，使用乐观锁、事务、状态历史和幂等键；禁止客户端直接提交任意目标状态。
6. 用户接口只返回 `PUBLIC` 消息和附件；内部消息、内部分派、内部备注和内部附件从查询层即排除。
7. 来源 URL 只传标识，后端重新读取并校验；不得信任前端传来的标题、错误详情、账户 ID 或关联对象快照。
8. 不读取、保存或展示 API Key 原文；不把 Prompt、完整请求／响应体、供应商数据写入工单关联元数据。
9. 附件使用私有存储、临时上传、类型与哈希校验、安全扫描和下载鉴权；Mock 环境也要模拟扫描中、拒绝和过期状态。
10. 文本按纯文本转义展示，敏感检测结果和被拦截内容不写入日志与埋点。
11. 尚未接入的真实工单服务、对象存储、扫描器和消息服务通过明确的 Provider／Adapter 接口隔离；Mock 只能在开发配置启用，生产不得静默回退。
12. 按第 17 章覆盖权限隔离、幂等、并发、状态流转、敏感内容、附件安全和身份切换等必要测试，并在交付说明中列出仍使用 Mock 的能力。

后续如建设运营受理端，应单独编写“运营门户—工单管理”需求，复用本文状态、消息可见性和附件模型，并补充分派、处理组、内部优先级、SLA、内部协作与统计报表。
