# TokenHub 用户门户需求与技术设计：09 平台公告

版本：V0.1，开发评审稿  
适用范围：用户门户前端、门户后端、公告数据服务、接口联调与验收  
依据：《TokenHub平台设计方案.docx》及《用户门户公共设计》  
页面路由：`/help/announcements`、`/help/announcements/:announcementId`

## 1. 文档范围

平台设计方案明确要求用户门户提供公告查看入口，公告内容主要包括模型上下架、维护通知等平台信息。本模块负责用户侧的公告列表、公告详情、未读状态和关联页面跳转。

公告的创建、编辑、审核、发布、撤回属于运营管理能力，不在用户门户页面范围内；但本文定义公告生命周期、数据表和用户侧接口，保证后续运营端可以基于同一数据模型建设。

本文引用[《用户门户公共设计》](用户门户公共设计.md)中的登录身份、接口格式、错误处理、时间格式和数据隔离约定，不重复定义冲突规则。

规则标记：

- **方案已有**：原设计方案明确提出。
- **本版设计**：为形成完整页面和开发契约补充的规则。
- **待业务确认**：原方案未明确，开发可先按暂定规则实现，生产发布前确认。

## 2. 建设目标

平台公告需要帮助用户完成以下任务：

1. 快速了解模型上下架、系统维护、服务调整和一般通知。
2. 识别公告的影响范围、开始时间和结束时间。
3. 查看完整公告内容以及相关模型、服务或文档入口。
4. 区分未读和已读公告，避免重要信息被遗漏。
5. 只能查看对当前账户身份有效且处于发布状态的公告。

平台公告不是站内工单、告警或营销活动：

| 内容类型 | 归属模块 |
|---|---|
| 面向一批用户发布的模型变更、维护和平台通知 | 平台公告 |
| 某个账户余额不足、调用异常 | 告警中心 |
| 用户提交问题并等待处理 | 我的工单 |
| CRM 产品订购、促销和交易信息 | CRM 或相关产品页面 |

## 3. 角色与权限

### 3.1 用户侧角色

主账户和子账户均可访问平台公告。后端根据当前登录用户及 `accountContextId` 判断公告是否可见，前端隐藏不能代替后端鉴权。

用户侧只有以下权限：

- 查看公告列表。
- 查看公告详情。
- 将当前身份下的公告标记为已读。
- 通过公告中的受控关联入口跳转到模型目录、接入文档或服务详情。

用户不能创建、修改、删除、发布或撤回公告。

### 3.2 公告可见范围

本版支持以下范围：

| 范围代码 | 含义 | 用户侧判断 |
|---|---|---|
| `ALL` | 所有有效账户身份 | 主账户、子账户均可见 |
| `MAIN_ACCOUNT` | 仅主账户 | 子账户不可见 |
| `SUB_ACCOUNT` | 仅子账户 | 主账户不可见 |
| `SPECIFIED_ACCOUNT` | 指定业务账户 | 当前身份关联的业务账户在目标范围内才可见 |
| `SPECIFIED_SERVICE` | 指定服务实例用户 | 当前身份对指定服务实例有查看权限才可见 |

公告目标范围由服务端计算。接口不得返回当前身份无权查看的公告标题、摘要或正文。

同一登录用户切换主账户或子账户身份时，公告列表、未读数和已读状态均按新身份重新查询。已读状态暂按 `accountContextId` 隔离，不跨身份同步。

```text
帮助与支持
└─ 平台公告
   ├─ 公告列表
   │  ├─ 分类筛选
   │  ├─ 关键字搜索
   │  ├─ 已读状态筛选
   │  └─ 分页列表
   └─ 公告详情
```

## 5. 公告列表页

### 5.1 页面布局

```text
┌──────────────────────────────────────────────────────────┐
│ 平台公告                                                  │
│ 查看模型变更、平台维护和服务通知                           │
├──────────────────────────────────────────────────────────┤
│ [全部分类▼] [全部状态▼] [标题关键字________] [查询] [重置] │
├──────────────────────────────────────────────────────────┤
│ [置顶][维护通知][未读] 计划于10月1日进行平台升级            │
│ 影响时间：2026-10-01 00:00 至 02:00       2026-09-28      │
│ 升级期间部分模型调用可能出现短暂中断……                     │
├──────────────────────────────────────────────────────────┤
│ [模型变更][已读] 某模型版本升级说明                         │
│                                                     ...  │
├──────────────────────────────────────────────────────────┤
│                                             分页器         │
└──────────────────────────────────────────────────────────┘
```

### 5.2 筛选条件

| 条件 | 类型 | 默认值 | 规则 |
|---|---|---|---|
| 公告分类 | 单选下拉 | 全部 | 支持维护通知、模型变更、服务通知、一般公告 |
| 阅读状态 | 单选下拉 | 全部 | 全部、未读、已读 |
| 标题关键字 | 输入框 | 空 | 去除首尾空格，最长 50 字符，回车可查询 |

查询参数写入 URL，示例：

```text
/help/announcements?category=MAINTENANCE&readStatus=UNREAD&keyword=升级&page=1&pageSize=10
```

刷新或从详情返回时保留查询条件和页码。切换身份后清空筛选条件并回到第一页，防止旧身份筛选结果残留。

### 5.3 列表展示规则

每条公告展示：

- 置顶标识，仅 `isPinned=true` 时展示。
- 分类标签。
- 未读／已读状态；未读标题使用较高字重。
- 公告标题，最多两行，超出省略。
- 公告摘要，最多两行；无摘要时不从富文本正文直接截取 HTML。
- 发布时间。
- 影响开始时间和结束时间，仅有值时展示。
- “重要”标识，仅 `importance=IMPORTANT` 时展示。

排序规则由服务端统一执行：

1. 有效置顶公告优先。
2. 同为置顶时按置顶时间倒序。
3. 非置顶公告按发布时间倒序。
4. 时间相同时按公告 ID 倒序，保证分页稳定。

置顶不是永久置顶。`pinnedUntil` 已过期后按普通公告排序，但公告仍可继续展示。

### 5.4 列表交互

1. 点击标题或整条公告进入详情页。
2. 进入详情成功后标记为已读；只打开列表不自动标记已读。
3. 点击查询后页码重置为 1。
4. 点击重置恢复默认筛选并立即查询第一页。
5. 页面大小支持 10、20、50，默认 10。
6. 查询过程中保留筛选区，列表显示加载状态并防止重复请求覆盖最新结果。
7. 无符合条件数据时显示“暂无符合条件的公告”。
8. 首次查询失败时显示错误状态和“重新加载”；不得将失败显示成无公告。

### 5.5 公告是否显示

一条公告只有同时满足以下条件才出现在用户列表：

- 状态为 `PUBLISHED`。
- 当前时间不早于 `publishAt`。
- `offlineAt` 为空或当前时间早于 `offlineAt`。
- 当前身份符合可见范围。
- 公告未被逻辑删除。

“影响结束时间”不等于“公告下线时间”。维护结束后公告可以继续保留供用户查阅。

## 6. 公告详情页

### 6.1 页面内容

详情页展示：

| 区域 | 字段 |
|---|---|
| 标题区 | 标题、分类、重要程度、发布时间 |
| 影响信息 | 影响开始时间、影响结束时间、影响说明 |
| 正文区 | 公告富文本正文 |
| 附加信息 | 相关模型、相关服务或相关文档入口 |
| 底部操作 | 返回公告列表 |

详情页不显示创建人账号、审核人、内部备注、指定用户清单等运营字段。

### 6.2 已读规则

1. 详情接口鉴权并成功返回内容后，服务端异步或在同一事务后写入阅读记录。
2. 阅读记录写入失败不阻断正文展示，但应记录服务端错误日志。
3. 同一 `announcementId + accountContextId` 只保留一条阅读记录。
4. 重复查看更新 `lastReadAt` 和 `readCount`，首次阅读时间保持不变。
5. 公告正文更新后是否重新变为未读属于待确认项；本版暂不重置已读状态。

### 6.3 富文本安全

- 正文由运营端受控富文本编辑器产生，服务端保存前进行白名单清洗。
- 前端仍使用安全的富文本渲染组件，不直接执行任意 HTML。
- 禁止 `script`、内联事件、iframe、表单及未知协议链接。
- 外部链接必须使用 `https`，打开新窗口时增加安全属性。
- 图片只能使用平台允许的资源地址；加载失败显示替代文本。
- 用户侧不提供正文编辑能力。

### 6.4 关联入口

关联入口采用结构化数据，不允许在正文中写任意内部路由。支持：

| 类型 | 路由示例 |
|---|---|
| 模型详情 | `/models/:modelId` |
| 服务详情 | `/services/:serviceId` |
| 接入文档 | `/help/docs/:documentId` |

服务端返回前必须验证当前身份对目标对象有访问权限。无权限或目标已下线时不返回入口；正文仍可以正常展示。

### 6.5 异常情况

| 情况 | 页面行为 |
|---|---|
| 公告不存在 | 显示“公告不存在或已删除”，提供返回列表 |
| 公告已下线 | 视为不可访问，显示“公告已下线” |
| 当前身份不在范围内 | 返回 404，避免泄露公告存在性 |
| 登录失效 | 由公共框架处理重新登录 |
| 正文加载失败 | 显示错误状态和重试入口，不写入已读记录 |
| 关联目标不存在 | 隐藏对应关联入口，不影响正文 |

## 7. 页面状态与响应式要求

- 初次加载显示列表骨架屏。
- 筛选查询显示列表区加载状态，不清空筛选条件。
- 空结果、请求失败和无权限必须使用不同状态。
- 内容宽度建议不超过 1200px；正文阅读区建议不超过 900px。
- 小于 768px 时筛选项纵向排列，列表元信息换行，不产生整页横向滚动。
- 标题、筛选项、公告列表和返回按钮支持键盘操作。
- 标签不仅依赖颜色表达，必须显示文字。
- 正文标题层级、链接和图片提供可访问语义。

## 8. 接口设计

接口前缀示例为 `/api/portal/v1`，实际以前后端统一配置为准。

### 8.1 获取公告列表

```http
GET /api/portal/v1/announcements
```

请求参数：

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| category | string | 否 | 公告分类 |
| readStatus | string | 否 | `READ` 或 `UNREAD` |
| keyword | string | 否 | 标题关键字，最长 50 字符 |
| page | integer | 否 | 默认 1，最小 1 |
| pageSize | integer | 否 | 默认 10，可选 10、20、50 |

响应示例：

```json
{
  "requestId": "req_01",
  "accountContextId": "ctx_1001",
  "data": {
    "items": [
      {
        "announcementId": "ann_1001",
        "title": "平台升级维护通知",
        "summary": "平台将于指定时间进行升级维护。",
        "category": "MAINTENANCE",
        "importance": "IMPORTANT",
        "isPinned": true,
        "publishedAt": "2026-09-28T10:00:00+08:00",
        "impactStartAt": "2026-10-01T00:00:00+08:00",
        "impactEndAt": "2026-10-01T02:00:00+08:00",
        "isRead": false
      }
    ],
    "page": 1,
    "pageSize": 10,
    "total": 1,
    "unreadCount": 1
  }
}
```

`total` 是当前筛选条件下总数，`unreadCount` 是当前身份所有可见有效公告的未读总数，不受当前阅读状态和分页参数影响。

### 8.2 获取公告详情

```http
GET /api/portal/v1/announcements/{announcementId}
```

响应核心字段：

```ts
interface AnnouncementDetail {
  announcementId: string;
  title: string;
  summary: string | null;
  category: AnnouncementCategory;
  importance: 'NORMAL' | 'IMPORTANT';
  publishedAt: string;
  impactStartAt: string | null;
  impactEndAt: string | null;
  impactDescription: string | null;
  contentHtml: string;
  contentVersion: number;
  isRead: boolean;
  relatedLinks: Array<{
    type: 'MODEL' | 'SERVICE' | 'DOCUMENT';
    targetId: string;
    label: string;
    path: string;
  }>;
}
```

详情接口仅返回经过服务端清洗后的 `contentHtml`。接口成功后完成已读记录；如采用独立写接口，则详情加载成功后调用下述接口，并保证幂等。

### 8.3 标记已读（可选独立接口）

```http
PUT /api/portal/v1/announcements/{announcementId}/read
```

无请求体，重复调用返回成功。公告不可见时返回 404。

### 8.4 获取公告未读数

```http
GET /api/portal/v1/announcements/unread-count
```

用于公共菜单角标。返回：

```json
{
  "requestId": "req_02",
  "accountContextId": "ctx_1001",
  "data": { "unreadCount": 3 }
}
```

首版在登录、切换身份、进入公告页面及成功阅读公告后更新未读数，不要求实时推送。

### 8.5 获取概览公告摘要

概览页可调用：

```http
GET /api/portal/v1/announcements?summary=true&page=1&pageSize=3
```

返回与列表相同的可见范围和排序结果，避免概览另建一套公告数据。

## 9. 数据字典

### 9.1 公告分类 `announcement_category`

| 代码 | 展示名称 | 典型内容 |
|---|---|---|
| `MAINTENANCE` | 维护通知 | 系统升级、计划维护、服务中断 |
| `MODEL_CHANGE` | 模型变更 | 模型上线、下线、版本升级、能力调整 |
| `SERVICE_NOTICE` | 服务通知 | 接口、计费口径、服务规则调整 |
| `GENERAL` | 一般公告 | 平台一般性通知 |

### 9.2 公告状态 `announcement_status`

| 代码 | 含义 | 用户门户是否可见 |
|---|---|---|
| `DRAFT` | 草稿 | 否 |
| `PENDING_REVIEW` | 待审核 | 否 |
| `PUBLISHED` | 已发布 | 结合发布时间、下线时间和可见范围判断 |
| `OFFLINE` | 已下线 | 否 |
| `REJECTED` | 审核驳回 | 否 |

### 9.3 重要程度 `announcement_importance`

| 代码 | 含义 |
|---|---|
| `NORMAL` | 普通公告 |
| `IMPORTANT` | 需要突出提示的重要公告 |

重要程度只影响展示，不改变可见权限和排序。是否置顶由独立字段控制。

### 9.4 目标类型 `announcement_target_type`

| 代码 | 含义 |
|---|---|
| `ALL` | 全部账户身份 |
| `MAIN_ACCOUNT` | 所有主账户 |
| `SUB_ACCOUNT` | 所有子账户 |
| `SPECIFIED_ACCOUNT` | 指定业务账户 |
| `SPECIFIED_SERVICE` | 指定服务实例相关用户 |

### 9.5 字段约束

| 字段 | 约束 |
|---|---|
| title | 必填，1～200 字符，纯文本 |
| summary | 选填，最多 500 字符，纯文本 |
| contentHtml | 必填，清洗后富文本，建议不超过 2 MB |
| publishAt | 必填，到达该时间才可在用户侧查询 |
| offlineAt | 选填，必须晚于 publishAt |
| impactStartAt / impactEndAt | 均可为空；同时存在时结束时间必须晚于开始时间 |
| pinnedUntil | `isPinned=true` 时可为空；为空表示发布期间持续置顶 |
| contentVersion | 从 1 开始，每次正文或关键展示字段修改递增 |

## 10. 表结构设计

以下为 MySQL 逻辑设计。审计字段、主键生成方式和逻辑删除规范应服从项目公共数据库规范。

### 10.1 公告主表 `portal_announcement`

| 字段 | 类型 | 允许空 | 说明 |
|---|---|---|---|
| id | varchar(64) | 否 | 公告 ID，主键 |
| title | varchar(200) | 否 | 公告标题 |
| summary | varchar(500) | 是 | 列表摘要 |
| category | varchar(32) | 否 | 公告分类 |
| importance | varchar(16) | 否 | 重要程度 |
| content_html | mediumtext | 否 | 清洗后的公告正文 |
| content_version | int | 否 | 内容版本，默认 1 |
| status | varchar(32) | 否 | 公告状态 |
| target_type | varchar(32) | 否 | 可见范围类型 |
| is_pinned | tinyint(1) | 否 | 是否置顶 |
| pinned_at | datetime(3) | 是 | 置顶时间 |
| pinned_until | datetime(3) | 是 | 置顶截止时间 |
| publish_at | datetime(3) | 否 | 计划／实际生效发布时间 |
| offline_at | datetime(3) | 是 | 自动下线时间 |
| impact_start_at | datetime(3) | 是 | 影响开始时间 |
| impact_end_at | datetime(3) | 是 | 影响结束时间 |
| impact_description | varchar(1000) | 是 | 影响范围说明 |
| created_by | varchar(64) | 否 | 创建人 |
| created_at | datetime(3) | 否 | 创建时间 |
| updated_by | varchar(64) | 否 | 最后修改人 |
| updated_at | datetime(3) | 否 | 最后修改时间 |
| deleted | tinyint(1) | 否 | 逻辑删除标识 |

建议索引：

- 主键：`pk_portal_announcement(id)`。
- 用户查询：`idx_announcement_visible(status, publish_at, offline_at, deleted)`。
- 列表排序：`idx_announcement_sort(is_pinned, pinned_at, publish_at)`。
- 分类筛选：`idx_announcement_category(category, publish_at)`。

### 10.2 公告目标表 `portal_announcement_target`

仅 `SPECIFIED_ACCOUNT` 和 `SPECIFIED_SERVICE` 需要数据。

| 字段 | 类型 | 允许空 | 说明 |
|---|---|---|---|
| id | varchar(64) | 否 | 主键 |
| announcement_id | varchar(64) | 否 | 公告 ID |
| target_type | varchar(32) | 否 | `ACCOUNT` 或 `SERVICE` |
| target_id | varchar(64) | 否 | 业务账户 ID 或服务实例 ID |
| created_at | datetime(3) | 否 | 创建时间 |

唯一约束：`uk_announcement_target(announcement_id, target_type, target_id)`。

目标数量较大时不得在用户请求中逐行扫描；运营端发布时应完成索引数据准备，或由账户／服务关系查询服务提供高效判断。

已读写入采用幂等更新，避免重复插入。删除公告时阅读记录可以保留用于审计，由数据留存规则统一清理。

## 11. 后端处理逻辑

### 11.1 列表查询流程

1. 校验登录状态和当前 `accountContextId`。
2. 获取当前身份角色、业务账户以及有权查看的服务范围。
3. 根据发布时间、下线时间、公告状态和逻辑删除筛选有效公告。
4. 根据 `targetType` 和目标表过滤可见范围。
5. 应用分类、阅读状态和关键字筛选。
6. 关联当前身份的阅读记录，计算 `isRead`。
7. 按置顶及发布时间稳定排序并分页。
8. 返回列表和当前身份未读总数。

关键字查询首版只匹配标题，不搜索富文本正文，避免数据库低效模糊扫描。后续如需全文检索应接入独立检索能力。

### 11.2 详情查询流程

1. 校验身份。
2. 按与列表完全相同的规则判断公告是否有效且可见。
3. 查询清洗后的正文和结构化关联对象。
4. 对每个关联对象再次执行当前身份权限检查。
5. 返回详情。
6. 幂等写入或更新阅读记录。

列表和详情必须复用同一可见性判断组件，防止用户通过猜测 ID 读取不可见公告。

## 12. 验收标准

| 编号 | 场景 | 预期结果 |
|---|---|---|
| AC01 | 主账户查看 `ALL` 公告 | 列表和详情正常展示 |
| AC02 | 子账户访问 `MAIN_ACCOUNT` 公告 ID | 返回 404，不泄露标题和正文 |
| AC03 | 指定服务公告面向某服务 | 只有对该服务有权限的身份可见 |
| AC04 | 公告发布时间未到 | 列表与详情均不可见 |
| AC05 | 公告已到下线时间 | 列表不展示，详情显示已下线或返回 404 |
| AC06 | 公告影响时间结束但未下线 | 公告仍可查阅 |
| AC07 | 同时存在置顶和普通公告 | 有效置顶优先，普通公告按发布时间倒序 |
| AC08 | 置顶时间已过期 | 公告保留，按普通公告参与排序 |
| AC09 | 从筛选后的第3页进入详情再返回 | 恢复筛选条件和页码 |
| AC10 | 打开公告详情 | 当前身份未读数减少，其他身份已读状态不变 |
| AC11 | 重复打开同一公告 | 不产生重复阅读记录，阅读次数更新 |
| AC12 | 列表请求失败 | 显示错误和重试，不显示“暂无公告” |
| AC13 | 正文包含脚本或危险链接 | 保存或渲染时被清理，不能执行脚本 |
| AC14 | 关联服务已无权限 | 不返回服务入口，正文仍展示 |
| AC15 | 快速切换账户身份 | 旧身份列表响应不得渲染到新身份页面 |
| AC16 | 公告正文更新 | 内容版本递增；本版原阅读状态保持不变 |
| AC17 | 无任何可见公告 | 显示正常空状态，未读数为0 |
| AC18 | 移动端查看长公告 | 正文可读，无整页横向滚动 |

开发 Mock 至少覆盖：普通公告、重要公告、有效置顶、过期置顶、模型变更、维护通知、未读／已读、指定主账户、指定服务、未到发布时间、已下线、危险富文本和接口失败。

## 13. 待确认项

| 事项 | 需确认方 | 当前处理 |
|---|---|---|
| 公告是否需要运营审核流程 | 产品／运营 | 数据字典预留待审核和驳回状态，用户侧不受影响 |
| 正文修改后是否重新变为未读 | 产品／运营 | 暂不重置，保留阅读内容版本供后续扩展 |
| 指定账户范围按主账户还是业务身份配置 | 产品／账户模块 | 暂按业务账户配置，展示时再映射当前身份 |
| 子账户是否查看所有平台公告 | 产品 | 默认可查看 `ALL` 和明确面向子账户的公告 |
| 是否需要站内实时推送和弹窗强提醒 | 产品 | 首版不做实时推送和强制弹窗，仅提供未读标识 |
| 公告附件是否支持下载 | 产品／安全 | 首版不支持附件，仅支持安全正文图片和结构化关联入口 |
| 公告保留时间及阅读记录清理周期 | 运营／合规 | 待统一数据留存规则确定 |
| 富文本图片存储位置与域名白名单 | 架构／安全 | 接入前配置，不允许任意外链图片 |

## 14. 交给代码生成模型的实施说明

请实现本文定义的用户门户“平台公告”模块，不扩展实现运营端公告管理页面。

1. 遵循现有 Vue 3、TypeScript、Ant Design Vue、Spring Boot 及项目目录规范。
2. 前端拆分公告筛选、公告列表项、分页、公告详情、关联入口和页面状态组件；所有请求经过统一服务层。
3. 查询条件同步 URL，详情返回时恢复列表状态；身份切换时清除旧状态和旧请求结果。
4. 后端统一实现公告有效性和可见范围判断，列表与详情复用；禁止仅依赖前端隐藏。
5. 富文本必须在服务端清洗，并在前端安全渲染；禁止任意脚本、iframe、表单和未知协议链接。
6. 使用本文定义的数据字典、接口和表结构；枚举不要以魔法字符串散落在组件中。
7. 阅读记录按 `announcementId + accountContextId` 幂等写入。
8. 不实现在线营销、CRM 订单通知、用户告警或工单功能。
9. 对可见范围越权、发布时间边界、置顶排序、身份切换、富文本安全和已读幂等进行必要验证。
10. 真实运营发布接口尚未接入时可以提供开发环境 Mock，但生产环境不得回退到 Mock 公告。
