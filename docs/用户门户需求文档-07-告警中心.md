## 第一部分：业务需求与页面交互

## 1. 模块定位与范围

### 1.1 用户目标

告警中心集中展示当前业务身份范围内的额度风险和异常调用风险，回答以下问题：

1. 当前有哪些问题需要关注，严重程度如何？
2. 问题影响哪个服务、子账户或用户密钥？
3. 问题是否仍在持续，是否已经影响模型调用？
4. 告警依据是什么，应该去哪里核对和处理？
5. 同一问题是否反复发生，何时产生、升级和恢复？

### 1.2 本期范围

- 告警列表、分类标签、条件筛选、稳定分页和详情抽屉。
- 顶部消息铃铛所需的未读数量和最近告警查询。
- 额度不足、额度严重不足、额度耗尽和子账户配额不足告警。
- 请求频率异常、持续失败、超大请求、密钥疑似滥用和调用受限告警。
- 告警产生、持续、升级、恢复和阅读状态管理。
- 单条、批量、全部标记已读。
- 主账户和子账户的数据隔离及字段裁剪。
- 跳转我的服务、用量中心、API密钥和工单的处理入口。
- 告警事件接收、幂等处理、聚合关联和历史留存结构。

本期不做：用户自定义告警阈值、用户手动关闭或删除告警、告警检测算法、用户自行配置异常检测规则、短信／邮件等站外通知配置、请求或响应正文查看、管理员全平台告警、供应商渠道熔断告警、自动暂停密钥、复杂订阅规则、告警导出、告警统计大屏。

### 1.3 模块边界

| 模块／系统 | 本模块使用的数据 | 边界 |
|---|---|---|
| 额度／计费服务 | 服务额度、子账户配额、阈值突破及恢复事件 | 本模块不重新计算余额，不决定调用准入 |
| 大网关／实时计算 | 异常调用检测及聚合事件 | 本模块不从调用明细自行判定异常 |
| 我的服务 | 服务名称、类型、状态及处理入口 | 订购、变更套餐和资金账归CRM |
| API密钥 | 用户密钥历史名称、掩码和可执行动作 | 只允许管理用户密钥；业务密钥不暴露 |
| 用量中心 | 与告警相关的统计及调用明细 | 告警只传筛选条件，不复制用量数据 |
| 子账户管理 | 子账户名称、配额和归属 | 权限范围由服务端依据当前身份确定 |
| 工单 | 告警编号、请求ID等预填信息 | 工单受理和流转不在本模块实现 |
| 操作审计 | 告警已读操作事件 | 仅真实未读→已读变化产生审计事件 |
| 平台公告 | 模型上下架、计划维护、平台通知 | 不作为用户风险告警混入本模块 |
| 运营门户 | 渠道熔断、供应商端点异常 | 用户门户不展示渠道和供应商内部信息 |

## 2. 告警分类与级别

### 2.1 额度告警

额度告警按权威额度池产生。多个用户密钥共享同一Token服务额度时，不为每个密钥重复产生余额告警。

| alertType | 中文名称 | 触发语义 | 默认级别 | 处理方向 |
|---|---|---|---|---|
| SERVICE_QUOTA_LOW | 服务额度不足 | 剩余额度首次低于预警阈值 | NOTICE | 查看服务余量并及时补充 |
| SERVICE_QUOTA_CRITICAL | 服务额度严重不足 | 剩余额度首次低于严重阈值 | WARNING | 加订急救包或前往CRM办理 |
| SERVICE_QUOTA_EXHAUSTED | 服务额度耗尽 | 额度为零或不足以完成预扣，调用可能被拒绝 | CRITICAL | 立即补充额度 |
| SUBACCOUNT_QUOTA_LOW | 子账户配额不足 | 子账户剩余配额首次低于预警阈值 | NOTICE | 联系主账户调整配额 |
| SUBACCOUNT_QUOTA_EXHAUSTED | 子账户配额耗尽 | 子账户配额为零或不足以完成预扣 | CRITICAL | 联系主账户调整配额 |
| OWNER_QUOTA_BLOCKING | 主账户额度不足 | 主账户额度不足已影响子账户调用 | CRITICAL | 由主账户补充服务额度 |

原方案示例使用“10元、0.5元”，但平台同时存在Token额度包、配额和可能的金额计价。本文不把示例金额固化为生产规则。事件必须携带 `metricUnit`、当前值和阈值，前端按单位展示，不自行换算。

首版建议由平台统一配置阈值，不向用户提供阈值编辑入口。可选判断维度包括固定余量、剩余比例或权威系统给出的预测可用时长；实际采用哪一种待产品和额度模块确认。

### 2.2 异常调用告警

| alertType | 中文名称 | 触发语义示例 | 默认级别 | 处理方向 |
|---|---|---|---|---|
| REQUEST_RATE_ANOMALY | 请求频率异常 | RPS或并发持续超过阈值 | WARNING | 检查调用频率和重试逻辑 |
| CONTINUOUS_FAILURE | 持续调用失败 | 时间窗口内连续或高比例失败 | WARNING | 查看错误分布及调用明细 |
| OVERSIZED_REQUEST | 请求体持续超限 | 多次提交超过平台限制的请求体 | NOTICE | 调整或拆分请求内容 |
| API_KEY_SUSPECTED_ABUSE | 密钥疑似滥用 | 调用行为明显偏离正常模式 | CRITICAL | 暂停用户密钥并检查泄露 |
| CALL_RESTRICTED | 调用持续受限 | 持续因限流或风控被拒绝 | WARNING | 查看限制原因并提交工单 |

异常检测算法、阈值和时间窗口由大网关或实时计算模块负责。门户接收已标准化和聚合的告警事件，不根据错误码数量自行产生权威告警。

### 2.3 告警级别

| 值 | 中文 | 页面语义 |
|---|---|---|
| NOTICE | 提醒 | 暂未阻断使用，但需要关注 |
| WARNING | 重要 | 风险正在扩大，可能很快影响使用 |
| CRITICAL | 严重 | 已经或很可能立即影响模型调用／账户安全 |

状态必须同时显示文字和图标，不能只依赖颜色。未知级别显示“未知级别”，不得按普通提醒处理。

## 3. 权限与数据范围

### 3.1 权限码

- `portal.alert.read`：查看列表、详情、未读数量。
- `portal.alert.markRead`：单条、批量或全部标记已读。
- `portal.apiKey.pause`：从告警详情暂停用户密钥；由API密钥模块实际校验和执行。

读取和标记已读权限分开判断。页面不能因为显示“暂停密钥”按钮而绕过API密钥模块的权限与状态校验。

### 3.2 权限矩阵

| 身份 | 可见范围 | 字段与操作差异 |
|---|---|---|
| 主账户 | 当前主账户审计域内的服务额度、本人及子账户异常调用告警 | 可筛选子账户；可跳转相关服务及有权管理的用户密钥 |
| 子账户 | 自身配额、自身用户密钥和自身调用产生的告警 | 不显示其他子账户；不返回主账户精确余额 |
| AI应用用户 | 当前身份可见AI应用服务的额度和异常告警 | 业务密钥显示为“系统业务调用”，无密钥管理入口 |
| 多身份用户 | 一次只查看当前已验证业务身份 | 切换身份后重新加载，不合并未读数量 |

**本版设计、待确认：**主账户默认可查看其服务下子账户产生的异常调用告警；子账户默认具备告警查看权限。公共设计目前将子账户告警列为待确认，生产开发前必须统一。

### 3.3 数据隔离规则

- 后端依据登录会话和当前 `accountContextId` 确定查询范围，不信任前端传入的主账户ID或子账户ID。
- 当前身份有效且有模块权限，但访问不可见 `alertId` 时返回404，避免泄露记录存在性。
- 子账户收到 `OWNER_QUOTA_BLOCKING` 时，只展示“所属主账户可用额度不足”，不得返回主账户精确额度、订单或其他子账户信息。
- 历史告警按发生时的 `ownerAccountId` 保存。子账户后续转移、解除关系或改名，不改变原告警归属。
- 对象已经删除或改名时，列表和详情使用告警发生时快照，不依赖当前对象一定存在。
- 业务密钥内部ID、名称和掩码均不返回门户；仅展示对应AI应用或服务名称。

## 4. 页面结构

### 4.1 列表页

```text
告警中心                                      [全部标记已读] [刷新]
查看当前账户范围内的额度与异常调用风险。

[全部 12] [额度告警 3] [异常调用 9]

未读告警 5        严重告警 2        最近24小时新增 4

┌──────────────────────────────────────────────────────────┐
│ 发生时间 [近7天/近30天/自定义]  级别 [全部] 状态 [全部]  │
│ 关联服务 [全部]  关联子账户 [全部，仅主账户]              │
│ 关键词 [告警标题/告警编号/对象名称]       [查询] [重置]   │
└──────────────────────────────────────────────────────────┘

级别 | 告警内容 | 关联对象 | 首次发生 | 最近发生 | 状态 | 操作
严重   密钥疑似滥用  生产环境Key  ……          ……       告警中  查看

每页 [20/50/100] 条                    [上一页] 第N页 [下一页]
```

桌面端表格在自身容器内横向滚动，操作列固定右侧；窄屏使用卡片列表。筛选、标签、分页、详情和关闭操作均支持键盘。列表默认按以下优先级排序：

1. 未读优先；
2. 告警级别由高到低；
3. 最近发生时间倒序；
4. 告警ID倒序，保证稳定顺序。

首版使用游标分页，不承诺未经计算的总记录数和总页数。分类标签计数按当前身份返回，可为近似实时，但必须携带数据截至时间。

### 4.2 顶部指标

| 指标 | 定义 |
|---|---|
| 未读告警 | 当前身份下 `readStatus=UNREAD` 的可见告警数 |
| 严重告警 | 当前身份下 `severity=CRITICAL` 且 `lifecycleStatus=ACTIVE` 的告警数 |
| 最近24小时新增 | 最近24小时首次产生的告警数，不含旧告警持续事件 |

数量未知时显示 `—`，不能显示0。指标失败不阻断列表，按分区状态单独提示。

### 4.3 分类标签

- “全部”：全部可见告警。
- “额度告警”：`category=QUOTA`。
- “异常调用”：`category=USAGE_ANOMALY`。

切换标签保留时间、级别、状态和关键词，清空不适用于新分类的筛选项，并回到第一页。标签计数不受页面关键词影响，是否受时间筛选影响由接口固定为“当前全部可见未读数”，避免数字随查询条件跳变。

### 4.4 列表字段

| 列 | 展示规则 |
|---|---|
| 告警级别 | 严重／重要／提醒，含文字和图标 |
| 告警内容 | 标题；未读使用视觉强调；下方可显示类型名称 |
| 关联对象 | 优先服务／AI应用名称；异常密钥告警显示用户密钥历史名称和掩码 |
| 首次发生时间 | `YYYY-MM-DD HH:mm:ss`，北京时间 |
| 最近发生时间 | 同一告警最近事件时间；等于首次发生时可显示“—”或相同时间，需全站统一 |
| 状态 | 告警中／已恢复；另以未读标记展示阅读状态 |
| 操作 | 查看详情；不提供删除和手动恢复 |

### 4.5 详情抽屉

建议宽度720px，窄屏全宽。列表URL使用 `alertId`，例如 `/alerts?alertId=...`，支持刷新恢复和其他页面直达。

详情分为以下区域：

**基本信息**：告警编号、标题、类型、级别、阅读状态、事件状态、首次发生、最近发生、恢复时间。

**影响对象**：服务、AI应用、子账户、用户密钥历史名称及掩码、影响范围。对象无权查看时服务端不返回，前端不自行补全。

**判断依据**：当前值、阈值、单位、统计窗口、累计次数、影响调用次数、错误码分布和可复制的请求ID。仅显示事件源明确提供并允许用户查看的字段。

**处理建议**：根据服务端返回的可用动作展示“查看服务”“查看额度与套餐”“查看相关用量”“查看调用明细”“管理密钥”“暂停密钥”“提交工单”。前端不按告警类型自行推断权限。

**事件记录**：首次触发、持续发生、级别升级、恢复等时间线。用户阅读事件不混入风险时间线，可在基本信息中显示首次阅读时间。

异常告警不得展示请求正文、响应正文、提示词、供应商端点、渠道名称、内部堆栈和完整密钥。

打开详情成功后，若当前为未读且具备权限，调用标记已读接口。标记失败不阻止用户阅读详情，但保留未读状态并提供轻量重试提示。

## 5. 筛选与交互规则

### 5.1 筛选定义

| 条件 | 默认值 | 规则 |
|---|---|---|
| 分类 | 全部 | 由标签控制，全部／额度告警／异常调用 |
| 发生时间 | 近30个自然日（含今天） | 查询首次发生时间；支持近7天、近30天、自定义；单次最多180天，本版设计 |
| 告警级别 | 全部 | NOTICE／WARNING／CRITICAL |
| 阅读状态 | 全部 | UNREAD／READ |
| 事件状态 | 告警中 | ACTIVE／RECOVERED；可选全部 |
| 关联服务 | 全部 | 远程搜索当前身份可见的历史服务快照 |
| 关联子账户 | 全部 | 仅主账户显示；按历史账户快照搜索 |
| 关键词 | 空 | 匹配告警标题、告警编号或对象历史名称，2～100字符 |

日期采用 `Asia/Shanghai` 自然日，查询区间左闭右开。默认只看“告警中”，用户可以切换为全部或已恢复。

修改筛选不会立即发起查询；点击“查询”或输入框回车后校验并回到第一页。“重置”恢复默认分类、近30天和告警中状态，并立即查询。

### 5.2 标记已读

- 单条标记已读：详情打开后自动执行，也可在列表快捷执行。
- 批量标记已读：只作用于用户在当前页明确勾选的告警ID，不作用于“当前筛选全部结果”。
- 全部标记已读：作用于当前业务身份下所有可见未读告警，不受当前分页影响；需要二次确认并由接口返回实际变更数量。
- 已读告警重复操作为幂等成功，`changedCount=0`，不重复记录审计事件。
- 标记已读只修改当前阅读主体的阅读状态，不修改告警生命周期。

**待确认：**阅读状态按业务身份还是登录用户保存。公共设计暂按业务身份处理；若同一主账户有多个可登录用户，需要决定“一人已读是否全账户已读”。数据模型预留 `readerSubjectType` 和 `readerSubjectId`，实现前必须确认。

### 5.3 页面联动

| 场景 | 目标页及参数 |
|---|---|
| Token服务额度不足 | `/services/:serviceId?tab=quota` |
| AI应用额度不足 | `/services/:serviceId`，不传业务密钥 |
| 用户密钥异常 | `/api-keys?keyId=...`，仅在仍有权限且对象存在时 |
| 核对额度消耗 | `/usage?tab=statistics&serviceId=...&startDate=...&endDate=...` |
| 核对异常调用 | `/usage?tab=details&keyId=...&startDate=...&endDate=...` |
| 无法自行处理 | `/help/tickets/new?alertId=...`，工单后端重新读取告警，不信任URL内容 |

目标页仍须独立鉴权。告警中心只传稳定ID和时间条件，不把名称、余额、密钥信息等作为可信数据传递。

### 5.4 顶部消息铃铛

公共框架查询当前身份的未读数量和最近5条未读告警。身份切换后立即清空旧数量和消息，再查询新身份；旧响应与当前 `accountContextId` 不一致时丢弃。

铃铛弹层展示级别、标题、发生时间和“查看全部”。点击告警进入 `/alerts?alertId=...`。弹层打开本身不标记已读；只有成功打开详情后才标记。

首版不要求WebSocket或SSE实时推送，可按公共框架约定在登录、身份切换、页面回到前台和用户手动刷新时更新。是否增加定时轮询需结合接口容量确认。

### 5.5 空态与异常

| 场景 | 页面行为 |
|---|---|
| 当前无告警 | 显示“当前没有需要处理的告警”，不显示风险数字0以外的虚构数据 |
| 当前条件无结果 | 保留筛选，提示“当前条件下暂无告警”，提供重置 |
| 列表失败 | 显示错误及重试；保留旧数据时标明数据截至时间，不冒充最新结果 |
| 详情不存在／无权 | 统一提示“该告警不存在或当前无法查看” |
| 标记已读失败 | 保持未读状态，提示重试，不关闭详情 |
| 告警事件延迟 | 显示接口返回的数据截至时间；不承诺实时到秒 |
| 关联对象已删除 | 使用历史快照，相关管理按钮隐藏，仍可查看告警历史 |
| 可用动作加载失败 | 不显示高风险操作按钮，详情信息仍可查看 |

## 第二部分：告警规则与生命周期

## 6. 额度告警生命周期

### 6.1 阈值突破

同一服务额度池、同一阈值级别仅在从阈值之上首次跌破时触发。持续低于该阈值时不重复创建新告警，只更新同一告警的最近发生时间和事件记录。

```text
额度正常
  ↓ 首次跌破预警阈值
创建“额度不足”告警
  ↓ 继续跌破严重阈值
升级为“额度严重不足”
  ↓ 无法满足预扣／额度耗尽
升级为“额度耗尽”
  ↓ 急救包到账／周期刷新／额度调整
恢复到解除阈值以上，告警自动恢复
  ↓ 再次跌破阈值
创建新一轮告警
```

首版将同一轮额度风险作为一条告警升级，避免列表出现三条描述同一余额问题的活动告警。每次升级均保留事件记录。若产品要求每个级别单独留存，可调整事件聚合规则，但不能在前端临时拆分。

### 6.2 恢复回差

为避免额度在阈值附近波动造成反复告警，事件源建议设置恢复回差，例如低于10%触发、恢复到12%以上才恢复。具体回差由额度模块配置并在事件中返回 `recoveryThreshold`；门户只展示结果，不参与判断。

额度增加后仍低于解除阈值时，告警继续保持ACTIVE。连续包周期刷新、急救包到账、人工调整或扣减回滚均可能触发恢复事件，恢复原因需记录标准枚举。

### 6.3 多额度包

当一个服务存在连续包和多个急救包时，告警必须针对权威服务可用额度产生。门户不得自行相加不同单位、不同有效期或不可共同抵扣的额度包。

事件可携带 `quotaPoolId` 作为内部归并键，但用户页面优先展示服务名称和当前生效额度摘要，不暴露内部账本结构。

## 7. 异常告警聚合

### 7.1 聚合键

建议事件源采用以下稳定维度聚合：

```text
ownerAccountId + subjectType + subjectId + alertType + aggregationWindow
```

其中 `subject` 可以是用户密钥、子账户、服务或当前业务身份。事件源生成稳定 `sourceAlertKey`，门户不使用标题文本或错误信息拼接聚合键。

同一窗口内持续发生时发送OCCURRED事件，更新累计次数、最近发生时间和指标摘要。新窗口是否延续原告警或产生新一轮告警，由事件源通过同一／新的 `sourceAlertKey` 明确。

### 7.2 事件类型

| eventType | 含义 | 门户处理 |
|---|---|---|
| OPENED | 首次产生告警 | 创建告警和首条时间线事件 |
| OCCURRED | 同一告警持续发生 | 更新最近发生时间、累计次数和指标 |
| ESCALATED | 级别提升 | 更新级别并写入升级事件 |
| RECOVERED | 异常已解除 | 标记已恢复并记录恢复时间／原因 |
| REOPENED | 已恢复后同一告警重新发生 | 本版建议创建新一轮告警；如复用记录须增加cycle编号 |

事件乱序时以 `sourceEventSeq` 优先；如果事件源无法提供序号，则按事件时间和事件ID进行保守处理。晚到的旧OCCURRED不得把已恢复告警重新变为ACTIVE。

### 7.3 自动处置

原方案说明异常行为可能触发限流、密钥停用、用户冻结和人工审核，但没有明确用户门户告警是否直接执行处置。本期告警中心不自动暂停密钥。

若上游已经执行限流或停用，事件应携带处置结果，门户只展示“平台已限制调用”等事实。用户点击“暂停密钥”属于API密钥模块的新业务操作，需重新鉴权和确认，并产生操作审计记录。

## 8. 阅读状态与生命周期状态

两个状态维度不得混用：

| 维度 | 值 | 含义 |
|---|---|---|
| `readStatus` | UNREAD／READ | 当前阅读主体是否查看过告警 |
| `lifecycleStatus` | ACTIVE／RECOVERED | 风险事件是否仍在持续 |

已读不代表问题已解决；已恢复也可能仍是未读。用户不能手动把ACTIVE改成RECOVERED，也不能删除告警。

对于告警升级，若告警原本已读，升级到更高级别后建议重新置为未读，使用户看到新的风险变化。该规则属于本版设计，待产品确认。

### 9.4 并发与身份切换

- 所有响应携带 `accountContextId`，前端只渲染与当前身份一致的结果。
- 新查询取消或忽略旧查询；详情关闭后晚到响应不得重新打开。
- 标记已读使用服务端幂等更新；并发重复请求只产生一次实际状态变更。
- 身份切换立即清空列表、摘要、未读数、筛选候选、游标、详情和URL中的旧 `alertId`。

### 11.4 事务与幂等

事件接收推荐在同一事务中完成：

1. 按 `source_event_id` 尝试登记事件幂等记录。
2. 查找或创建 `source_alert_key + cycle_no` 对应主告警。
3. 按事件序号／时间校验是否允许更新状态。
4. 更新主告警、插入事件时间线、初始化或重置阅读状态。
5. 提交事务后再触发站内未读刷新消息；通知失败不回滚权威告警，可重试。

读状态更新和操作审计若跨库，应采用Outbox或项目已有可靠事件机制，不能用无保障的双写声称原子一致。

## 12. 错误码、Mock与验收

### 12.1 建议错误码

| 错误码 | 场景 |
|---|---|
| ALERT_INVALID_QUERY | 查询参数或日期范围不合法 |
| ALERT_NOT_FOUND | 告警不存在、不可见或已超保留范围 |
| ALERT_PERMISSION_DENIED | 当前身份无模块／操作权限 |
| ALERT_CURSOR_EXPIRED | 游标过期或查询快照失效 |
| ALERT_BATCH_LIMIT_EXCEEDED | 批量ID超过100条 |
| ALERT_EVENT_DUPLICATE | 内部重复事件，接口可作为幂等成功返回 |
| ALERT_EVENT_INVALID | 内部事件字段、枚举或时序不合法 |
| ALERT_SOURCE_UNAVAILABLE | 告警查询依赖暂不可用 |

### 12.2 Mock场景

- 主账户无告警。
- 同时存在未读额度告警、已读异常告警和已恢复历史告警。
- 额度不足逐步升级为额度耗尽，再恢复。
- 同一异常在窗口内持续发生，累计次数和最近时间更新。
- 子账户仅看到自身告警，不返回主账户精确余额。
- AI应用告警不返回业务密钥信息。
- 用户密钥已删除，告警仍显示历史名称但无管理入口。
- 详情读取成功、标记已读失败。
- 列表成功、摘要统计失败。
- 告警升级后重新变为未读。
- 重复、乱序和晚到恢复事件。
- 身份切换时旧请求晚到且被丢弃。
- 未知告警类型和未知级别的兼容展示。

### 12.3 验收标准

1. 用户只能查看当前业务身份权限范围内的告警。
2. 主账户与子账户的列表、摘要、筛选候选和详情均完成服务端隔离。
3. 用户可按分类、时间、级别、阅读状态、事件状态、服务和关键词查询。
4. 打开未读告警详情后能够标记已读；失败时保持未读并可重试。
5. 批量和全部标记已读幂等，返回实际变更数量并更新顶部未读数。
6. 同一额度同一级阈值持续低于阈值时不重复创建告警。
7. 额度风险升级、恢复和再次发生均有明确且可追溯的生命周期。
8. 同一异常聚合窗口内只维护一条活动告警，累计次数与最近发生时间正确更新。
9. 已读和已恢复状态相互独立，用户不能手动恢复或删除告警。
10. 告警详情能够按权限跳转到服务、用量、用户密钥或工单页面。
11. 页面和接口不展示请求正文、响应正文、完整密钥、业务密钥和供应商内部信息。
12. 对象删除或改名后，历史告警仍可通过快照正确展示。
13. 重复事件不会重复计数；晚到旧事件不会把已恢复告警错误重开。
14. 身份切换后旧身份的未读数、列表、详情和筛选候选不会残留。
15. 未知类型、部分接口失败和数据延迟均有明确降级，不显示伪造的0或正常状态。

## 14. 开发约束

- 未确认的阈值、单位、权限和通知策略必须通过配置或适配层隔离，不写死为原方案示例值。
- 门户前端不重新计算告警、不从调用明细推导风险，也不根据标题拼接处理动作。
- 页面按钮由后端权限和 `availableActions` 共同决定；隐藏按钮不能替代后端鉴权。
- 所有名称按纯文本渲染，禁止未经净化的HTML。
- 所有数量使用十进制字符串，前端避免JavaScript大整数精度损失。
- 所有时间数据库建议存UTC，接口带偏移，页面按 `Asia/Shanghai` 展示。
- Mock必须覆盖权限、恢复、升级、重复事件和部分失败，不使用随机数据冒充真实接口。
- 生产联调前必须完成第13章A01、A02、A05、A06、A08和A14的确认。
